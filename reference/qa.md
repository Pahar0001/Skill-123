# Проверки: что, чем, и когда результат считается подтверждённым

Проверка — не этап в конце, а часть каждой задачи. Финальный проход
повторяет всё разом и ищет регресс.

## Что означают вердикты скриптов

`OK` — в браузере произошло ожидаемое. `WARN` — произошло что-то
подозрительное, решает взгляд. `FAIL` — не произошло или появились ошибки.
Ни один `OK` не говорит, что стало красиво: это отвечает снимок, открытый
глазами. Ни один снимок не говорит, что работает: это отвечает `runtime.mjs`.

## Runtime

Во всех командах этого файла `--out <папка>` опущен для краткости — передавать
его всегда (SKILL.md → «Папка прогона»), а `runtime.mjs` — ещё свой `--tag`
на каждый набор шагов: без него протокол называется по экрану и следующий
запуск на том же экране его перезаписывает.

```
node ~/.claude/skills/site-rework/scripts/runtime.mjs <url> --scroll --canvas --motion --video --fullpage
node ~/.claude/skills/site-rework/scripts/runtime.mjs <url> --viewport mobile --scroll --click "<меню>" --shot menu --click "<закрыть>" --shot closed
node ~/.claude/skills/site-rework/scripts/runtime.mjs <url> --viewport mobile-s --scroll                      # 320: переполнение по элементам
node ~/.claude/skills/site-rework/scripts/runtime.mjs <url> --hover-all --nav --css
node ~/.claude/skills/site-rework/scripts/runtime.mjs <url> --click "a[href='#contacts']" --edit "input[type=tel]" --type "#phone=89001234567" --click "form button[type=submit]" --shot sent
node ~/.claude/skills/site-rework/scripts/runtime.mjs <url> --reduced-motion --scroll --motion --canvas
node ~/.claude/skills/site-rework/scripts/runtime.mjs <url> --eval "document.querySelectorAll('.card').length" --expect 12
node ~/.claude/skills/site-rework/scripts/runtime.mjs <url> --assert "getComputedStyle(document.querySelector('.cta')).position === 'sticky'"
```

`--eval` без `--expect` — запись, а не проверка: он всегда OK. Утверждения
писать через `--assert` (ложь или отклонённый Promise — FAIL) или
`--eval … --expect значение`.

`--type` и `--select` делят «селектор=значение» по первому «=» вне `[ ]`,
`( )` и кавычек: `--type "input[name=phone]=89001234567"` вводит в поле
телефона, `--select "#sel=a=b"` выбирает вариант «a=b». Без «=» вне скобок —
ошибка аргументов, код 2. Значение, которое начинается с «--», пишется через
«=» (`--hover="--x"`): иначе шаг без значения — тоже код 2, до браузера.

`--cpu 4` — процессор вчетверо медленнее, как у среднего телефона: холсты,
анимации и тяжёлые обработчики на `--viewport mobile` проверять с ним
(`perf.mjs` на телефоне замедляет так же сам).

Карта импортов. При загрузке `runtime.mjs` в любом браузере проверяет разметку:
`<script type="importmap">` стоит раньше всех `<link rel="modulepreload">`, module-скриптов
(встроенных тоже) и заголовка `Link: rel=modulepreload`, и карта одна. Иначе WARN «карта
импортов после modulepreload/module-скрипта — Firefox её отбросит» или «карт импортов N —
Firefox примет только первую»: Chrome прощает, а в Firefox `import('three')` по имени падает
и 3D не запускается.

`--scroll`: поля формы и прозрачное без перехода и анимации — «невидимы по замыслу», без
WARN (радиокнопка с `opacity: 0` поверх подписи — приём оформления); «не появились» — только
то, что не стало видно ни на одном шаге прохода. `--canvas`: у FAIL «ПУСТОЙ» названа причина —
ни разу не рисовала; буфер сменил размер после кадра; рисует только по событию и кадр потерян
(нужен `preserveDrawingBuffer: true` или перерисовка по `visibilitychange`); контекст WebGL потерян.

Что считается эффектом клика: изменения DOM за время клика (атрибуты,
классы, узлы) за вычетом того, что менялось и без клика (карусель,
таймеры), переход, сетевой запрос, диалог, фокус на **другом** элементе.
Своя прокрутка к кнопке и фокус на ней самой — не эффект. Кнопка без
эффекта — FAIL, ссылка без эффекта — WARN. Якорь: скрипт ждёт, пока
прокрутка встанет, и сверяет верх цели с `scroll-margin` (или низом
закреплённой шапки) ±8 px.

Что должно быть на выходе: ноль ошибок консоли и исключений (404 на
`/favicon.ico` — отдельный WARN, не провал; не загрузился внешний шрифт
или CDN — тоже FAIL: перепрогнать, а если повторилось — задача, см.
SKILL.md → «Восстановление после сбоев»); все блоки появления
показались; переполнения по элементам нет ни на одном экране, включая
320; меню открывается и закрывается; у каждого правила `:hover` есть
видимый эффект; ввод и правка поля с маской проходят все сценарии;
отправка формы что-то показывает и не роняет консоль; холсты рисуют и
резкие после каждого действия; при «меньше движения» бесконечные анимации
и автоплей-видео останавливаются, а содержимое видно.

## Автопроверки состояния

Ошибки, которые на глаз не видны и которые скилл однажды пропустил, пока
писал «10 из 10». Каждая ловится своей командой; прогонять на каждом
сайте перед отчётом. Проверено на стенде «ХОЛСТ», где все они есть:

| ошибка | команда | что ловит |
|---|---|---|
| объявление CSS, выброшенное браузером | `--css` | FAIL `art.css:128 .room__art { border: 1.2% solid #F4F1EA }` |
| маска телефона не стирается и уводит курсор | `--edit "#oPhone"` | FAIL «застревает на +7 (900) 123-45-», FAIL «курсор уезжает» |
| холст размыт после смены состояния | `--select "#wallWork=6"` | FAIL «буфер 151×113 на 227×170 CSS px → ×0.66» |
| холсты размыты после смены ширины | `--resize 1152` | FAIL 12 холстов ×0.77 |
| вкладка нижней панели за краем на 320 | `--viewport mobile-s --scroll` | FAIL `a [fixed] 279…334px «ЗАЯВКА»` |
| наведение перебито анимацией | `--hover-all` | FAIL `.hero:hover .tilt { transform }` — держит `tiltIn (fill: both)` |
| подсвеченный пункт меню не на экране | `--nav` | FAIL «[снова верх] Разделы: подсвечен «order», а этого раздела нет на экране» (раздел и положение зависят от предыдущих шагов) |
| мёртвая кнопка | `--click "<кнопка>"` | FAIL «КНОПКА БЕЗ ЭФФЕКТА» |
| якорь не доводит до раздела | `--click "a[href='#id']"` | FAIL «верх цели 300px — ЦЕЛЬ НЕ У ВЕРХА ОКНА» |
| видео: автоплей со звуком, без poster, без playsinline | `--video` | FAIL / WARN по каждому ролику; пауза вне экрана и при «меньше движения» |
| зерно не видно (multiply на чёрном) | `texture.mjs <url>` или `texture.mjs compare` | WARN «multiply гасит на тёмном: σ 0», FAIL против донора |

После `--click`, `--select` и `--resize` холсты и переполнение
перепроверяются сами, когда закончатся переходы; печатается только то,
что изменилось.

Перебитое `:hover` (правило срабатывает, но значение задаёт более сильное
— у Tilda так у активного пункта меню) — WARN: решить, задумано ли.
Пустое правило (объявлено то же, что без наведения) — не в счёт.

## Инвентарь контролов

Перед финальной проверкой составить в `analysis.md` список всего, с чем
может взаимодействовать человек, и по каждому типу пройти сценарии.
У каждой строки — ссылка на протокол `runtime/*.json`.

| тип | сценарии, обязательные все |
|---|---|
| поле с маской (телефон, дата) | `--edit`: набор; Backspace до пустого; правка в середине — курсор на месте; Delete; вставка «8 (900) …»; Ctrl+A и стереть |
| обычное поле | `--type`, `--key Tab` (пишет значение и курсор), ошибка и исправление |
| список и выбор вариантов | `--select` каждого значения хотя бы раз; после — холсты и переполнение сами |
| пункт меню и вкладка | `--click` по каждому; `--nav`: подсветка на первом экране, после прокрутки и после возврата наверх |
| наведение | `--hover-all` один раз на desktop |
| аккордеон и FAQ | открыть и закрыть мышью (`--click`) и клавиатурой (`--key Enter`) |
| холст и картинка, которые перерисовываются | `--canvas`, затем действие; ширина окна туда и обратно (`--resize 1152 --resize 1440`) |
| видео | `--video` на desktop и mobile |

Сложное поведение (перетаскивание, многошаговые опросники, оплата) —
пошагово через chrome-devtools MCP: `click` → `take_screenshot` →
`list_console_messages`, с записью каждого шага в отчёт.

## Визуал

```
node ~/.claude/skills/site-rework/scripts/shots.mjs <url> --tag after --pages <те же, что в before> --viewports desktop,tablet,mobile --with-320
node ~/.claude/skills/site-rework/scripts/diff.mjs <папка>/before <папка>/after
```

`shots.mjs` снимает первый экран **до** прокрутки, потом листает до низа и
снимает его снова дважды — прыжком наверх (`first-return`) и листанием вверх
(`first-up`). Отличие от первого — FAIL «состояние не сбрасывается» с
областью, элементами и вырезкой `*-stale.png` (на «ХОЛСТе»: `a.fnav__cta.is-active
«ЗАЯВКА»` остаётся подсвеченным наверху). Пропала подписанная ссылка или
кнопка первого экрана — FAIL «пропала ссылка или кнопка первого экрана и
наверху не вернулась», пропало поле формы — FAIL «пропало поле формы первого
экрана и наверху не вернулось» (`lostField: true` в `shots.json`): так же
выходит и плашка cookie или промо со ссылкой, которую сайт убирает прокруткой
нарочно, — решить по вырезке. «Узел заменён новым — компонент меняется сам»
пишется только при настоящей замене: родитель сам менял детей при наблюдении,
и на месте удалённого стоит новый узел того же вида. Если у родителя сами
менялись только атрибуты (стиль от анимации, класс), а кнопку убрала
прокрутка, — это пропажа, FAIL.
Только пропало, ушло за экран или стало невидимым без такой ссылки
(подсказка «листайте ↓») — WARN «пропал после прокрутки — проверить,
задумано ли»; только проявилось — WARN. Живые холсты, видео и карусели
(и узел, который живой компонент заменил новым) ложной тревоги не дают
(WARN «меняется само»). Текст, который меняется сам (печатающийся заголовок), — тоже
«меняется само» на любом экране, как и соседи в его блоке, сдвинутые пересчётом строки.
Закреплённое (sticky) после прокрутки рисуется отдельным слоем: сдвиг на ≤1 px внутри
него не в счёт («закреплённое …: сдвиг на ≤1 px после прокрутки не в счёт», `stickySkipped`
в `shots.json`); залипшее состояние закреплённого (класс, цвет, фон) — по-прежнему FAIL.
Предупреждения самой проверки («свой стиль не вставился» при строгом CSP) выходят строкой
под страницей и считаются в вердикте (`shots[].warnings`). Вся страница по умолчанию
склеивается из снимков окна (`--full-mode segments`): закреплённые слои и
зерно видны на всей высоте. В `shots.json` — вердикт, `fails`, `warns` и у
каждого файла `scale`, `cssWidth`, `dpr`, `viewport` — по ним `state.mjs`
принимает снимок как доказательство, а `diff.mjs` приводит масштаб.

| флаг shots | умолчание |
|---|---|
| `--tag` | before (не в Chrome — before-firefox, before-edge) |
| `--browser` | chrome; firefox, edge |
| `--viewports` (или `--viewport`) | desktop,tablet,mobile; пресеты, `ШxВ@плотность`, ширина |
| `--with-320` | добавить mobile-s |
| `--pages` | только адрес |
| `--segments N` | 8 снимков окна по высоте (0 — без них) |
| `--full-mode segments\|auto` | segments |
| `--return both\|jump\|up` | both |
| `--sheet` | лист миниатюр |
| `--no-freeze`, `--scheme`, `--shot-pause`, `--strict` (код 1 при FAIL) | — |

`diff.mjs` приводит снимки ×2 и ×1 к одному масштабу по `shots.json` (без
него — по ширине) и предупреждает; края букв после приведения всё равно
расходятся на несколько процентов — это не изменение. `--no-rescale` —
без приведения, `--all` — сравнивать и вырезки `*-stale`, листы. Два
отдельных файла (например, `first` и `first-return` одного экрана) —
`diff.mjs --pair a.png b.png`; пары донор/результат так не сравнивают
(`reference/donor-mode.md` §5).

У Chrome есть предел высоты снимка около 16 тысяч пикселей в устройстве:
выше него полноэкранный снимок молча повторяет верх страницы (телефон при
масштабе ×2 упирается в него уже на 8 тысячах CSS-пикселей). Скрипты
снимают такие страницы в масштабе ×1 или сегментами со склейкой и пишут
об этом в протокол («снята как dpr1 / segments»). Если снимок всей
страницы выглядит как повтор — это оно; сверить с высотой документа.

Открыть глазами: каждый `after/*-first.png` и `*-full.png` на трёх экранах,
каждый `diff/*.png`. Чек-лист взгляда:

- иерархия: первым читается то, что должно; кнопка видна;
- типографика: `typeset.mjs` без FAIL; строки основного текста 45–80 знаков на desktop и 28–50 на телефоне; висячие предлоги и одинокие слова первого экрана исправлены или в отчёте с причиной; нет знаков системным шрифтом (₽!); кириллица на месте; `typeset/after-*/00-hero.png` и вырезки открыты глазами;
- вёрстка: ничего не наезжает, не обрезано, не прилипло к краю; отступы из ритма системы;
- цвет: роли соблюдены; акцент — только если он есть у донора или сайта («акцента нет» — тоже правило); контраст читается;
- картинки: не растянуты, в фокусе, соответствуют подписям, единая обработка;
- движение: конечные состояния появлений — видимые; ничего не дёргается на снимках прокрутки;
- 3D: холст на месте, не перекрывает текст, на телефоне не пустой;
- регресс: красные зоны в diff совпадают с планом; зоны «не трогать» без изменений; высота страницы изменилась объяснимо.

Число из `verify.mjs` скилла design-reference — расхождения с собственной
дизайн-системой — тоже в отчёт.

## Функции

Все ссылки шапки и подвала ведут туда, куда написано (обход через
`runtime.mjs --click` или chrome-devtools `list_network_requests`); якоря
прокручивают к нужной секции; формы: обязательные поля, маска, согласие,
сообщение после отправки, письмо/запись доходит (если есть доступ к
бэкенду — проверить, если нет — записать «отправка не проверена»); слайдеры
листаются кнопками и свайпом; вкладки и аккордеоны открываются с клавиатуры;
диалоги закрываются по Esc и по клику вне; 404 существует. Каждый пункт
отметить в отчёте (`templates/report.md` → «Функции»): да / нет /
неприменимо с причиной.

## Телефон

`mobile` 390 px и `tablet` 834 px обязательны; **`mobile-s` 320 px — тоже**
для переполнения: нижние панели, плавающие меню, длинные подписи на
кнопках (`runtime.mjs --viewport mobile-s --scroll`; `discover.mjs` делает
такой проход сам). `android` 360×800@3 — когда аудитория на Android;
любой экран можно задать записью `ШxВ@плотность`. `laptop` 1280 — когда
сетка трёхколоночная. Смотреть: первый экран (заголовок, действие,
«позвонить»), меню, формы (16 px, 44 px цели), таблицы, картинки (не
крупнее и не мельче показанного — `a11y.mjs`, `perf.mjs`), переполнение по
элементам (`runtime --scroll`: fixed-панели в `scrollWidth` не входят,
поэтому проверка идёт по краям элементов), липкая шапка не выше 15% экрана,
поворот планшета (`--resize rotate`).

## Скорость

```
node ~/.claude/skills/site-rework/scripts/perf.mjs <url>                     # телефон, ×4 процессор, fast3g — как у покупателя
node ~/.claude/skills/site-rework/scripts/perf.mjs <url> --viewport desktop --net none --cpu 1
node ~/.claude/skills/site-rework/scripts/perf.mjs <url> --runs 3            # медиана трёх прогонов — для решения «хуже или нет»
node ~/.claude/skills/site-rework/scripts/perf.mjs <url> --overlay           # цена слоя зерна или вуали в покое
```

Что ещё проверяет `perf.mjs`, кроме LCP, CLS, веса и кадров:

- **прокрутка честная**: мгновенная, по реальному `scrollY`; дошли меньше
  чем на 90% высоты — FAIL замера, а не «90 кадров/с» (раньше при
  `scroll-behavior:smooth` «прокрутили 12453 px», а дошли до 149);
- **картинки мельче показанного** с учётом `object-fit` и `background-size`
  (cover — по большей оси): FAIL ниже 1 пикселя картинки на CSS-пиксель,
  WARN ниже плотности экрана; настоящий размер `srcset` и `<picture>`
  перечитывается;
- **видео**: полный вес роликов первого экрана — телефон и планшет ≤1 МБ,
  desktop ≤2.5 МБ — OK; до вдвое больше — WARN; выше — FAIL; размер не
  определён или нет poster — WARN;
- **`--overlay [селектор]`**: растровые задачи и Paint за 2 с покоя со слоем
  и без, не меньше 5 чередующихся раундов (`--rounds`), медиана и разброс;
  бюджет — прибавка не больше 2 задач. Кипящее через GIF или
  `background-position` зерно перерисовывается каждый кадр (у донора — 80
  задач против 0); сдвиг `transform` из `templates/grain.css` — нет;
- **холодный кэш и окно замера**: у каждого прогона отдельный контекст браузера, кэш очищен
  (в строке прогона «из кэша: 0»). После загрузки perf ждёт тишины сети (1 с, до 20 с; видео,
  потоки и маяки не ждёт): модуль, начатый после load (Three.js), в каждом прогоне попадает и в вес,
  и в долгие задачи. Вес — всё, что запрошено до прокрутки замера; догруженное прокруткой — отдельной
  строкой, в бюджет не входит;
- **сжатие текста**: вердикт веса — по передаче. Строка «Сжатие текста» говорит, сжимает ли сервер;
  если нет — у «JS по сети» и «Всего по сети» стоит «со сжатием было бы ≈ N КБ gzip / M КБ br»: FAIL
  веса на сервере без сжатия — ещё не FAIL на бою. Локальную папку отдавать `serve.mjs` — он сжимает,
  как хостинг;
- **LCP с элементом**: у каждого прогона — элемент, размер, место, время. В вердикте — последний
  кандидат до начала прокрутки замера: у человека первая прокрутка или касание останавливает LCP,
  прокрутку скриптом Chrome не замечает. Кандидаты при прокрутке замера — отдельным списком: картинка в
  нём значит, что появление прячет её до прокрутки. LCP «ниже первого экрана» до прокрутки — элемент
  сдвинуло содержимое, отрисованное позже (страница, которую дорисовывает скрипт);
- **долгие задачи по фазам**: список (начало, длительность, фаза: загрузка / после load / прокрутка
  замера); в вердикте — загрузка и после load, прокрутка замера — справочно.

`--tag`, `--out`, `--cpu`, `--net fast3g|slow4g|none` — как раньше.

Сравнивать `perf/after.json` с базой разведки `perf/base.json` (этап 1 — `--tag base`, этап 4 — `--tag after`; без своего тега оба прогона пишут в один файл, и база пропадает). База, снятая до 24.09.2026, с новой несравнима (вес включал догруженное прокруткой, LCP — кандидатов при прокрутке) — перемерить её текущим perf. Ухудшение любого бюджета
после правок — задача, а не примечание. Когда виноват конкретный скрипт
или картинка и `perf.mjs` не показывает, кто, — `performance_start_trace`
в chrome-devtools и `performance_analyze_insight`. Скорость проверять
после: новых картинок, шрифтов, библиотек, 3D, анимаций на прокрутке.

**Кто сдвинул вёрстку (CLS).** Наблюдатель, поставленный после загрузки,
ранние сдвиги не видит. Ставить его до всех скриптов страницы:

```
node ~/.claude/skills/site-rework/scripts/runtime.mjs <url> --init "window.__ls=[];new PerformanceObserver(l=>{for(const e of l.getEntries())if(!e.hadRecentInput)window.__ls.push({v:e.value,t:Math.round(e.startTime),src:(e.sources||[]).map(s=>(s.node&&s.node.tagName?s.node.tagName+'#'+s.node.id+'.'+s.node.className:'text')+' y'+Math.round(s.previousRect.y)+'→'+Math.round(s.currentRect.y)+' h'+Math.round(s.previousRect.height)+'→'+Math.round(s.currentRect.height))})}).observe({type:'layout-shift',buffered:true})" --wait 3000 --eval "window.__ls"
```
В `src` — элементы, которые поехали, и на сколько. Типичные виновники:
подмена шрифта меняет число строк заголовка (лечится запасным шрифтом с
`size-adjust`, подогнанным по замеру ширины, и запасом ширины в
контейнере, а не `ch`-единицами), картинки без `width/height`, вставка
блоков над содержимым, липкая шапка, меняющая высоту.

## Доступность

```
node ~/.claude/skills/site-rework/scripts/a11y.mjs <url> --viewport mobile
node ~/.claude/skills/site-rework/scripts/a11y.mjs <url>
```
плюс `lighthouse_audit` (chrome-devtools) для полного списка по WCAG и SEO.

`a11y.mjs` сначала мгновенно прокручивает страницу целиком (все блоки
появления показаны, иначе проверялись 2 из 21), потом проверяет:

- **контраст** с учётом альфы цвета и прозрачности самого элемента и
  предков (текст с `opacity:.25` больше не проходит как белый); на картинке —
  попиксельно по снимку фона;
- **зерно поверх текста**: действие полноэкранного слоя меряется снимками
  на чёрном, сером и белом; пары, упавшие из-за зерна, — FAIL, пары в пределах
  10% над нормой перечисляются (`--no-grain` — без поправки);
- **кегль**: видимый текст мельче 12 px — WARN, мельче 10 px — FAIL
  («не обязательно» 9 px на «ХОЛСТе»);
- **фокус** — обход Tab на свежей странице; обошли меньше min(5, число
  остановок Tab; группа радиокнопок — одна) — WARN «обход не состоялся». Фокус засчитывается и
  тогда, когда рамка на подписи, на соседе сразу за полем (`input:focus-visible + span`) или на обёртке
  (`:focus-within`); рамка только у самого невидимого элемента (прозрачного, обрезанного как sr-only) —
  FAIL «рамка только у самого элемента, а он невидим»;
- **телефон**: цель нажатия радиокнопки и флажка мерится вместе с подписью; «поля ввода текста мельче
  16px» (iOS приближает страницу) — только текстовые поля, `select` и `textarea`.

Закреплённый текст (шапка, меню, нижняя панель) `a11y.mjs` мерит и на
прокрутке: ставит страницу ещё на несколько высот (до 8) над секциями с
другим фоном и снимает фон под строками. Строка «контраст закреплённого
текста на прокрутке» — FAIL с высотой и секцией («на 1840 px меню nav.menu
над секцией section#catalog … — 1.07:1»). Спрятанное, ушедшее за окно,
перекрытое или обрезанное на высоте не мерится (в выводе — сколько). Sticky закреплён только в пределах
своего контейнера: высоты для него берутся, пока он закреплён, а на остальных он «не закреплён» (уехал
вместе с контейнером) — это не пропуск; ноль замеров только из-за этого — OK с пометкой «мерить нечего». Ни
одного замера — WARN «смотреть глазами», тогда `scroll-NN` глазами на каждом
фоне. После замеров видимая область возвращается на исходное место (начало
страницы; у `dir=rtl` шире экрана — её отрицательный сдвиг); если не вернулась,
строка получает WARN «видимая область N раз из M не вернулась … смотреть
глазами», в json — `viewReset.failed`. Правило подложки — `reference/authorship.md` §4.

Без `FAIL` в `a11y.mjs`; `WARN` — с решением в отчёте. Скилл
`design:accessibility-review` — когда нужен разбор конкретного экрана.

## Движение

```
node ~/.claude/skills/site-rework/scripts/motion.mjs compare <папка>/motion/<донор>.json <url> --out <папка>
```
Каждое движение донора — с парой у нас (тот же вид, похожие числа) или с решением в
`<папка>/motion-decisions.json` («почему нет / чем заменено»). FAIL — движение донора без пары и без
решения; WARN — вид тот же, числа другие (какие — в строке). «Своё (у донора нет)» — сверить с планом и
банком идей: задумано ли. Протокол сверки годится доказательством задачи движения. Рецепты и общие
правила (reduced-motion, LCP, петли дольше 5 с) — `reference/motion.md`. «Меньше движения» — отдельно:
`runtime.mjs --reduced-motion` + assert конечного состояния каждого движения.

## Браузер пользователя

`runtime.mjs`, `shots.mjs` и `typeset.mjs` проверяют в Chrome, с `--browser firefox` (или `edge`) — в
другом браузере; остальные скрипты — только Chrome. У `typeset.mjs` в Firefox — переносы, `text-wrap:
pretty` и строки первого экрана: Firefox ломает строки иначе, чем Chrome. Первая строка их вывода — браузер прогона и браузер
пользователя по умолчанию (Windows, реестр): «у пользователя по умолчанию Firefox — проверьте и в
нём: --browser firefox». Если это не Chrome — дымовая проверка в нём перед сдачей: страницы
открываются без ошибок, 3D и движение запускаются, картинки грузятся.

```
node ~/.claude/skills/site-rework/scripts/runtime.mjs <url> --browser firefox --wait 3000 --canvas --scroll
node ~/.claude/skills/site-rework/scripts/shots.mjs <url> --browser firefox --viewports desktop,mobile
```

Без `--tag` протокол — `<экран>-firefox.json`, снимки — в `before-firefox`: доказательства Chrome
не затираются. Чего у Firefox нет, то WARN «не поддерживается в Firefox», а не падение: `--cpu`,
`--scheme no-preference`, на телефоне — meta viewport и события касания (размер, плотность, агент,
`(hover: none)` и `(pointer: coarse)` есть). Вёрстку телефона и скорость судить по Chrome.

Частая причина поломки только в Firefox — `<link rel="modulepreload">` перед
`<script type="importmap">`: Firefox отбрасывает карту, `import('three')` падает, остаётся запасная
картинка (VN3D, 24.09). `runtime.mjs` ловит это в любом браузере (раздел «Runtime» → «Карта импортов»).

## Регресс: что не должно было измениться

Отдельно, не вместе с проверкой нового:

- diff по страницам и зонам из матрицы «не трогать» — ноль или объяснимо;
- контакты, цены, юридические тексты, ссылки на документы — те же (сверить текстом через `evaluate`);
- формы уходят туда же (`action`, поля, скрытые поля);
- аналитика и счётчики на месте;
- проектные тесты, если они есть (`npm test`, smoke, e2e, скилл `predrelease`), — зелёные.

## Сверка с планом и решениями

Журнал этого не делает: `state.mjs` принимает протокол без FAIL и не
сверяет его с колонкой «чем проверяем» плана — VERIFIED задаче, где план
требовал `--hover` по первому экрану, пройдёт и по протоколу без наведения.
Поэтому перед отчётом, руками:

- по каждой задаче плана (`analysis.md` → «План») найти в её доказательстве
  шаг, названный в «чем проверяем»; нет шага — прогнать и перепоставить статус;
- пройти решения `analysis.md` — матрицу «менять / не трогать», трение из
  воронки («одно действие на первом экране»), паспорт донора «как / никогда»
  — и у каждого отметить на готовой странице: выполнено (снимок или число)
  или нет. Невыполненное — задача или строка в «Что осталось».

С реестром требований (`requirements.mjs`) доказательство критерия находится по маркеру
(`/*R-x.a*/` в `--assert`) и проверяется `state.mjs probe`: ограничение «не сверяет «чем проверяем»»
для требований с маркером закрыто; остальное — руками, как выше.

## Условие завершения

Все задачи P0–P2: `impl=DONE`, `runtime=VERIFIED`, `visual=VERIFIED`,
`mobile=VERIFIED` (или `NA` с причиной) — каждое с доказательством новее
последней правки сайта (`state.mjs show` без «устарело» и «без
доказательства»); инвентарь контролов пройден; автопроверки состояния без
FAIL; `shots` без FAIL («состояние не сбрасывается», «пропала ссылка или кнопка»); 320 без переполнения; `perf` не
хуже базы; `a11y` без `FAIL`; `copy.mjs lint` без FAIL; `typeset.mjs` без FAIL в Chrome и Firefox;
с реестром — `requirements.mjs report` без «без доказательства», «устарело», «провалено» у активных must;
`cliche.mjs` без FAIL против базы; фактура —
`texture.mjs compare` OK, если у донора она есть; `motion.mjs compare` без FAIL (в режиме донора);
дымовая проверка в браузере пользователя; проектные тесты зелёные;
регресс чист; план и решения `analysis.md` сверены. Если что-то из этого не
достигнуто — либо ещё круг, либо строка в «Что осталось» отчёта с
настоящим статусом. Третьего варианта («почти готово») нет.
