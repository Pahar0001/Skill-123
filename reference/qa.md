# Проверки: что, чем, и когда результат считается подтверждённым

Проверка — не этап в конце, а часть каждой задачи. Финальный проход
повторяет всё разом и ищет регресс.

## Что означают вердикты скриптов

`OK` — в браузере произошло ожидаемое. `WARN` — произошло что-то
подозрительное, решает взгляд. `FAIL` — не произошло или появились ошибки.
Ни один `OK` не говорит, что стало красиво: это отвечает снимок, открытый
глазами. Ни один снимок не говорит, что работает: это отвечает `runtime.mjs`.

## Runtime

```
node scripts/runtime.mjs <url> --scroll --canvas --motion --fullpage
node scripts/runtime.mjs <url> --viewport mobile --scroll --click "<меню>" --shot menu --click "<закрыть>" --shot closed
node scripts/runtime.mjs <url> --hover ".btn-primary" --hover "a.nav-link" --hover ".card"
node scripts/runtime.mjs <url> --click "a[href='#contacts']" --type "input[name=phone]=+7 900 000-00-00" --click "form button[type=submit]" --shot sent
node scripts/runtime.mjs <url> --reduced-motion --scroll --motion --canvas
```

Что должно быть на выходе: ноль ошибок консоли и исключений; все блоки
появления показались после прокрутки; нет горизонтальной прокрутки; меню
открывается и закрывается (меняется `aria-expanded` или число видимых
элементов); у каждого типа кнопки есть состояние наведения; ввод в поле
остаётся в поле; отправка формы что-то показывает (диалог, сообщение,
переход) и не роняет консоль; холсты рисуют и меняют кадр; при «меньше
движения» бесконечные анимации останавливаются, а содержимое видно.

Сложное поведение (перетаскивание, многошаговые опросники, оплата) —
пошагово через chrome-devtools MCP: `click` → `take_screenshot` →
`list_console_messages`, с записью каждого шага в отчёт.

## Визуал

```
node scripts/shots.mjs <url> --tag after --pages <те же, что в before> --viewports desktop,tablet,mobile
node scripts/diff.mjs <папка>/before <папка>/after
```

У Chrome есть предел высоты снимка около 16 тысяч пикселей в устройстве:
выше него полноэкранный снимок молча повторяет верх страницы (телефон при
масштабе ×2 упирается в него уже на 8 тысячах CSS-пикселей). Скрипты
снимают такие страницы в масштабе ×1 или сегментами со склейкой и пишут
об этом в протокол («снята как dpr1 / segments»). Если снимок всей
страницы выглядит как повтор — это оно; сверить с высотой документа.

Открыть глазами: каждый `after/*-first.png` и `*-full.png` на трёх экранах,
каждый `diff/*.png`. Чек-лист взгляда:

- иерархия: первым читается то, что должно; кнопка видна;
- типографика: шкала выдержана, строки не длиннее 75 знаков, кириллица на месте (нет подмены гарнитуры);
- вёрстка: ничего не наезжает, не обрезано, не прилипло к краю; отступы из ритма системы;
- цвет: роли соблюдены, акцент один, контраст читается;
- картинки: не растянуты, в фокусе, соответствуют подписям, единая обработка;
- движение: конечные состояния появлений — видимые; ничего не дёргается на снимках прокрутки;
- 3D: холст на месте, не перекрывает текст, на телефоне не пустой;
- регресс: красные зоны в diff совпадают с планом; зоны «не трогать» без изменений; высота страницы изменилась объяснимо.

Число из `verify.mjs` скилла design-reference — расхождения с собственной
дизайн-системой — тоже в отчёт.

## Функции

Все ссылки шапки и подвала ведут туда, куда написано (обход через
`runtime.mjs --click` или chrome-devtools `list_network_requests`); якоря
прокручивают к нужной секции; формы: обязательные поля, маска, согласие,
сообщение после отправки, письмо/запись доходит (если есть доступ к
бэкенду — проверить, если нет — записать «отправка не проверена»); слайдеры
листаются кнопками и свайпом; вкладки и аккордеоны открываются с клавиатуры;
диалоги закрываются по Esc и по клику вне; 404 существует.

## Телефон

`mobile` 390 px и `tablet` 834 px обязательны; `laptop` 1280 — когда сетка
трёхколоночная. Смотреть: первый экран (заголовок, действие, «позвонить»),
меню, формы (16 px, 44 px цели), таблицы, картинки (не крупнее показанного,
`a11y.mjs --viewport mobile` и `perf.mjs`), горизонтальная прокрутка
(`runtime --scroll`), липкая шапка не выше 15% экрана.

## Скорость

```
node scripts/perf.mjs <url>                     # телефон, ×4 процессор, fast3g — как у покупателя
node scripts/perf.mjs <url> --viewport desktop --net none --cpu 1
```

Сравнивать с базой из разведки: `perf/*.json`. Ухудшение любого бюджета
после правок — задача, а не примечание. Когда виноват конкретный скрипт
или картинка и `perf.mjs` не показывает, кто, — `performance_start_trace`
в chrome-devtools и `performance_analyze_insight`. Скорость проверять
после: новых картинок, шрифтов, библиотек, 3D, анимаций на прокрутке.

**Кто сдвинул вёрстку (CLS).** Наблюдатель, поставленный после загрузки,
ранние сдвиги не видит. Ставить его до всех скриптов страницы:

```
node scripts/runtime.mjs <url> --init "window.__ls=[];new PerformanceObserver(l=>{for(const e of l.getEntries())if(!e.hadRecentInput)window.__ls.push({v:e.value,t:Math.round(e.startTime),src:(e.sources||[]).map(s=>(s.node&&s.node.tagName?s.node.tagName+'#'+s.node.id+'.'+s.node.className:'text')+' y'+Math.round(s.previousRect.y)+'→'+Math.round(s.currentRect.y)+' h'+Math.round(s.previousRect.height)+'→'+Math.round(s.currentRect.height))})}).observe({type:'layout-shift',buffered:true})" --wait 3000 --eval "window.__ls"
```
В `src` — элементы, которые поехали, и на сколько. Типичные виновники:
подмена шрифта меняет число строк заголовка (лечится запасным шрифтом с
`size-adjust`, подогнанным по замеру ширины, и запасом ширины в
контейнере, а не `ch`-единицами), картинки без `width/height`, вставка
блоков над содержимым, липкая шапка, меняющая высоту.

## Доступность

```
node scripts/a11y.mjs <url> --viewport mobile
node scripts/a11y.mjs <url>
```
плюс `lighthouse_audit` (chrome-devtools) для полного списка по WCAG и SEO.
Без `FAIL` в `a11y.mjs`; `WARN` — с решением в отчёте. Скилл
`design:accessibility-review` — когда нужен разбор конкретного экрана.

## Регресс: что не должно было измениться

Отдельно, не вместе с проверкой нового:

- diff по страницам и зонам из матрицы «не трогать» — ноль или объяснимо;
- контакты, цены, юридические тексты, ссылки на документы — те же (сверить текстом через `evaluate`);
- формы уходят туда же (`action`, поля, скрытые поля);
- аналитика и счётчики на месте;
- проектные тесты, если они есть (`npm test`, smoke, e2e, скилл `predrelease`), — зелёные.

## Условие завершения

Все задачи P0–P2: `impl=DONE`, `runtime=VERIFIED`, `visual=VERIFIED`,
`mobile=VERIFIED` (или `NA` с причиной); `perf` не хуже базы; `a11y` без
`FAIL`; проектные тесты зелёные; регресс чист. Если что-то из этого не
достигнуто — либо ещё круг, либо строка в «Что осталось» отчёта с
настоящим статусом. Третьего варианта («почти готово») нет.
