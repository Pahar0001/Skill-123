# Разведка: визуальный разбор, дизайн-система, референсы

Скрипт `discover.mjs` даёт факты. Этот файл — про то, что из фактов и
снимков нужно **сформулировать словами**, потому что план строится на
формулировках, а не на числах.

```
node ~/.claude/skills/site-rework/scripts/discover.mjs <url> [--out <папка прогона>] [--viewports desktop,tablet,mobile] [--keep-consent] [--no-clicks] [--no-pages] [--pages-shots N]
     [--no-design] [--light] [--no-320] [--no-hover] [--no-texture] [--scheme dark] [--tag discover] [--strict]
```

| флаг | что делает |
|---|---|
| `--viewports` | экраны через запятую: `desktop`, `laptop`, `tablet`, `mobile`, `mobile-s` (320), `android` (360), `ШxВ@плотность`, одна ширина; по умолчанию `desktop,tablet,mobile`; `--viewport` — то же самое |
| `--no-320` | без отдельного прохода на 320 px (он ищет только переполнение, без снимков; делается, если 320 нет в списке) |
| `--no-design` | без дизайн-системы (скилл `design-reference`) |
| `--light` | без серии снимков по прокрутке — быстрее; палитра сверяется по first/full |
| `--no-hover` | не наводить мышь на карточки, разбирая блоки, невидимые после прокрутки |
| `--no-texture` | не мерить фактуру по пикселям (слои всё равно перечисляются) |
| `--no-texture-module` | запасной путь без `texture.mjs` (для проверки) |
| `--tag` | подпапка снимков, по умолчанию `discover`; `--tag before` — старое поведение |
| `--keep-consent` | не закрывать окно cookie. По умолчанию оно закрывается до первого снимка: «Accept all» / «Accept» / «Принять» / «Согласен» / «OK», иначе «Reject» / «Отклонить», иначе крестик (и во фреймах CMP, и в shadow DOM); что закрыто — в «Технике» |
| `--no-clicks` | не нажимать на аккордеоны и переключатели меню. По умолчанию нажимаются до 2 пунктов в группе, до 4 групп и до 2 переключателей; ссылки на другие адреса не нажимаются |
| `--no-pages` | без раздела «Страницы сайта по типам» (по умолчанию он строится из ссылок страницы и `/sitemap.xml`, без захода на страницы) |
| `--pages-shots N` | снять по одной странице каждого из N типов (вся страница + h1–h3) в `pages/`; по умолчанию 0. Для донора — обязательно (`reference/donor-mode.md` §1) |
| `--strict` | код выхода 1, если в итоге есть FAIL (переполнение, не снявшийся экран); без него код 0 |
| `-h`, `--help` | справка, ничего не запускает |

`discovery.json` и `discovery.md` пишутся **до** шага дизайн-системы и
дописываются после: если `design-reference` упадёт, разведка уже на диске.
Снимки разведки лежат в `discover/` — они для взгляда. Набор «до» для
сравнения с «после» снимает только `shots.mjs --tag before`.

## Что открыть глазами и в каком порядке

1. `discover/desktop-first.png` — первое впечатление: что сайт обещает за три секунды.
2. `discover/mobile-first.png` — то же на телефоне: помещается ли обещание, видна ли кнопка.
3. `discover/desktop-scroll-sheet.png` — вся прокрутка листом: порядок секций, ритм, где «провисает».
4. `discover/*-scroll-NN.png` — снимки окна равномерно по всей высоте: появления, подгрузка, **закреплённые слои**.
5. `discover/*-full.png` — вся страница. Закреплённое (зерно, шапка, нижняя
   панель) на ней есть только в верхнем экране: фактуру по full не судить.
6. `runtime/*.png` — меню, диалоги, состояния наведения после базового прогона.
7. `pages/*.png` (с `--pages-shots`) — по странице каждого типа: что там и нужен ли нам аналог.
8. `motion/<tag>.md` и вырезки `motion/<tag>/mNN.png` (`motion.mjs`) — всё движение числами.

Большой снимок `Read` может показать мелко: сначала `first`, потом лист,
при нужде — `scroll-NN` по частям. Фактуру и тонкие линии — только
вырезками 1:1 (`texture.mjs` кладёт их в `discover/texture/`).

## Визуальный разбор — заполнить в `<папка>/analysis.md`

Не «цвет красивый», а правило, по которому другой человек соберёт
похожую страницу. Не «тёмный премиум с акцентным золотом», а «рамка 4 px
r30 вокруг абзаца, без заливки».

| пункт | что записать | пример формулировки |
|---|---|---|
| Язык дизайна | одним-двумя словами и пояснением | «плотная витринная сетка на сером, чёрные плашки-этикетки» |
| Иерархия | что читается первым, вторым, третьим; работает ли | «h1 доминирует, кнопка теряется на фоне картинки» |
| Композиция | сетка, выравнивание, симметрия, ширина контента | «одна колонка 1100 px, всё по центру, секции одной высоты» |
| Отступы и плотность | ритм из `design/site.tokens.css` и ощущение | «секции по 150 px, внутри плотно — контраст уместен» |
| Типографика | пары гарнитур, шкала, регистр, разрядка, кириллица | «гротеск 900 капсом рядом с антиквой; разрядки нет нигде» |
| Цвет | роли по темам (тёмные и светлые секции): фон, текст, приглушённый, акцент; сколько акцента **на экране** | «акцента нет: жёлтый есть только в CSS, на снимках 0%» |
| Фактура и свет | зерно, шум, стекло, плёнки, свечение: чем сделано, где лежит, какой силы (σ), движется ли, на каких экранах | «зерно поверх всего, включая чёрное: плитка 4 кадра по 100 мс, opacity .07, normal, σ ≈ 5 на чёрном и сером; только ≥1200 px» |
| Картинки | тип, качество, пропорции слотов, обработка, соответствие подписям | «фото товара 4:5 cover, без плёнок; стоковые с чужой кухней — снижают доверие» |
| Иконки | стиль (линейные / залитые / эмодзи), единство | «иконки из трёх наборов» |
| Компоненты | кнопки, карточки, формы, навигация: радиусы, границы, состояния | «кнопки — пилюли r30 без разрядки, все капсом» |
| Движение | язык движения: какие блоки появляются и как, длительности, кривые | «при прокрутке появляется один блок сверху −100 px; подписи карточек — при наведении» |
| Необычные черты | 3–5 приёмов, по которым сайт узнают с одного экрана, каждый с кропом | «плавающая пилюля-меню внизу; бегущая строка; огромный наклонённый кадр» |
| Чего донор не делает никогда | числами из «Паспорта донора» | «разрядка ≥ .05em: 0 из 21 кнопки; радиусы 8–12: 0; форм: 0» |
| Характер бренда | три прилагательных сейчас и три, которых ждёт запрос | «сейчас: дешёвый, шумный; надо: спокойный, точный» |

## Разделы `discovery.md`, на которые опираться

**Кнопки и карточки-ссылки.** Кнопка — компактный элемент с заливкой у себя или у вложенного блока
(Framer); стиль текста — от видимого текста внутри. Ссылка с картинкой или коробка от 120 px —
«Карточки-ссылки», у них своя роль в паспорте. Кнопки окна cookie не считаются.

**Цвета и акцент.** Каждый пиксель — одному ближайшему цвету; «≈» — оттенки ближе ΔE 3. Заливка кнопок —
в их коробках (меньше 20% — WARN). **Акцент** — цвет действий: цветная заливка кнопок (в том числе у
вложенного блока), сначала на первом экране; нет таких — цвет ссылок при наведении; фоны секций, шапки и
подвала — не акцент (так же считают extract и cliche).

**FAQ и аккордеоны.** details, aria-expanded и «свои» пункты (значок + спрятанный ответ), подтверждённые
кликом. «Наведение, не аккордеон» и «клик не раскрыл» аккордеонами не считаются.

**Переключатель меню.** Селектор и итог клика; проверка — `runtime.mjs <url> --viewport mobile --click
"<селектор>" --shot menu` (готовая команда — в выводе).

**Картинки донора.** Хостинг и ссылки на лицензию/условия; материалы донора без законного получения не берём.

**Страницы сайта по типам.** Шаблон адреса → адресов по ссылкам (ссылок) → в sitemap.xml → где ссылки →
пример. Для донора — основа таблицы «тип страницы → что там → аналог → совет» и вопроса пользователю.

**Движение** — в `discovery.md` только наличие (сколько анимаций, появления, закреплённые). Числами —
`motion.mjs` (`reference/motion.md`).

**Паспорт донора: есть / нет.** Что у сайта есть — только эти значения и
брать: радиусы видимых коробок, кегли, начертания, капс и разрядка по
ролям (кнопки, навигация, подписи, заголовки, текст), стили кнопок, поля.
Что нет — список компонентов (форма, поля, аккордеон, вкладки, слайдер…):
их **проектировать из языка донора**, а не по умолчанию
(`reference/authorship.md`). «Чего донор не делает никогда» — числами:
это рамка, за которую своё решение без причины не выходит.

**Фактура (параметры для переноса).** Замер `texture.mjs`: слой, его файл
(кадры, мс), прозрачность, режим наложения, `image-rendering`, условие
`@media`; σ по полосам фона (тёмная, средняя, светлая) по вкладу слоя —
снимок со слоем минус без. Диагнозы: «multiply гасит на тёмном», «слой
есть, но не виден», «на снимке σ 1.8 — не зерно (картинки)». Рецепт готов,
а блок переменных `--grain-*` discover сам дописывает в конец
`design/site.tokens.css` (между `/* texture:start */` и `/* texture:end */`),
если хоть на одном экране зерно измерено («есть» или «нет»); иначе причина —
в `discovery.md`, раздел «Дизайн-система». Как переносить —
`reference/engines.md` → «Фактура».

**Подписные приёмы.** Числа из вычисленных стилей для крупных наклонов и
скосов (> 3°), стекла (`backdrop-filter`), крупного текста (кегль в vw,
интерлиньяж, разрядка, вылезает ли за край), обрезок по диагонали
(`clip-path` с углами). Переносить приём с этими значениями, а не «наклон
вообще».

**Медиа-слоты.** Роль (первый экран, карточки, фон секции, вставка),
показанный размер, пропорции, вписывание (`object-fit`, `background-size`),
плёнки и градиенты поверх, фильтр, фото или графика; доля фото на странице
и на первом экране. Это запрос к подбору кадров (`media.mjs search`):
пропорции, роль, обработка.

**Визуал (замеры).** Вес цвета = видимая площадь × итоговая прозрачность;
вуали и зерно — не в палитре. У каждого цвета — доля пикселей на снимках:
меньше 0.1% — «в CSS есть, на экране нет», в дизайн-систему не брать.

**Движение.** Идут, бесконечные, **держат значение** (закончились с
`fill: both/forwards`) — и предупреждение «наведение перебито
удерживающей анимацией», если `:hover` целится в то же свойство.
Появления при прокрутке считаются по тем, что действительно изменились
за проход; постоянно сдвинутое и бегущая строка — не в счёт. Невидимые
после прокрутки — группами, с проверкой наведением на карточку («58 × «О
БРЕНДЕ» — появляются при наведении, норма»).

**Ошибки и сбои.** Консоль и исключения, упавшие запросы, переполнение по
ширине **по элементам** (включая fixed-панели; на 320 — отдельным
проходом), WARN, если прокрутка не дошла до низа.

## Что сохранять

Отдельный список **сильных сторон**: то, что работает и трогать нельзя
(узнаваемый цвет, удачный первый экран, честные фото, короткая форма).
Он входит в матрицу «не трогать» и защищает результат от переделки ради
переделки. Ограничения из брифа — туда же. Каждая строка «сохранить»
потом проверяется отдельно — снимком или числом (фактура — `texture.mjs
compare`).

## Дизайн-система

`discover.mjs` через скилл `design-reference` кладёт `design/site.tokens.css`
и `design/site.json`: роли цветов по темам, шрифты, шкала, контейнер,
отступы, радиусы, тени, длительности и кривые, фактура, паспорт. Цвета
токенов сверяются с пикселями снимков: токен, которого на экране нет, —
WARN в сводке, в вёрстку не брать. Что дописать руками, посмотрев снимки:

- роли цветов — проверить глазами, особенно акцент (его может не быть совсем — это тоже правило);
- сетка: колонки, желоба, поведение на планшете;
- кнопки: первичная / вторичная / текстовая, состояния наведения, фокуса, нажатия, недоступности;
- карточки, формы, навигация — по одному эталону каждого (чего нет у донора — `reference/authorship.md`);
- границы, радиусы, тени — три уровня, не больше, и только из паспорта;
- движение: тип появления донора (`desktop.motion.scrollReveal` и `mobile.motion.scrollReveal` в `design/site.json`), две длительности, одна кривая;
- иконки: набор и размер;
- картинки: пропорции из медиа-слотов, обработка (цвет, зерно, скругление);
- фактура: в вёрстку — блок `--grain-*` (его дописал discover) со слоем
  `templates/grain.css`; `--texture-opacity` и `--texture-blend` от
  `design-reference` — сырой CSS слоя донора, справочно
  (`reference/engines.md` → «Фактура»).

Все новые правки делать **через эти переменные**. Если нужной переменной
нет — добавить в систему, а не в компонент. Проверка после правок:
`node ~/.claude/skills/design-reference/scripts/verify.mjs <папка>/design/site.json <url>` — покажет,
где новая страница разошлась с собственной системой; сознательные отступления
записать в `<папка>/design/site.ignore` (`.ignore` ищется рядом со спецификацией).

## Референсы и донор

Для каждого адреса из брифа:

```
node ~/.claude/skills/design-reference/scripts/extract.mjs <референс> --out <папка>/refs --name <имя>
```

Затем сравнить с основным сайтом и записать в `analysis.md` раздел
«Референсы»: чем референс сильнее, **почему** это работает, и что из этого
переносится на основной сайт **как принцип**. Не переносятся: тексты,
картинки, логотипы, структура целиком, файлы (в том числе чужой `noise.gif`).
Когда сайт строится с нуля в языке образца — это режим донора,
`reference/donor-mode.md`.

## Техника и структура — что вынести из `discovery.md`

- платформа и её ограничения: конструктор (Tilda, Wix, Webflow) — правки
  через их средства или встроенный код; WordPress — тема и плагины; свой код — исходники;
- переход «с N-й попытки, только DOMContentLoaded» — замеры могли сняться с недогруженной страницы;
- сторонние скрипты: что тянет вес и может ломаться; самое тяжёлое — по байтам из CDP (сжатый размер);
- ошибки консоли и исключения, упавшие запросы — сразу кандидаты в P0;
- переполнение по ширине на телефоне и на 320 — P0/P1;
- шрифты: не загрузившиеся начертания, отсутствие кириллицы;
- холсты: тип контекста (без пробного создания — разведка его не трогает), размыт ли буфер;
- картинки крупнее показанного, без alt, без ленивой загрузки — в план скорости;
- формы: поля, обязательность, согласие, куда уходит — путь к заявке должен быть понятен до правок;
- meta: title, description, viewport, lang — дешёвые P0/P1 находки.
