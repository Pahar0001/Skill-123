# Разведка: визуальный разбор, дизайн-система, референсы

Скрипт `discover.mjs` даёт факты. Этот файл — про то, что из фактов и
снимков нужно **сформулировать словами**, потому что план строится на
формулировках, а не на числах.

## Что открыть глазами и в каком порядке

1. `before/desktop-first.png` — первое впечатление: что сайт обещает за три секунды.
2. `before/mobile-first.png` — то же на телефоне: помещается ли обещание, видна ли кнопка.
3. `before/desktop-full.png` — весь путь: порядок секций, ритм, где «провисает».
4. `before/*-scroll-NN.png` — появления блоков и подгрузка: что выглядит живым, что дёргается.
5. `runtime/*.png` — меню, диалоги, состояния наведения после базового прогона.

Большой full-page снимок `Read` может показать мелко: читать сначала
`first`, потом `full`, при нужде — `scroll-NN` по частям.

## Визуальный разбор — заполнить в `<папка>/analysis.md`

Не «цвет красивый», а формулировка, по которой другой человек соберёт
похожую страницу:

| пункт | что записать | пример формулировки |
|---|---|---|
| Язык дизайна | одним-двумя словами и пояснением | «минимализм с большим воздухом»; «плотная витринная сетка»; «тёмный премиум с акцентным золотом»; «дружелюбный, скруглённый, пастельный» |
| Иерархия | что читается первым, вторым, третьим; работает ли | «h1 доминирует, кнопка теряется на фоне картинки» |
| Композиция | сетка, выравнивание, симметрия, ширина контента | «одна колонка 1100 px, всё по центру, секции одной высоты» |
| Отступы и плотность | ритм из `design/site.tokens.css` и ощущение | «секции по 96 px, внутри плотно — контраст уместен» |
| Типографика | пары гарнитур, шкала, регистр, кириллица | «Bebas Neue в капсе + Inter; заголовки без кириллицы падают в Arial» |
| Цвет | роли: фон, поверхность, текст, приглушённый, акцент, граница; насколько выдержано | «акцент один, но кнопки трёх разных заливок» |
| Картинки | тип (фото / иллюстрация / 3D / нет), качество, соответствие подписям | «стоковые фото с чужой кухней — снижают доверие» |
| Иконки | стиль (линейные / залитые / эмодзи), единство | «иконки из трёх наборов» |
| Компоненты | кнопки, карточки, формы, навигация: радиусы, тени, границы, состояния | «карточки с тенью 0 8 24, кнопки без hover» |
| Движение | есть ли язык движения: длительности, кривые, появления, сколько всего | «появления снизу 600 мс каскадом; бесконечный пульс на кнопке мешает» |
| Характер бренда | три прилагательных, которые сайт транслирует сейчас, и три — которых ждёт запрос | «сейчас: дешёвый, шумный, старый; надо: спокойный, дорогой, точный» |

## Что сохранять

Отдельный список **сильных сторон**: то, что работает и трогать нельзя
(узнаваемый цвет, удачный первый экран, честные фото, короткая форма).
Он входит в матрицу «не трогать» и защищает результат от переделки ради
переделки. Ограничения из брифа — туда же.

## Дизайн-система

`discover.mjs` через скилл `design-reference` кладёт `design/site.tokens.css`
и `design/site.json`: роли цветов, шрифты, шкала, контейнер, отступы,
радиусы, тени, длительности и кривые. Что дописать руками, посмотрев снимки:

- роли цветов — скрипт назначает автоматически и может перепутать акцент и ошибку;
- сетка: колонки, желоба, поведение на планшете;
- кнопки: первичная / вторичная / текстовая, состояния наведения, фокуса, нажатия, недоступности;
- карточки, формы, навигация — по одному эталону каждого;
- границы, радиусы, тени — три уровня, не больше;
- движение: две длительности (короткая для наведения, длинная для появления), одна кривая, одно правило каскада;
- иконки: набор и размер;
- картинки: пропорции, обработка (цвет, зерно, скругление).

Все новые правки делать **через эти переменные**. Если нужной переменной
нет — добавить в систему, а не в компонент. Проверка после правок:
`design-reference/scripts/verify.mjs design/site.json <url>` — покажет,
где новая страница разошлась с собственной системой; сознательные отступления
записать в `design/site.ignore`.

## Референсы

Для каждого адреса из брифа:

```
node ~/.claude/skills/design-reference/scripts/extract.mjs <референс> --out <папка>/refs --name <имя>
```

Затем сравнить с основным сайтом и записать в `analysis.md` раздел
«Референсы»: чем референс сильнее (в терминах таблицы выше — воздух, шкала,
одна гарнитура, тон фото), **почему** это работает, и что из этого
переносится на основной сайт **как принцип**. Не переносятся: тексты,
картинки, логотипы, структура целиком, конкретные значения без адаптации
к своей палитре. Границу держать жёстко: точная копия чужого сайта —
юридическая и репутационная проблема заказчика.

## Техника и структура — что вынести из `discovery.md`

- платформа и её ограничения: конструктор (Tilda, Wix, Webflow) — правки
  через их средства или через встроенный код; WordPress — тема и плагины;
  свой код — исходники;
- сторонние скрипты: что тянет вес и может ломаться;
- ошибки консоли и упавшие запросы — сразу кандидаты в P0;
- горизонтальная прокрутка на телефоне — P0/P1;
- шрифты: не загрузившиеся начертания, отсутствие кириллицы;
- картинки крупнее показанного, без alt, без ленивой загрузки — в план скорости;
- формы: поля, обязательность, согласие, куда уходит — путь к заявке должен быть понятен до правок;
- meta: title, description, viewport, lang — дешёвые P0/P1 находки.
