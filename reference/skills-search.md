# Чужие навыки: найти, проверить, поставить

Нужен, когда под задачу не хватает умения (формат документа, библиотека движения, сервис),
и есть смысл взять готовый навык, а не писать свой. Чужой навык — это чужие инструкции модели
и чужие скрипты на этой машине: без проверки не ставить.

## Где искать

- **Skillry — [skillry.ai](https://skillry.ai)**: открытый каталог SKILL.md от сообщества — категории,
  оценки, число скачиваний. На странице навыка есть ссылка «source ↗» на SKILL.md в GitHub — её
  и отдавать на проверку. Лицензию и состав каталог не показывает.
- **[github.com/anthropics/skills](https://github.com/anthropics/skills)** — навыки Anthropic и
  спецификация. Большинство под Apache-2.0; docx, pdf, pptx, xlsx — «source-available», не
  свободные: для себя можно, раздавать нельзя. Там же ставятся плагином
  (`/plugin marketplace add anthropics/skills`), но плагин — это набор целиком, см. «Видимость».
- **Списки**: [travisvn/awesome-claude-skills](https://github.com/travisvn/awesome-claude-skills)
  (про Claude Code, живой в 2026, прямо требует читать SKILL.md и скрипты перед установкой),
  [ComposioHQ/awesome-claude-skills](https://github.com/ComposioHQ/awesome-claude-skills)
  (самый большой, по категориям). Список — указатель, а не проверка.
- **Проверенные авторы**: [emilkowalski/skills](https://github.com/emilkowalski/skills) (MIT, только
  текст), [pbakaus/impeccable](https://github.com/pbakaus/impeccable) (Apache-2.0, с лаунчером),
  [motiondivision/ai-kit](https://github.com/motiondivision/ai-kit) (MIT по package.json).

## Как выбрать

- **Одна задача.** Описание называет конкретное дело. «Любая задача по интерфейсу» — такой навык
  будет перехватывать просьбы у уже встроенных (impeccable, донор, site-rework).
- **Лицензия.** MIT, Apache-2.0, ISC, BSD — можно и для клиентов. Нет лицензии, NC или
  проприетарная — только для себя, в проекты клиентов не нести.
- **Что внутри важнее звёзд.** Только текст лучше скриптов; скрипты — читать; бинарники,
  лаунчеры и установщики «одной командой» (`npx … add`, `curl … | sh`) — не запускать.
- **Пересечения.** Навык про то же, что уже стоит, — правило владельца: **оставить лучший,
  остальные выключить, не удалять**. `install` печатает список похожих.
- **Живость.** Последний коммит и ответы на issue — вторично: старый навык из одного SKILL.md
  лучше свежего с установщиком.

## Проверка — `skill-audit.mjs audit`

```
node ~/.claude/skills/site-rework/scripts/skill-audit.mjs audit https://github.com/<автор>/<репозиторий>
node ~/.claude/skills/site-rework/scripts/skill-audit.mjs audit "<ссылка source ↗ со Skillry>"
node ~/.claude/skills/site-rework/scripts/skill-audit.mjs audit <папка или файл.zip> --out <протокол.json>
```

Скачивает zip ветки с codeload.github.com во временную папку (не клон, не в домашнюю), распаковывает
своим кодом и только читает. На каждый навык — таблица «пункт | итог | где | что делать»:
frontmatter, широта описания, `allowed-tools`, команды при загрузке (`` !`…` ``, ` ```! `), хуки,
«папка — плагин», сеть, установки, запуск программ, удаление, отправка наружу, секреты, настройки
Claude, обфускация, невидимые знаки, лицензия, размер. **FAIL — не ставить**; WARN — прочитать
строку по `файл:строка` и решить. Распакованное остаётся во временной папке — там и смотреть.

Пределы: поиск по образцам, смысла не понимает. Новый приём или длинный запутанный код может
пройти — SKILL.md и скрипты всё равно прочитать глазами.

## Установка — `skill-audit.mjs install`

```
node …/skill-audit.mjs install <источник> --skill <имя>            план: что и куда, WARN, пересечения
node …/skill-audit.mjs install <источник> --skill <имя> --yes      поставить
node …/skill-audit.mjs install <источник> --skill <имя> --exclude scripts/launcher.sh --yes
```

Ставит **одну** папку в `~/.claude/skills/<имя>`, ничего из неё не запуская. Отказ, если в навыке
или в архиве FAIL и если папка уже есть (старую убрать или переименовать самому). Рядом пишет
`ORIGIN.txt`: источник, коммит, лицензия, итог аудита, что изменено; лицензию из корня репозитория
кладёт рядом. `--exclude` — взять навык без опасной части (лаунчер, установщик) — это отметится
в ORIGIN.txt. Пакеты, которые навык просит (`npm i`, `pip install`), — отдельно и с согласия.

## Видимость — `skillOverrides` в `~/.claude/settings.json`

| значение | в списке у Claude | в меню `/` |
|---|---|---|
| `"on"` (по умолчанию) | имя и описание | да |
| `"name-only"` | только имя | да |
| `"user-invocable-only"` | скрыт — только вручную | да |
| `"off"` | скрыт | скрыт |

```json
"skillOverrides": { "ui-ux-pro-max": "user-invocable-only", "motion": "name-only", "frontend-design": "off" }
```

Широкое описание — `name-only` (Claude видит только имя и зовёт по имени) или `user-invocable-only`
(только вручную). Пересечение — лишний в `"off"`. **Навыки плагинов `skillOverrides` не скрывает**:
только весь плагин — `"enabledPlugins": { "<плагин>@<каталог>": false }` или меню `/plugin`.
Правит настройки владелец или по его слову; скрипт их только читает.

## Как было у владельца

- **impeccable.** Лаунчер `scripts/impeccable` качает с GitHub и запускает бинарник движка (плюс
  телеметрия). `audit` даёт FAIL «скачать и выполнить: скачивает программу (стр. 97) и запускает
  (стр. 42)». Поставлен без лаунчера (папка переименована в `scripts.disabled`), причина — в ORIGIN.txt;
  сейчас то же делает `--exclude scripts`.
- **UI UX Pro Max.** Описание «designing, building, reviewing, or fixing interfaces…» — WARN широта:
  перебивал бы impeccable и донора. Взят один навык из семи (остальные ходят в сеть),
  `skillOverrides: "user-invocable-only"`, используется как база данных.
- **Motion (ai-kit).** Пересекается с `animate` Эмиля по «animation, spring, transition» —
  `name-only`.
- **Firecrawl.** Установщик `init --all` разложил 28 навыков сразу по четырём агентам; семь
  пересекались с уже стоящими — выключены `"off"`. Так не ставить: по одной папке через `install`.
