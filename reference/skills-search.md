# Чужие навыки: найти, проверить, поставить

Нужен, когда под задачу не хватает умения (формат документа, библиотека движения, сервис),
и есть смысл взять готовый навык, а не писать свой. Чужой навык — это чужие инструкции модели
и чужие скрипты на этой машине: без проверки не ставить.

## Где искать

- **Skillry — [skillry.ai](https://skillry.ai)**: открытый каталог SKILL.md от сообщества — категории,
  оценки, число скачиваний. На странице навыка есть ссылка «source ↗» на SKILL.md в GitHub — её
  и отдавать на проверку. Лицензию и состав каталог не показывает.
- **[github.com/anthropics/skills](https://github.com/anthropics/skills)** — навыки Anthropic и
  спецификация. Большинство под Apache-2.0; docx, pdf, pptx, xlsx — «source-available», не
  свободные: для себя можно, раздавать нельзя. Там же ставятся плагином
  (`/plugin marketplace add anthropics/skills`), но плагин — это набор целиком, см. «Видимость».
- **Списки**: [travisvn/awesome-claude-skills](https://github.com/travisvn/awesome-claude-skills)
  (про Claude Code, живой в 2026, прямо требует читать SKILL.md и скрипты перед установкой),
  [ComposioHQ/awesome-claude-skills](https://github.com/ComposioHQ/awesome-claude-skills)
  (самый большой, по категориям). Список — указатель, а не проверка.
- **Проверенные авторы**: [emilkowalski/skills](https://github.com/emilkowalski/skills) (MIT, только
  текст), [pbakaus/impeccable](https://github.com/pbakaus/impeccable) (Apache-2.0, с лаунчером),
  [motiondivision/ai-kit](https://github.com/motiondivision/ai-kit) (MIT по package.json).

## Как выбрать

- **Одна задача.** Описание называет конкретное дело. «Любая задача по интерфейсу» — такой навык
  будет перехватывать просьбы у уже встроенных (impeccable, донор, site-rework).
- **Лицензия.** MIT, Apache-2.0, ISC, BSD — можно и для клиентов. Нет лицензии, NC или
  проприетарная — только для себя, в проекты клиентов не нести.
- **Что внутри важнее звёзд.** Только текст лучше скриптов; скрипты — читать; бинарники,
  лаунчеры и установщики «одной командой» (npx с подкомандой add; скачивание curl, вывод которого
  сразу передаётся в оболочку sh) — не запускать.
- **Пересечения.** Навык про то же, что уже стоит, — правило владельца: **оставить лучший,
  остальные выключить, не удалять**. `install` печатает список похожих.
- **Живость.** Последний коммит и ответы на issue — вторично: старый навык из одного SKILL.md
  лучше свежего с установщиком.

## Проверка — `skill-audit.mjs audit`

```
node ~/.claude/skills/site-rework/scripts/skill-audit.mjs audit https://github.com/<автор>/<репозиторий>
node ~/.claude/skills/site-rework/scripts/skill-audit.mjs audit "<ссылка source ↗ со Skillry>"
node ~/.claude/skills/site-rework/scripts/skill-audit.mjs audit <папка или файл.zip> --out <протокол.json>
```

Скачивает zip ветки с codeload.github.com во временную папку (не клон, не в домашнюю), распаковывает
своим кодом и только читает. На каждый навык — таблица «пункт | итог | где | что делать»:
frontmatter, широта описания, `allowed-tools`, команды при загрузке (`` !`…` ``, ` ```! `), хуки,
«папка — плагин», сеть, установки, запуск программ, удаление, отправка наружу, секреты, настройки
Claude, обфускация, невидимые знаки, лицензия, размер. **FAIL — не ставить**; WARN — прочитать
строку по `файл:строка` и решить. Распакованное остаётся во временной папке — там и смотреть.

Находки в стендах и тестах (папки `fixtures`, `__fixtures__`, `test`, `tests`, `__tests__`, `testdata`,
`spec`) показываются отдельно: «вне стендов» и «в стендах и тестах» — в колонке «где» и в итоге.
Итог от этого не мягче: груз можно спрятать и в `tests/`. Строка «FAIL только в стендах и тестах: N;
ссылаются ли на них файлы вне стендов: …» говорит, куда смотреть:

- «да — велят запустить: файл:строка → что» — SKILL.md или скрипт запускает стенд: путь рядом с sh, node,
  python, import; `cd tests && sh setup.sh`; npm test и другие раннеры тестов, когда это команда (в начале
  команды в скрипте оболочки, строкой в exec или subprocess, в блоке кода или в `…` SKILL.md, `scripts.test`
  в package.json — слово pytest в комментарии или в имени навыка и ключ "test" в чужом JSON не считаются);
  перебор папки стенда с import. Считается и чистый файл стенда, который подгружает файл с FAIL. Это повод
  не ставить;
- «ссылок на запуск по образцам не найдено — прочитать глазами» — образцы запуска не нашлись, но это не
  доказательство, что груз мёртвый;
- «упоминают стенды» — путь без запуска (описание папок, аргумент `--exclude`).

`--exclude путь,путь` — не проверять эти пути (от папки навыка при `--skill`, иначе от корня источника).
Это решение того, кто запускает, а не автора навыка: исключённое печатается в начале и в конце вывода
(«исключено при запуске: … (N файлов) — проверено не всё») и пишется в протокол. SKILL.md выбранного
навыка не исключается (и `skill.md` строчными тоже); вложенные навыки в исключённой папке уходят вместе
с ней — строка называет их число. Подсказка «Поставить один» переводит шаблоны в пути от папки навыка.
У чужого навыка исключать можно только то, что прочитано глазами.

«Настройки Claude» — запись или удаление:

- FAIL: `settings.json`, `CLAUDE.md`, `.mcp.json`, хуки, агенты, команды, плагины и другие поверхности
  Claude; SKILL.md своего или чужого навыка (после проверки навык стал бы другим); содержимое папки или
  архива и `git pull` в свою папку навыка (`${CLAUDE_SKILL_DIR}`, папка скрипта и выше) — «переписывает
  навык целиком после проверки»; файл прямо в корне `~/.claude`; содержимое папки или архива в корень
  (rsync папки со «/» на конце, `cp папка/.`, `tar -C`, `unzip -d`, распаковка из кода); `git pull`,
  `checkout`, `apply` в корне `~/.claude`; ссылка на саму папку Claude (символическая, жёсткая или
  junction) — запись через неё по строке не видна. `settings.json` без папки Claude — тоже FAIL, кроме
  папки другой программы (см. WARN) и обычной своей (`out/settings.json` — ничего);
- WARN: `~/.claude/skills` и своя папка вроде `~/.claude/site-rework` («пишет в ~/.claude/<папка> —
  рабочие данные?»); `settings.json` и `keybindings.json` другой программы — `.vscode`, `Code/User`,
  `.cursor`, `.idea`, `.zed` и папка программы под домашней или системной папкой (`~/.config/app`,
  `%APPDATA%\App`) — «пишет settings.json другой программы (VS Code) — не Claude; посмотреть, зачем»:
  настройки Claude не тронуты, но навык правит настройки редактора или чужой программы.

«Откуда» у копирования только читается, у `mv`, `ln` и `cp -s`, `cp -l` (ссылка вместо копии) — меняется.
Разбор понимает `$(…)`, `cd` и `cwd` у запуска из кода в папку Claude, путь в переменной и запись строкой
ниже, `path.join`, PowerShell и cmd, команду из кусков строки через «+», запись, разбитую на несколько
строк (перенос «\», аргументы вызова на следующих строках, сплаттинг PowerShell); что не разобрать — идёт
в счёт.

Нижняя граница. Разбор точнее прежнего правила («команда записи и имя настроек Claude в одной строке»),
но не слабее его: где прежнее правило срабатывает, итог ниже только когда разбор понял, чем занято
каждое такое имя — оно только читается (копия настроек наружу, `cat`, `jq`), разобрано как назначение
и не поверхность Claude (`out/settings.json` — ничего, `.vscode/settings.json` — WARN) или стоит
в комментарии. Иначе
остаётся находка «в строке команда записи и имя настроек Claude — куда идёт запись, разбор не понял;
проверить глазами». Так ловятся формы, которых разбор не знает: команда как данные во вложенных кавычках,
имя файла в переменной на той же строке, команда в прозе без кавычек.

Пределы: поиск по образцам, смысла не понимает. Новый приём или длинный запутанный код может
пройти — SKILL.md и скрипты всё равно прочитать глазами.

## Проверить сам site-rework

```bash
node ~/.claude/skills/site-rework/scripts/skill-audit.mjs audit ~/.claude/skills/site-rework --skill site-rework --exclude scripts/fixtures/skill-audit,scripts/skill-audit.mjs
```

Без `--exclude` итог — FAIL, и это не про навык: в `scripts/fixtures/skill-audit` лежат нарочно опасные
стенды самопроверки, а в `skill-audit.mjs` — образцы опасных строк (в выражениях поиска и в самих
проверках). С исключением (15 файлов, из них 6 вложенных навыков-стендов; строка «исключено при запуске»
в начале и в конце) ждать итог **WARN**: 9 пунктов WARN, ни одного FAIL (06.10.2026; до стендов Blender и deploy-check было 8). WARN по делу:

- сеть — `fetch` и http в скриптах, которые снимают сайты, ищут фото и шрифты (discover, mirror, texture,
  typeset, media/net и другие), `curl` в runtime, сокет в serve;
- установки — `git clone` навыка, `npm ci` и `npx` в README; подсказки «поставить: npm i … --prefix
  ~/.claude/site-rework», когда нет puppeteer-core, sharp или ffmpeg (lib, media, media/video, texture,
  grain-tile, SKILL.md, environment.md); `winget install gitleaks` в security.mjs и security.md (ставит
  программы в систему); примеры `git clone`, `npm`, `pip install` в этом файле (ставит пакеты Python);
- запуск программ — `child_process` в скриптах: браузер, ffmpeg, git, свои самопроверки;
- удаление — `fs.rmSync` своих временных папок;
- секреты — «файл .env»: security.mjs проверяет, не отдаёт ли сайт `/.env` и другие служебные файлы
  (24 находки), ключи медиа и Firecrawl читаются из `~/.claude/site-rework/.env` (media, media/net,
  recraft, firecrawl, справочники, `templates/deps/.env.example`); «ключ из окружения» — имена вроде
  `PEXELS_API_KEY` и `FIRECRAWL_API_KEY` (firecrawl, media, media/photo, media/video, образец .env);
  «файлы учётных данных» — `/.npmrc` в том же списке security.mjs;
- настройки Claude — `git clone` в `~/.claude/skills` (README), «пишет в ~/.claude/site-rework — рабочие
  данные?» (README — рабочая папка навыка; ideas.mjs — журнал идей в `~/.claude/site-rework/taste`),
  подключение MCP в README и donor-mode.md;
- обфускация — `new Function` и `eval` функций для страницы (lib, discover, runtime, typeset) и base64
  картинок (recraft, texture, perf);
- лицензия — файла LICENSE нет;
- размер и файлы — не текст в стендах: шрифты самопроверок (woff2, OFL), `scripts/fixtures/blender/stack.glb`
  («двоичный файл неизвестного вида»), PDF-заглушка стенда deploy-check, два документа Office.

Строки «FAIL только в стендах и тестах» здесь нет: FAIL в стендах остаётся только в исключённой папке.

Появился FAIL — разобрать по `файл:строка` до коммита: либо это новая опасная строка в навыке, либо
пример в справочнике надо переписать словами, как про установщики «одной командой» выше.

## Установка — `skill-audit.mjs install`

```
node …/skill-audit.mjs install <источник> --skill <имя>            план: что и куда, WARN, пересечения
node …/skill-audit.mjs install <источник> --skill <имя> --yes      поставить
node …/skill-audit.mjs install <источник> --skill <имя> --exclude scripts/launcher.sh --yes
```

Ставит **одну** папку в `~/.claude/skills/<имя>`, ничего из неё не запуская. Отказ, если в навыке
или в архиве FAIL и если папка уже есть (старую убрать или переименовать самому). Рядом пишет
`ORIGIN.txt`: источник, коммит, лицензия, итог аудита, что изменено; лицензию из корня репозитория
кладёт рядом. `--exclude` — взять навык без опасной части (лаунчер, установщик) — это отметится
в ORIGIN.txt. Пакеты, которые навык просит (`npm i`, `pip install`), — отдельно и с согласия.

## Видимость — `skillOverrides` в `~/.claude/settings.json`

| значение | в списке у Claude | в меню `/` |
|---|---|---|
| `"on"` (по умолчанию) | имя и описание | да |
| `"name-only"` | только имя | да |
| `"user-invocable-only"` | скрыт — только вручную | да |
| `"off"` | скрыт | скрыт |

```json
"skillOverrides": { "ui-ux-pro-max": "user-invocable-only", "motion": "name-only", "frontend-design": "off" }
```

Широкое описание — `name-only` (Claude видит только имя и зовёт по имени) или `user-invocable-only`
(только вручную). Пересечение — лишний в `"off"`. **Навыки плагинов `skillOverrides` не скрывает**:
только весь плагин — `"enabledPlugins": { "<плагин>@<каталог>": false }` или меню `/plugin`.
Правит настройки владелец или по его слову; скрипт их только читает.

## Как было у владельца

- **impeccable.** Лаунчер `scripts/impeccable` качает с GitHub и запускает бинарник движка (плюс
  телеметрия). `audit` даёт FAIL «скачать и выполнить: скачивает программу (стр. 97) и запускает
  (стр. 42)». Поставлен без лаунчера (папка переименована в `scripts.disabled`), причина — в ORIGIN.txt;
  сейчас то же делает `--exclude scripts`.
- **UI UX Pro Max.** Описание «designing, building, reviewing, or fixing interfaces…» — WARN широта:
  перебивал бы impeccable и донора. Взят один навык из семи (остальные ходят в сеть),
  `skillOverrides: "user-invocable-only"`, используется как база данных.
- **Motion (ai-kit).** Пересекается с `animate` Эмиля по «animation, spring, transition» —
  `name-only`.
- **Firecrawl.** Установщик `init --all` разложил 28 навыков сразу по четырём агентам; семь
  пересекались с уже стоящими — выключены `"off"`. Так не ставить: по одной папке через `install`.
