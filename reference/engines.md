# Движки: картинки, 3D, движение, телефон — и правила реализации

## Правила реализации (Code Agent)

- Правки хирургические: менять то, что в плане, и не переписывать соседнее «заодно».
- Работать через дизайн-систему (`design/site.tokens.css` или переменные самого сайта). Значение, которого нет в системе, — добавить в систему.
- На сайте без сборщика не появляется сборщик; без фреймворка — фреймворк. Библиотека подключается с CDN и только если без неё нельзя.
- Не ломать договорённости платформы: серверные плейсхолдеры, шаблонные переменные, скрипты аналитики, формы с их `action` — не трогать без задачи.
- Каждый компонент — со всеми состояниями: наведение, фокус, нажатие, недоступен, загрузка, ошибка, пусто.
- Семантика: `header/nav/main/section/footer`, один `h1`, кнопки — `button`, ссылки — `a`, картинки с `alt`.
- Всё новое обязано работать без JS хотя бы как статичная версия: содержимое видно, ссылки ведут, форма отправляется.
- После правки — перезагрузить и проверить, что консоль пуста, прежде чем смотреть красоту.

## Картинки и видео

```
Нужен кадр или ролик?
 ├─ нет → не добавлять ради заполнения места
 └─ да → есть подходящий на сайте? → переиспользовать (обрезать, пережать)
          └─ нет → законные бесплатные источники: media.mjs search → лист-контакт глазами → pick
                    └─ не нашлось годного → доработать найденное (кадр, цвет, зерно — под язык сайта)
                              └─ не вышло → генерация (Higgsfield, с согласия и с кредитами)
                                        └─ недоступна → SVG/CSS/canvas-графика или без кадра
```
Графика вместо фото — осознанное решение с причиной в `analysis.md`, а не
выход по умолчанию. Для товара, который покупают глазами (картины, еда,
интерьер, одежда), заглушка-абстракция — P2. Pinterest, Behance, Dribbble —
только доска настроения: ни один файл оттуда на сайт не попадает.

### media.mjs — подбор из бесплатных источников

```
node scripts/media.mjs doctor                                   # ключи (только имена), источники, sharp, ffmpeg
node scripts/media.mjs search "bakery bread" --kind photo --role hero [--profile art] [--orient landscape] [--n 24]
node scripts/media.mjs search "steaming mug" --kind video [--sources commons,mixkit] [--frames 8|all]
node scripts/media.mjs pick <папка поиска> 3 --seen "хлеб на деревянных полках пекарни" --caption "Свежий хлеб утром" \
     --role hero --dest <сайт>/img [--look duotone:#111111,#E9E6E0|mono] [--contrast 0.3] [--grain 0.04] [--crop-mobile 4:5]
node scripts/media.mjs import <страница кадра> [<файл>] --license <из белого списка> --seen … --caption …
node scripts/media.mjs credits <сайт>/img --md <сайт>/CREDITS.md
```

Порядок источников (профиль `photo`): Unsplash и Pexels (по ключу) →
Wikimedia Commons (CC0, «Quality images») → Pixabay (ключ, 1280 — для
карточек) → WordPress Photos → Openverse (только карточки: реальный потолок
500–1024 px). Профиль `art`: The Met, Cleveland, Rijksmuseum, Art Institute
of Chicago, SMK, Commons — общественное достояние с настоящим автором и
названием, как иллюстрация, не как товар и не под вымышленными именами;
срок охраны — по году смерти (жизнь + 70). Видео: Pexels и Pixabay (по
ключу) → Commons (в основном CC BY — подпись обязательна; перезаливы с
YouTube помечены `youtube?` и стоят в конце) → Mixkit (поштучно, одна
страница выдачи на запрос, лицензия `videoFree` проверяется в pick,
Restricted — отказ). Coverr, Videezy, Vecteezy, Freepik — не встраиваются.

Ключи — бесплатная регистрация, в `~/.claude/site-rework/.env` (имена — в
`.env.example`): `PEXELS_API_KEY`, `UNSPLASH_ACCESS_KEY`, `PIXABAY_API_KEY`,
`MEDIA_CONTACT` (контакт для User-Agent по правилам Wikimedia и AIC; личные
данные сами не подставляются). Без ключей работают Commons, Mixkit, музеи,
Openverse. У Unsplash кадр не пережимается у себя: pick выдаёт разметку со
ссылками `images.unsplash.com` по его правилам API.

**Отбор — глазами по листу-контакту** (`<папка>/sheet-1.jpg`): номер,
источник, реальный размер файла, лицензия, флаги `people?`, `brand?`,
`text-or-currency?`, `art?`, `ai?`, `small`. Флаги — подсказка: чужие ценники,
вывески, валюту и лица они пропускают, решает взгляд. Люди в кадре: согласий
моделей у стоков нет (и ст. 152.1 ГК РФ) — для фонов брать кадры без
узнаваемых лиц; руки без лица допустимы.

**Ворота pick**: без `--seen` (что на кадре, своими словами, не меньше трёх
слов) и `--caption` (подпись или роль на сайте) — отказ, код 2; кадр с
флагами — только с `--ok-flags`. Описывать то, что на кадре **после**
обработки (после duotone синий диван — серый).

**Что делает pick с фото**: скачивает лучший размер под роль и никогда не
растягивает («исходник даёт только N px»), проверяет подпись файла, убирает
EXIF и GPS, лестница по длинной стороне (hero 3840/2560/1920/1280, section
2560/1920/1280, card 1280/640), WebP и AVIF плюс JPEG запасной, кадр для
телефона по `--crop-mobile`, одна обработка `--look`/`--contrast`/`--grain`
(зерно в файл не больше 0.06) на все кадры сайта. Пишет запись в
`credits.json` папки назначения и печатает готовую `<picture>` с
`srcset`/`sizes`, `width`/`height`, `loading`, `alt` из `--caption`.

**Что делает pick с видео**: не качает 4K целиком — вырезает отрезок
(`--start`, `--dur`), убирает звук, делает петлю без шва (наплыв `--fade`),
1920×1080 H.264 + WebM VP9, телефон 1280×720 и вертикальный (у 1080p-исходника
вертикальный 606×1080 — не растягивается), постер из кадра стыка. Бюджет:
первый экран ≤2.5 МБ на desktop и ≤1 МБ на телефоне — иначе поднимается CRF;
4K на сайт не отдаётся; без ffmpeg ролик не берётся. Тон видео — CSS на
`<video>`, он же тонирует постер. Печатает `<video autoplay muted loop
playsinline preload="metadata" poster>` с webm и mp4 и заметку про
«меньше движения». Кэш отрезков — `~/.claude/site-rework/cache/video`.

**Обязательный шаг глазами для видео** — лист кадров
`<папка поиска>/check/<имя>-frames.jpg`. Кадр «середина наплыва» показывает,
не «двоит» ли петля (камера движется — на наплыве две полупрозрачные
чашки). Двоит — `--fade 0.4`, другой отрезок или ролик со статичной камерой.
Числом это не ловится.

**Сеть**: DNS через VPN иногда не отдаёт имена — media.mjs повторяет и
пробует DoH; ошибка печатается как «временно, повторить позже». Commons
отдаёт оригиналы с 429 волнами — pick берёт копию и честно пишет об этом;
можно повторить позже. Проверка: `runtime.mjs --video` — poster, пауза вне
экрана и при «меньше движения», вес.

Требования к кадру, любого происхождения:

- пропорция под место — из медиа-слотов разведки: hero 16:9 или 3:2 на десктопе и 4:5 на телефоне — два кадра или `object-position`;
- цвета из палитры сайта, единая обработка (температура, контраст, зерно) на всех кадрах;
- место под текст, если текст поверх: пустая зона, затемнение через переменную, не через «на глаз»;
- вес: WebP/AVIF, `srcset` под 1x/2x, `loading="lazy"` всему ниже первого экрана, `width/height` заданы (иначе CLS);
- **посмотреть глазами каждый**: стоковый кадр с чужой валютой, не тем блюдом, не той страной — хуже пустого места; кадры, противоречащие подписи, снимать;
- лицензия и подпись: `credits.json` → `media.mjs credits` → `CREDITS.md` и строка в подвале, если нужна (CC BY/BY-SA — обязательно); чужие сайты — никогда.

Промпт для генерации собирается из дизайн-системы: язык дизайна словами,
палитра в hex, композиция и пропорция, где пусто под текст, чего не должно
быть (текст на картинке, логотипы, лица, если нужен не портрет).

## Фактура: зерно, шум, плёнки

Фактуру переносят числом, а не на глаз: на уменьшенном снимке зерна не
видно, а multiply-зерно на чёрном даёт ровно ноль.

1. **Замер донора** (или своего сайта «до»):
   ```
   node scripts/texture.mjs <донор> --viewport desktop,tablet,mobile --out <папка>/texture
   ```
   Слои (фон, `img`, `picture`, `svg` с feTurbulence, `canvas`, `video`,
   псевдоэлементы; шум в фоне body/секции), файл текстуры по всем кадрам
   (мс на кадр, σ, альфа), σ по полосам фона — вклад слоя «со слоем − без»,
   кипит ли (два снимка через 250 мс; частота — из файла или `@keyframes`),
   на каких экранах есть (`@media` у слоя). Итог — рецепт и блок `--grain-*`.
2. **Своя плитка** — чужой файл не переносится никогда:
   ```
   node scripts/grain-tile.mjs --out <папка сайта> [--px 2] [--frames 4 --frame-ms 100]
   ```
   Детерминированно (тот же `--seed` — побайтно тот же файл), серая
   непрозрачная плитка 256 px, 16 уровней, σ 78.35; `--check файл` проверяет
   готовую плитку по всем кадрам.
3. **Слой по шаблону** `templates/grain.css`:
   ```
   node scripts/texture.mjs <папка>/texture/texture.json --css <сайт>/grain.css --tokens <сайт>/site.tokens.css
   ```
   Рецепт подставляется без нового замера: прозрачность, режим,
   `image-rendering` как у донора, `@media (min-width)` — где у донора
   зерна нет, число сдвигов «кипения» = число кадров донора. Разметка —
   последним элементом body: `<div class="grain-overlay" aria-hidden="true"></div>`.
   Отдельный элемент, а не `body::after`: чужой `body::after` не затирается.
4. **Сверка**: `texture.mjs compare <донор или его texture.json> <сайт>` → OK
   по всем экранам. Проверено: копия «ХОЛСТа» с шаблоном против
   streetwearbrands — σ 5.04/4.81 против 5.04/5.05, кипение 4×100 мс у обоих.

Правила режимов наложения:

- `normal`, `hard-light`, `luminosity` — одинаковая сила на любом фоне;
  `normal` поднимает чёрный на ≈ opacity × 127 — у плёнки так и есть;
- `multiply`, `overlay`, `soft-light` гаснут на тёмных фонах (Y до ~50):
  на чёрном зерна нет совсем; `overlay` и `soft-light` гаснут и на светлых;
  `screen` — на светлых;
- непрозрачная серая плитка + `opacity = нужная σ / σ плитки` (5 / 78.35 ≈ .064);
- feTurbulence не запрещён, но рисуется на каждый кадр — цену мерить
  `perf.mjs`; альфа шума без `feFuncA` ≈ 0.3, сила зависит от неё;
- на DPR 2 сглаживание делает зерно мягче — повторять `image-rendering`
  донора, сравнивать донора и сайт только при одинаковом DPR;
- «кипение» — сдвиг `::before` трансформацией по `steps(1)`: это работа
  композитора, страница не перерисовывается; при «меньше движения» — стоп.

Контраст текста под зерном — `a11y.mjs` (поправка на слой), цена слоя —
`perf.mjs --overlay`.

## 3D

**Сначала — нужно ли.** По умолчанию 3D нет. Если нужно — предмет
заказчика или объект из языка донора; частицы и сетки точек «для
атмосферы» — в каталоге дефолтов (`reference/authorship.md`). 3D оправдано, когда оно улучшает историю (объект
бренда, который иначе не показать), подачу продукта (вращающийся товар),
иерархию первого экрана (живой фон, который не спорит с текстом) или
взаимодействие (объект отвечает на курсор). Не оправдано: «чтобы было»,
на текстовых сайтах услуг, там, где аудитория со старых телефонов, где
скорость уже на грани.

Подход, от простого к сложному:

| подход | когда |
|---|---|
| CSS 3D-трансформации и перспектива | карточки, лёгкие параллаксы — без WebGL |
| Three.js + процедурная геометрия (сфера, тор, узлы) | объект из языка донора или товара; не «абстракция по умолчанию» |
| Three.js + шейдер (шум, градиент, искажение) | «дорогой» фон, реагирующий на курсор и прокрутку |
| GLB/GLTF модель (своя или из Higgsfield `generate_3d`) | продукт; вес модели ≤ 1–2 МБ, Draco-сжатие |
| React Three Fiber | только если сайт уже на React |

Обязательные элементы реализации:

- инициализация по `IntersectionObserver`: вне экрана не создаём и не рисуем;
- `renderer.setPixelRatio(Math.min(devicePixelRatio, 2))`, размер по контейнеру, `ResizeObserver`;
- пауза рендера вне видимости и при скрытой вкладке;
- `prefers-reduced-motion: reduce` — статичный кадр или отключение;
- запас: если WebGL недоступен или упал — постер (картинка/градиент), текст не зависит от холста;
- на телефоне — меньше частиц/сегментов, или статичный кадр; решение по `perf.mjs --viewport mobile`;
- сцена не мешает читать: контраст текста поверх проверить `a11y.mjs`;
- Three.js с CDN фиксированной версии, документация — через Context7, не по памяти.

**Проверка 3D — только так, никак иначе:**

```
node scripts/runtime.mjs <url> --canvas --shot hero --motion          # рисует, кадр меняется, резкость буфера, кадры/с
node scripts/runtime.mjs <url> --viewport mobile --canvas --resize rotate --shot hero
node scripts/runtime.mjs <url> --reduced-motion --canvas               # что при «меньше движения»
node scripts/perf.mjs <url>                                            # телефон: кадры/с при прокрутке, память
```
Резкость: FAIL, если буфер меньше 0.85 от ширины в CSS px (размыт на любом
экране); WARN, если меньше 0.85 от ширины × DPR — для WebGL это бывает
нарочно (`setPixelRatio(min(dpr, 1.5))`). После `--click`, `--select` и
`--resize` холсты перепроверяются сами: сцена, которая перерисовывается по
действию, часто размывается именно тогда.
Открыть снимки глазами на desktop и mobile. Провести курсором (`--hover`
по контейнеру) и посмотреть снимок: реагирует ли. Только после этого
статус VERIFIED — с цифрой кадров/с в отчёте.

## Движение

Вопросы перед каждой анимацией: где (какой элемент), зачем (направляет
взгляд, показывает связь, отвечает на действие), какая (появление, сдвиг,
масштаб, цвет), сколько (длительность), как (кривая), по какому событию
(загрузка, прокрутка, наведение, клик), что при «меньше движения».

Сначала — язык движения донора или сайта: тип появления из
`design/site.json` → `motion.scrollReveal`, длительности и кривые оттуда же,
«что появляется при наведении» — из разведки. У streetwearbrands при
прокрутке появляется один блок, а подписи карточек — при наведении: 21
блок со сдвигом 22 px на своём сайте — это уже не его язык.

Значения по умолчанию — только если у донора и сайта своего языка
движения нет, и с записью об этом в `authorship.md`:

- наведение и клик — 150–250 мс, `ease-out`;
- появление при прокрутке — 500–700 мс, `cubic-bezier(.2,.7,.2,1)`, сдвиг 16–24 px, каскад 60–90 мс, срабатывает один раз при 15–20% видимости;
- бесконечные анимации — только одна на экран и только если она несёт смысл; пульсирующая кнопка — почти всегда лишняя;
- ничего не анимировать дольше 1 с, кроме сцен на холсте.

Технология по возрастанию:

| технология | когда |
|---|---|
| CSS transition | состояния |
| CSS keyframes + класс от `IntersectionObserver` | появления при прокрутке |
| Web Animations API | последовательности из JS без библиотеки |
| GSAP (+ ScrollTrigger) | привязка к прокрутке, сложные таймлайны, закрепление |
| Lottie | только готовые файлы от дизайнера |
| Framer Motion | только на React |

Всегда:

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { animation-duration: .01ms !important; transition-duration: .01ms !important; }
}
```
или адресно — но блоки появления обязаны быть видимыми без анимации.

**Проверка:** `runtime.mjs --scroll` (все спрятанные появились, нет
горизонтальной прокрутки), `--motion` (сколько идёт, бесконечные, что
остаётся при «меньше движения» — в отдельной вкладке; какие законченные
анимации держат свойство), `--hover-all` (каждое правило `:hover` меняет
объявленное; анимация с `fill: both` его перебивает — FAIL), снимки
в фазах (`--shot`), `perf.mjs` — кадры/с при прокрутке не ниже 55 на десктопе
и 40 на телефоне.

## Телефон и планшет

Не уменьшать десктоп, а проектировать заново четыре вещи: первый экран
(заголовок, одно действие, «позвонить»), меню (открывается, закрывается,
не прокручивает фон), формы (поля 16 px, цели 44 px, маска телефона),
таблицы и сетки (в карточки или горизонтальную прокрутку с подсказкой).
Планшет — отдельный взгляд: две колонки вместо трёх, меню ещё десктопное
или уже мобильное.

Проверка на `desktop`, `tablet`, `mobile` (и `laptop`, если сетка ломается
на 1280): `shots.mjs`, `runtime.mjs --viewport mobile --scroll --click "<меню>"`,
`a11y.mjs --viewport mobile` (цели, размер полей), `perf.mjs` (по умолчанию
телефон и медленная сеть).
