# Движки: картинки, 3D, движение, телефон — и правила реализации

## Правила реализации (Code Agent)

- Правки хирургические: менять то, что в плане, и не переписывать соседнее «заодно».
- Работать через дизайн-систему (`design/site.tokens.css` или переменные самого сайта). Значение, которого нет в системе, — добавить в систему.
- На сайте без сборщика не появляется сборщик; без фреймворка — фреймворк. Библиотека подключается с CDN и только если без неё нельзя.
- Не ломать договорённости платформы: серверные плейсхолдеры, шаблонные переменные, скрипты аналитики, формы с их `action` — не трогать без задачи.
- Каждый компонент — со всеми состояниями: наведение, фокус, нажатие, недоступен, загрузка, ошибка, пусто.
- Семантика: `header/nav/main/section/footer`, один `h1`, кнопки — `button`, ссылки — `a`, картинки с `alt`.
- Всё новое обязано работать без JS хотя бы как статичная версия: содержимое видно, ссылки ведут, форма отправляется.
- После правки — перезагрузить и проверить, что консоль пуста, прежде чем смотреть красоту.

## Картинки

```
Нужен кадр?
 ├─ нет → не добавлять ради заполнения места
 └─ да → есть подходящий на сайте? → переиспользовать (обрезать, пережать)
          └─ нет → можно доработать существующий? (обтравка, дорисовка полей, цветокоррекция)
                    └─ нет → сгенерировать (Higgsfield, с согласия и с кредитами)
                              └─ недоступно → SVG/CSS-графика · фото по свободной лицензии · оставить без кадра
```

Требования к кадру, любого происхождения:

- пропорция под место: hero 16:9 или 3:2 на десктопе и 4:5 на телефоне — два кадра или `object-position`;
- цвета из палитры сайта, единая обработка (температура, контраст, зерно) на всех кадрах;
- место под текст, если текст поверх: пустая зона, затемнение через переменную, не через «на глаз»;
- вес: WebP/AVIF, `srcset` под 1x/2x, `loading="lazy"` всему ниже первого экрана, `width/height` заданы (иначе CLS);
- **посмотреть глазами каждый**: стоковый кадр с чужой валютой, не тем блюдом, не той страной — хуже пустого места; кадры, противоречащие подписи, снимать;
- лицензия: сгенерированное — свободно, Openverse — только CC0/PDM/BY/BY-SA с атрибуцией, чужие сайты — никогда.

Промпт для генерации собирается из дизайн-системы: язык дизайна словами,
палитра в hex, композиция и пропорция, где пусто под текст, чего не должно
быть (текст на картинке, логотипы, лица, если нужен не портрет).

## 3D

**Сначала — нужно ли.** 3D оправдано, когда оно улучшает историю (объект
бренда, который иначе не показать), подачу продукта (вращающийся товар),
иерархию первого экрана (живой фон, который не спорит с текстом) или
взаимодействие (объект отвечает на курсор). Не оправдано: «чтобы было»,
на текстовых сайтах услуг, там, где аудитория со старых телефонов, где
скорость уже на грани.

Подход, от простого к сложному:

| подход | когда |
|---|---|
| CSS 3D-трансформации и перспектива | карточки, лёгкие параллаксы — без WebGL |
| Three.js + процедурная геометрия (сфера, тор, узлы, сетка точек, частицы) | абстракция бренда на первом экране; по умолчанию |
| Three.js + шейдер (шум, градиент, искажение) | «дорогой» фон, реагирующий на курсор и прокрутку |
| GLB/GLTF модель (своя или из Higgsfield `generate_3d`) | продукт; вес модели ≤ 1–2 МБ, Draco-сжатие |
| React Three Fiber | только если сайт уже на React |

Обязательные элементы реализации:

- инициализация по `IntersectionObserver`: вне экрана не создаём и не рисуем;
- `renderer.setPixelRatio(Math.min(devicePixelRatio, 2))`, размер по контейнеру, `ResizeObserver`;
- пауза рендера вне видимости и при скрытой вкладке;
- `prefers-reduced-motion: reduce` — статичный кадр или отключение;
- запас: если WebGL недоступен или упал — постер (картинка/градиент), текст не зависит от холста;
- на телефоне — меньше частиц/сегментов, или статичный кадр; решение по `perf.mjs --viewport mobile`;
- сцена не мешает читать: контраст текста поверх проверить `a11y.mjs`;
- Three.js с CDN фиксированной версии, документация — через Context7, не по памяти.

**Проверка 3D — только так, никак иначе:**

```
node scripts/runtime.mjs <url> --canvas --shot hero --motion          # холст рисует, кадр меняется, кадры/с
node scripts/runtime.mjs <url> --viewport mobile --canvas --shot hero
node scripts/runtime.mjs <url> --reduced-motion --canvas               # что при «меньше движения»
node scripts/perf.mjs <url>                                            # телефон: кадры/с при прокрутке, память
```
Открыть снимки глазами на desktop и mobile. Провести курсором (`--hover`
по контейнеру) и посмотреть снимок: реагирует ли. Только после этого
статус VERIFIED — с цифрой кадров/с в отчёте.

## Движение

Вопросы перед каждой анимацией: где (какой элемент), зачем (направляет
взгляд, показывает связь, отвечает на действие), какая (появление, сдвиг,
масштаб, цвет), сколько (длительность), как (кривая), по какому событию
(загрузка, прокрутка, наведение, клик), что при «меньше движения».

Значения по умолчанию, если у сайта нет своего языка движения:

- наведение и клик — 150–250 мс, `ease-out`;
- появление при прокрутке — 500–700 мс, `cubic-bezier(.2,.7,.2,1)`, сдвиг 16–24 px, каскад 60–90 мс, срабатывает один раз при 15–20% видимости;
- бесконечные анимации — только одна на экран и только если она несёт смысл; пульсирующая кнопка — почти всегда лишняя;
- ничего не анимировать дольше 1 с, кроме сцен на холсте.

Технология по возрастанию:

| технология | когда |
|---|---|
| CSS transition | состояния |
| CSS keyframes + класс от `IntersectionObserver` | появления при прокрутке |
| Web Animations API | последовательности из JS без библиотеки |
| GSAP (+ ScrollTrigger) | привязка к прокрутке, сложные таймлайны, закрепление |
| Lottie | только готовые файлы от дизайнера |
| Framer Motion | только на React |

Всегда:

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { animation-duration: .01ms !important; transition-duration: .01ms !important; }
}
```
или адресно — но блоки появления обязаны быть видимыми без анимации.

**Проверка:** `runtime.mjs --scroll` (все спрятанные появились, нет
горизонтальной прокрутки), `--motion` (сколько идёт, бесконечные, что
остаётся при «меньше движения»), `--hover` по каждому типу кнопки, снимки
в фазах (`--shot`), `perf.mjs` — кадры/с при прокрутке не ниже 55 на десктопе
и 40 на телефоне.

## Телефон и планшет

Не уменьшать десктоп, а проектировать заново четыре вещи: первый экран
(заголовок, одно действие, «позвонить»), меню (открывается, закрывается,
не прокручивает фон), формы (поля 16 px, цели 44 px, маска телефона),
таблицы и сетки (в карточки или горизонтальную прокрутку с подсказкой).
Планшет — отдельный взгляд: две колонки вместо трёх, меню ещё десктопное
или уже мобильное.

Проверка на `desktop`, `tablet`, `mobile` (и `laptop`, если сетка ломается
на 1280): `shots.mjs`, `runtime.mjs --viewport mobile --scroll --click "<меню>"`,
`a11y.mjs --viewport mobile` (цели, размер полей), `perf.mjs` (по умолчанию
телефон и медленная сеть).
