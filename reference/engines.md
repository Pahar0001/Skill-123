# Движки: картинки, 3D, движение, телефон — и правила реализации

## Правила реализации (Code Agent)

- Правки хирургические: менять то, что в плане, и не переписывать соседнее «заодно».
- Работать через дизайн-систему (`design/site.tokens.css` или переменные самого сайта). Значение, которого нет в системе, — добавить в систему.
- Инструменты — любые, если дают лучший результат (правило 5 в SKILL.md): Motion, GSAP, Lenis, Three.js и
  шейдеры, Lottie, видео; сборщик или фреймворк — если выигрыш того стоит и выкладка сайта не ломается (Docker,
  Caddy, автообновление — проверить до сдачи). Версия библиотеки — точная; без сборщика — модуль с CDN
  (jsDelivr, cdnjs). Чем делать движение — `reference/motion.md` → «Техника». Платное (Motion+, платные шрифты,
  генерации) — только с согласия владельца.
- Не ломать договорённости платформы: серверные плейсхолдеры, шаблонные переменные, скрипты аналитики, формы с их `action` — не трогать без задачи.
- Каждый компонент — со всеми состояниями: наведение, фокус, нажатие, недоступен, загрузка, ошибка, пусто.
- Семантика: `header/nav/main/section/footer`, один `h1`, кнопки — `button`, ссылки — `a`, картинки с `alt`.
- Всё новое обязано работать без JS хотя бы как статичная версия: содержимое видно, ссылки ведут, форма отправляется.
- После правки — перезагрузить и проверить, что консоль пуста, прежде чем смотреть красоту.

## Картинки и видео

```
Нужен кадр или ролик?
 ├─ нет → не добавлять ради заполнения места
 └─ да → есть подходящий на сайте? → переиспользовать (обрезать, пережать)
          └─ нет → законные бесплатные источники: media.mjs search → лист-контакт глазами → pick
                    └─ не нашлось годного → доработать найденное (кадр, цвет, зерно — под язык сайта)
                              └─ не вышло → генерация (с согласия и с деньгами пользователя):
                                        иконки, иллюстрации, паттерны в SVG — recraft.mjs; фото, видео, 3D — Higgsfield
                                        └─ недоступна → SVG/CSS/canvas-графика или без кадра
```
Графика вместо фото — осознанное решение с причиной в `analysis.md`, а не
выход по умолчанию. Для товара, который покупают глазами (картины, еда,
интерьер, одежда), заглушка-абстракция — P2. Pinterest, Behance, Dribbble —
только доска настроения: ни один файл оттуда на сайт не попадает.

### media.mjs — подбор из бесплатных источников

```
node ~/.claude/skills/site-rework/scripts/media.mjs doctor                                   # ключи (только имена), источники, sharp, ffmpeg
node ~/.claude/skills/site-rework/scripts/media.mjs search "bakery bread" --kind photo --role hero [--profile art] [--orient landscape] [--n 24]
node ~/.claude/skills/site-rework/scripts/media.mjs search "steaming mug" --kind video [--sources commons,mixkit] [--frames 8|all]
node ~/.claude/skills/site-rework/scripts/media.mjs pick <папка поиска> 3 --seen "хлеб на деревянных полках пекарни" --caption "Свежий хлеб утром" \
     --role hero --dest <сайт>/img [--look duotone:#111111,#E9E6E0|mono] [--contrast 0.3] [--grain 0.04] [--crop-mobile 4:5]
node ~/.claude/skills/site-rework/scripts/media.mjs import <страница кадра> [<файл>] --license <из белого списка> --seen … --caption …
node ~/.claude/skills/site-rework/scripts/media.mjs credits <сайт>/img --md <сайт>/CREDITS.md
```

Порядок источников (профиль `photo`): Unsplash и Pexels (по ключу) →
Wikimedia Commons (CC0, «Quality images») → Pixabay (ключ, 1280 — для
карточек) → WordPress Photos → Openverse (только карточки: реальный потолок
500–1024 px). Профиль `art` по порядку: The Met, Cleveland, Rijksmuseum,
Art Institute of Chicago, SMK, Smithsonian (по ключу), Commons — общественное достояние с настоящим автором и
названием, как иллюстрация, не как товар и не под вымышленными именами;
срок охраны — по году смерти (жизнь + 70). Видео: Pexels и Pixabay (по
ключу) → Commons (в основном CC BY — подпись обязательна; перезаливы с
YouTube помечены `youtube?` и стоят в конце) → Mixkit (поштучно, одна
страница выдачи на запрос, лицензия `videoFree` проверяется в pick,
Restricted — отказ). Coverr, Videezy, Vecteezy, Freepik — не встраиваются.

Ключи — бесплатная регистрация, в `~/.claude/site-rework/.env` (образец —
`~/.claude/site-rework/.env.example`, если он есть на машине: в git скилла его
нет): `PEXELS_API_KEY`, `UNSPLASH_ACCESS_KEY` (и
`UNSPLASH_APP_NAME` — имя приложения из кабинета Unsplash, идёт в utm ссылок
подписи), `PIXABAY_API_KEY`, `SI_API_KEY` (Smithsonian в профиле
`art`), `MEDIA_CONTACT` (контакт для User-Agent по правилам Wikimedia и AIC;
личные данные сами не подставляются). Без ключей работают Mixkit, Openverse
и музеи, кроме Smithsonian; Commons и AIC — только с `MEDIA_CONTACT`. У Unsplash кадр не пережимается у себя:
pick выдаёт разметку со ссылками `images.unsplash.com` по его правилам API,
сообщает Unsplash о скачивании (`download_location`) и помечает подпись
**обязательной**: лицензия Unsplash подписи не требует, а правила API требуют —
имя автора и «Unsplash», обе ссылки с utm, рядом с кадром (лучше) или в общем
блоке подписей (готовая строка — `media.mjs credits`). Файл, скачанный человеком на
unsplash.com и заведённый через `import --license unsplash`, подписи не требует.

Без ключей крупный кадр первого экрана — в основном Commons, видео — Commons
(шумная выдача, чаще CC BY) и Mixkit поштучно; Openverse — только карточки.
Без ключей и без `MEDIA_CONTACT` остаются Mixkit поштучно, Openverse и музеи
без контакта — для первого экрана этого почти всегда мало.
`media.mjs doctor` перечисляет незаданные ключи отдельным блоком «WARN: не
заданы ключи (N из 5) … — чем грозит»: по строке на ключ и подсказки, откуда
тогда брать кадры. Итог OK — только когда ответили все пробы и заданы все
пять ключей, иначе WARN; код 1 — только без `sharp`. Если первому экрану или
видео-петле этого мало, а в блоке есть `PEXELS_API_KEY`, — один раз попросить
у пользователя бесплатный ключ (pexels.com/api → Your API Key) и положить в `.env`.

`MEDIA_CONTACT` не задан — Commons (фото, видео, копии `thumb.wikimedia`) и
AIC пропускаются без единого запроса: их правила требуют контакт в
User-Agent. `doctor` и `search` пишут `SKIP <источник> … нет MEDIA_CONTACT`,
вердикт search остаётся OK, в `manifest.json` у источника
`status: {state: 'skip', no_contact: true}`. `pick` кадра Commons/AIC и
`import` адреса с Wikimedia/AIC без контакта — FAIL до сети (import советует
скачать файл в браузере и передать путь). Если без Commons кадров мало —
спросить у пользователя адрес сайта или рабочую почту для таких писем и
записать `MEDIA_CONTACT=…` в `.env`; самому почту из git или профиля не брать.

`--run <адрес>` у search и import — папка прогона по тому же правилу, что у
остальных скриптов (`lib.slugFromUrl`, с портом и путём:
`http://localhost:4177/` → `runs/localhost-4177`); без `--run` — `runs/media/…`.

**Отбор — глазами по листу-контакту** (`<папка>/sheet-1.jpg`): номер,
источник, реальный размер файла, лицензия, флаги `people?`, `brand?`,
`text-or-currency?`, `art?`, `ai?`, `small`. Флаги — подсказка: чужие ценники,
вывески, валюту и лица они пропускают, решает взгляд. Люди в кадре: согласий
моделей у стоков нет (и ст. 152.1 ГК РФ) — для фонов брать кадры без
узнаваемых лиц; руки без лица допустимы.

**Марки, имена файлов, листы.** Напитки и еду искать без названия марки («orange spritz cocktail», а не
«aperol spritz»): на бокалах и этикетках окажется чужой логотип, а `brand?` ловит не всё. Кадры, которые лягут
в репозиторий под фиксированными именами (база ссылается на путь), брать с Pexels, а не с Unsplash: по
правилам его API кадр отдаётся только ссылкой `images.unsplash.com`. Листы-контакты смотреть по одному и сразу
записывать выбор (имя | папка | номер | что на кадре) в файл плана: несколько листов подряд выпадают из контекста.

**Стоковый кадр — не товар.** Pexels, Unsplash и Pixabay запрещают
продавать кадры без переработки как принты и постеры, а на витрине с ценой
кадр читается именно товаром. Картиной, принтом или постером на продажу
бывают только работы заказчика; музейная работа — иллюстрация с настоящим
автором и названием, без цены; стоковый кадр — только обстановка (стена,
интерьер). Флаг `art?` значит, что на кадре чужое произведение: лицензия
фотографа на него не распространяется.

**Ворота pick**: без `--seen` (что на кадре, своими словами, не меньше трёх
слов) и `--caption` (подпись или роль на сайте) — отказ, код 2; кадр с
флагами — только с `--ok-flags`. Описывать то, что на кадре **после**
обработки (после duotone синий диван — серый).

**Что делает pick с фото**: скачивает лучший размер под роль и никогда не
растягивает («исходник даёт только N px»), проверяет подпись файла, убирает
EXIF и GPS, лестница по длинной стороне (hero 3840/2560/1920/1280, section
2560/1920/1280, card 1280/640), WebP и AVIF плюс JPEG запасной, кадр для
телефона по `--crop-mobile`, одна обработка `--look`/`--contrast`/`--grain`
(зерно в файл не больше 0.06) на все кадры сайта. Пишет запись в
`credits.json` папки назначения и печатает готовую `<picture>` с
`srcset`/`sizes`, `width`/`height`, `loading`, `alt` из `--caption`.

**Что делает pick с видео**: не качает 4K целиком — вырезает отрезок
(`--start`, `--dur`), убирает звук, делает петлю без шва (наплыв `--fade`),
1920×1080 H.264 + WebM VP9, телефон 1280×720 и вертикальный (у 1080p-исходника
вертикальный 606×1080 — не растягивается), постер из кадра стыка. Бюджет:
первый экран ≤2.5 МБ на desktop и ≤1 МБ на телефоне — иначе поднимается CRF;
4K на сайт не отдаётся; без ffmpeg ролик не берётся. Тон видео — CSS на
`<video>`, он же тонирует постер. Печатает `<video autoplay muted loop
playsinline preload="metadata" poster>` с webm и mp4 и заметку про
«меньше движения». Кэш отрезков — `~/.claude/site-rework/cache/video`.

**Обязательный шаг глазами для видео** — лист кадров
`<папка поиска>/check/<имя>-frames.jpg`. Кадр «середина наплыва» показывает,
не «двоит» ли петля (камера движется — на наплыве две полупрозрачные
чашки). Двоит — `--fade 0.4`, другой отрезок или ролик со статичной камерой.
Числом это не ловится.

**Сеть**: DNS через VPN иногда не отдаёт имена — media.mjs повторяет и
пробует DoH; ошибка печатается как «временно, повторить позже». Commons
отдаёт оригиналы с 429 волнами — pick берёт копию и честно пишет об этом;
можно повторить позже. Проверка: `runtime.mjs --video` — poster, пауза вне
экрана и при «меньше движения», вес.

Требования к кадру, любого происхождения:

- пропорция под место — из медиа-слотов разведки: hero 16:9 или 3:2 на десктопе и 4:5 на телефоне — два кадра или `object-position`;
- цвета из палитры сайта, единая обработка (температура, контраст, зерно) на всех кадрах;
- место под текст, если текст поверх: пустая зона, затемнение через переменную, не через «на глаз»;
- вес: WebP/AVIF, `srcset` под 1x/2x, `loading="lazy"` всему ниже первого экрана, `width/height` заданы (иначе CLS);
- **посмотреть глазами каждый**: стоковый кадр с чужой валютой, не тем блюдом, не той страной — хуже пустого места; кадры, противоречащие подписи, снимать;
- лицензия и подпись: `credits.json` → `media.mjs credits` → `CREDITS.md` и строка в подвале, если нужна (CC BY/BY-SA и Unsplash из API — обязательно); чужие сайты — никогда;
- **подпись автора у кадра — сбоку и незаметно** (пожелание пользователя 24.09: «подписи под фото это круто, но надо где-то сбоку и не так, чтобы выделялось, шрифт и попрозрачней»): вдоль правого края кадра снизу вверх (`writing-mode: vertical-rl` + `rotate(180deg)`), 12 px, цвет светлее приглушённого, но не ниже 4.5:1 к фону — бледнее мелкий текст не читается и a11y даёт FAIL; ссылки — 24 px поперёк строки (`padding: 0 6px`). У большого кадра — полоса 24 px справа под подпись, на телефоне тоже. Не строкой по центру под фото; описание к кадру (что на нём) — отдельно, под фото, если нужно. Образец — VN3D (`runs/figurki/site/css/pages.css`, `.photo-credit`).

Промпт для генерации собирается из дизайн-системы: язык дизайна словами,
палитра в hex, композиция и пропорция, где пусто под текст, чего не должно
быть (текст на картинке, логотипы, лица, если нужен не портрет).

### recraft.mjs — иконки, иллюстрации, паттерны в SVG (Recraft API)

```
node ~/.claude/skills/site-rework/scripts/recraft.mjs doctor                          # ключ (есть/нет), баланс, модели и цены
node ~/.claude/skills/site-rework/scripts/recraft.mjs gen "flat line icon of a 3D printer nozzle, 2px stroke" --for icon \
     --colors "#6A4EE1,#232530" --bg "#FFFFFF" --n 3 --run <папка>                 # без --yes — только сумма (код 2)
node ~/.claude/skills/site-rework/scripts/recraft.mjs gen … --yes                     # после согласия: черновики в <папка>/media/recraft/…
node ~/.claude/skills/site-rework/scripts/recraft.mjs take <черновик.svg> --dest <сайт>/img --seen "<что на картинке>" --caption "<роль>"
node ~/.claude/skills/site-rework/scripts/recraft.mjs vectorize|remove-bg|upscale <файл> --yes   # take — с --license-from <исходник> или --own
node ~/.claude/skills/site-rework/scripts/recraft.mjs selftest                        # поддельный сервер, 14 проверок
```

Когда: нужна графика, которой нет на стоках, — набор иконок одной линией, иллюстрация к шагу,
паттерн или фон в языке донора, векторизация своего знака. Не для «наших работ», людей, блюд и
места: сгенерированное выдаёт себя за реальность — на сайте клиента `--for photo/mockup` с таким
промптом скрипт отвергает (демо-сайт студии — `--demo`). Модель по назначению (`--for`):
icon, illustration, pattern, decor — `recraftv4_1_vector` ($0.08, настоящий SVG), background,
texture, photo — `recraftv4_1` ($0.035), mockup — `recraftv4_1_utility`; черновик дешевле —
`--model recraftv4_1_flash` ($0.007, растр). Палитра — `--colors`/`--bg` из токенов сайта, текста
на картинке нет (`--text` — осознанно, кириллицу смотреть глазами), промпт по-английски.

Ключ `RECRAFT_API_TOKEN` — в `~/.claude/site-rework/.env` (recraft.ai → профиль → API → Generate,
нужен положительный баланс API; 1 $ = 1000 единиц). Права (Developer Terms, 11.08.2026): картинки
из API — владельца ключа, коммерческое использование можно, подпись не нужна; учить на них нейросети
нельзя; метаданные, водяные знаки и метки Recraft **не удалять и не менять** — файл берётся как есть,
SVG со скриптом не вырезается, а отвергается (перегенерировать), растр пережимать с сохранением
метаданных (sharp `.keepMetadata()`). Фон, векторизация, увеличение чужого кадра — права исходника
(`take --license-from`). Recraft V4.1 есть и внутри Higgsfield (`generate_image`), но отдаёт ли он
там SVG файлом — не проверено; для SVG — этот скрипт.

## Фактура: зерно, шум, плёнки

Фактуру переносят числом, а не на глаз: на уменьшенном снимке зерна не
видно, а multiply-зерно на чёрном даёт ровно ноль.

1. **Замер донора** (или своего сайта «до»):
   ```
   node ~/.claude/skills/site-rework/scripts/texture.mjs <донор> --viewport desktop,tablet,mobile --out <папка>/texture
   ```
   Слои (фон, `img`, `picture`, `svg` с feTurbulence, `canvas`, `video`,
   псевдоэлементы; шум в фоне body/секции), файл текстуры по всем кадрам
   (мс на кадр, σ, альфа), σ по полосам фона — вклад слоя «со слоем − без»,
   кипит ли (два снимка через 250 мс; частота — из файла или `@keyframes`),
   на каких экранах есть (`@media` у слоя). Итог — рецепт и блок `--grain-*`.
2. **Своя плитка** — чужой файл не переносится никогда:
   ```
   node ~/.claude/skills/site-rework/scripts/grain-tile.mjs --out <папка сайта> [--px N]   # N = --grain-px из рецепта
   ```
   Для `templates/grain.css` нужен один кадр: кипение делается сдвигом, а
   имя плитки в нём — `grain-gray-256[-pxN].png`, поэтому `--px` должен
   совпасть с `--grain-px` рецепта. `--frames 4 --frame-ms 100` пишет
   анимированную плитку (спрайт, GIF, WebP) — шаблон её не использует.
   Детерминированно (тот же `--seed` — побайтно тот же файл), серая
   непрозрачная плитка 256 px, 16 уровней, σ 78.35; `--check файл` проверяет
   готовую плитку по всем кадрам. `--mode alpha` — светлые и тёмные зёрна с
   прозрачностью (только PNG и WebP, GIF её не держит; 16 уровней альфы, σ и
   среднее в самопроверке — как плитка видна на сером 128); шаблон
   `templates/grain.css` рассчитан на серую плитку.
3. **Слой по шаблону** `templates/grain.css`:
   ```
   node ~/.claude/skills/site-rework/scripts/texture.mjs <папка>/texture/texture.json --css <сайт>/grain.css --tokens <сайт>/site.tokens.css
   ```
   Рецепт подставляется без нового замера: прозрачность, режим,
   `image-rendering` как у донора, `@media (min-width)` — где у донора
   зерна нет, число сдвигов «кипения» = число кадров донора. Разметка —
   последним элементом body: `<div class="grain-overlay" aria-hidden="true"></div>`.
   Отдельный элемент, а не `body::after`: чужой `body::after` не затирается.
   Переменные — только группа `--grain-*`: это рецепт под свою плитку, его
   и читает шаблон. После разведки этот блок уже стоит в конце
   `design/site.tokens.css` (discover с `--no-design` его не пишет — некуда);
   `--tokens` пишет его в указанный файл и
   заменяет прежний блок между `/* texture:start */` и `/* texture:end */`,
   а не дублирует. `--texture-opacity` и `--texture-blend` от `extract.mjs` —
   сырой CSS слоя донора, справочно: с рецептом они расходятся (на «ХОЛСТе»
   `--texture-opacity: 0.07` multiply, а `--grain-opacity: 0` — на снимках
   это зерно не видно).
4. **Сверка**: `texture.mjs compare <донор или его texture.json> <сайт>` → OK
   по всем экранам. Проверено: копия «ХОЛСТа» с шаблоном против
   streetwearbrands — σ 5.04/4.81 против 5.04/5.05, кипение 4×100 мс у обоих.

Правила режимов наложения:

- `normal`, `hard-light`, `luminosity` — одинаковая сила на любом фоне;
  `normal` поднимает чёрный на ≈ opacity × 127 — у плёнки так и есть;
- `multiply`, `overlay`, `soft-light` гаснут на тёмных фонах (Y до ~50):
  на чёрном зерна нет совсем; `overlay` и `soft-light` гаснут и на светлых;
  `screen` — на светлых;
- непрозрачная серая плитка + `opacity = нужная σ / σ плитки` (5 / 78.35 ≈ .064);
- feTurbulence не запрещён, но рисуется на каждый кадр — цену мерить
  `perf.mjs`; альфа шума без `feFuncA` ≈ 0.3, сила зависит от неё;
- на DPR 2 сглаживание делает зерно мягче — повторять `image-rendering`
  донора, сравнивать донора и сайт только при одинаковом DPR;
- «кипение» — сдвиг `::before` трансформацией по `steps(1)`: это работа
  композитора, страница не перерисовывается; при «меньше движения» — стоп.

Контраст текста под зерном — `a11y.mjs` (поправка на слой), цена слоя —
`perf.mjs --overlay`.

## Крупная фактура: мятая и зернистая бумага, камень, ткань

Это не зерно. Зерно — мелкий шум слоем поверх всего. Крупная фактура —
картинка-плитка в фоне: прожилки, заломы, волокна, нити, доски; детали
крупнее пикселя. «Фон не просто белый, а с прожилками и мятостями» — это она
(образец: zakroma.rest, плитка 1416×1688, яркость 248 ± 2.5).

**Когда брать.** У донора она есть — повторяем числом. Своим решением — когда
языку сайта нужна вещественность: ремесло, еда, растения, бумага, ткань, и
всегда, когда в анкете фон — «фактура» (ровная заливка владельцем названа
пустой: «не хватает заднего фона… не просто белый, а детали, текстура»).
Не брать на плотных интерфейсах и там, где фон — фотографии.

**Заметность.** Фактуру должно быть видно без подсказки: грани, заломы,
прожилки. На «Зелёном уголке» первая плитка с σ 1.5 была «слишком тихой»
(«я говорил… именно текстуру, какие-то прожилки, мятости»), принята с σ 3.2;
у образца zakroma.rest — 2.5. Цель плитки — не ниже образца, без образца —
`--sd 2.5…3.2`; прожилки не выключать (`--veins 0` — только по просьбе).
До вёрстки показать владельцу вырез 1:1 на цвете поля рядом с вырезом образца.

1. **Снять** — тем же замером, что и зерно:
   ```
   node ~/.claude/skills/site-rework/scripts/texture.mjs <донор> --viewport desktop,mobile --out <папка>/texture
   ```
   В выводе — «крупная фактура: есть / нет / не измерено», плитка (размер,
   яркость ± σ, шов, **вид**), по каждой секции: в фоне блока или слоем поверх,
   тон под ней, наложение, размер показа, сила; где выключена (`@media`). Ищется
   не по имени файла (слова texture, paper в пути — только подсказка: фотография
   с таким именем слоем не считается): кандидат — картинка в фоне любого
   большого блока, решает разбор файла — σ яркости 0.8…12, детали крупнее
   пикселя (в том числе у JPEG с шумом сжатия: мятая бумага, доски), детали по
   всей площади; ткань узнаётся по повтору нитей, полупрозрачная плитка
   разбирается как на белом поле. Не проходят — и причина пишется:
   фотография и градиент (общий уклон яркости больше 0.7 σ; у плитки до
   512 px — больше 0.8), шум и мягкое зерно (шум, размытый на пару пикселей:
   соседи связаны, а рисунка — пятен, линий — нет), рисунок на ровном поле
   (линии, значки, орнамент: поле между знаками ровное и одного тона, крупных
   пятен нет), сетка в два тона, полупрозрачная картинка с крупными пятнами
   (фотография в png с ровной альфой). Сила — вклад «с плиткой − без» на
   ровных участках 128 px (мало — 64 px), лежащих под фактурой целиком;
   «есть» — σ от 0.6.
   Ложная находка хуже пропуска: по рецепту на сайт положат слой, которого у
   образца нет. Поэтому сомнительное отсекается; что при этом не различается —
   в справке `texture.mjs -h` («Не различает и не видит»).
   **Вид плитки** скрипт называет сам, с уверенностью (число и слово) и
   основанием: `canvas` — «повтор с шагом 3 px по обеим осям»; `stone` —
   «тонкие тёмные линии на гладком поле»; `pulp` — «зерно и волокна»
   (зернистая бумага, крафт, картон); `paper` — «заломы и грани» (мятая
   бумага). «Не определён» — в рецепте два кандидата и «выбрать глазами по
   вырезке 1:1» — там, где признак держится на шуме: уверенность низкая;
   мягкие пятна без линий; зерно без волокон поверх крупного рельефа (мятая
   бумага в JPEG, пергамент с разводами); дерево (своего вида плитки для досок
   нет); яркость упирается в край шкалы (почти белая плитка 254 ± 2: обрезка
   по 255 сама даёт асимметрию); разброс мал (σ меньше 1.8: тонкие прожилки
   тонут в квантовании — «бумага» не доказана); тёмные выбросы занимают мало
   площади (редкие пятнышки винтажной бумаги, волокна после сильного сжатия —
   не прожилки); асимметрия у самой границы; зерно со слабыми штрихами поверх
   сильного рельефа (мятая бумага в JPEG с шумом: такой эксцесс дают и заломы).
   Средняя уверенность — тоже сверить глазами. Пороги проверены 02.10.2026 на
   36 живых сайтах (13 с крупной фактурой, 5 с зерном, 5 с ровным фоном, 13
   обманок), на 454 файлах-обманках и 432 своих плитках независимого
   проверяющего; таблица «было → стало» — ниже, «Пороги: было → стало».
   **Зерно без слоя не выдаётся.** Слоёв зерна на странице нет — вердикт
   «зерна нет»: σ на «ровных» участках дают сами картинки (шум матрицы в
   тёмных фотографиях, сжатие), рецепта слоя шума не будет. Исключение —
   бледная шум-плитка в фоне блока (в выводе — строка о ней).
2. **Своя плитка** — чужой файл не переносится никогда:
   ```
   node ~/.claude/skills/site-rework/scripts/surface-tile.mjs --out <папка сайта> --like <папка>/texture/texture.json --sheet
   ```
   `--like` берёт из замера **вид**, яркость и σ, **размер** (период показа:
   файл выходит `surface-<вид>-<период>.webp` — тем же именем его называют
   рецепт и `--css`), у ткани — **шаг переплетения**, у зернистой бумаги —
   **направление волокон**; `--kind`, `--mean`, `--sd`, `--size`,
   `--thread`, `--dir` главнее (без замера — paper, 248 ± 2.5, 1024 px).
   Виды: `paper` (мятая бумага: грани, заломы, трещины), `pulp` (зернистая
   бумага без заломов: мелкая бугристость, вкрапления, короткие ворсинки —
   крафт, картон, упаковочная бумага; у живых сайтов встречается чаще мятой;
   `--veins N` — число ворсинок, 0 — без них; `--dir 0` — волокна вдоль
   ширины: рисунок тогда другой — тонкие короткие штрихи и «линовка» на
   ровном поле вместо бугристости, как у бумаги с уложенными волокнами),
   `stone` (мягкие пятна и ветвящиеся
   прожилки), `canvas` (переплетение нитей; `--thread N` — шаг переплетения
   в px, по умолчанию 32 — крупная корзинка, у живых сайтов бывает 3 и 6 px).
   Вид в замере «не определён» —
   сделать оба кандидата, которые назвал замер, положить вырезки 1:1 рядом с
   вырезкой донора и выбрать глазами. Своя плитка — не копия: совпадут тон,
   сила и род материала, рисунок будет свой (у донора прожилки чаще и тоньше;
   для досок своего вида нет вовсе) — владельцу показать пару вырезок.
   Бесшовная, детерминированная (`--seed`), WebP 1024 px при 248 ± 2.5 весит
   8–26 КБ, зернистая бумага `pulp` — 40 КБ (при σ 4.6 — 71 КБ, при σ 6.3 —
   95–100: зерно по всей площади сжимается хуже; период больше 1024 px ей
   рецепт не назначает — она однородна). Ткань с шагом мельче 16 px пишется с
   качеством 92 (при 86 сжатие ломает мелкий рисунок), рецепт даёт ей плитку
   не больше 512 px.
   `--sheet` пишет лист 2×2 и крест стыков 1:1 — **открыть глазами**.
   `--check файл` — шов числом (у ткани — и сбой фазы нитей на краю), яркость
   ± σ, узнаёт ли плитку `texture.mjs`, её вид; с `--like` — тот ли это вид,
   что у донора (другой — WARN-подсказка, не провал).
3. **Положить** — `templates/surface.css`:
   ```
   node ~/.claude/skills/site-rework/scripts/texture.mjs <папка>/texture/texture.json --css <сайт>/surface.css --tokens <сайт>/site.tokens.css
   ```
   Картинка в фоне блока, а не слой поверх: текст и кнопки остаются чистыми.
   Класс `surface` — светлому или цветному полю, `surface--dark` — тёмному.
   У поля должен быть свой `background-color`: плитка умножается только на него.
   Карточки с текстом можно оставлять гладкими — фактура у фона, чистота у
   содержимого. В печати выключена.
4. **Сверка**: `texture.mjs compare <донор> <сайт>` — строки «крупная фактура»
   (есть / нет), «вид плитки» (другой вид — подсказка, не FAIL), «фактура σ»
   по полосам фона (±30 %, `--surface-tol`), «наложение». Мимо допуска только
   тёмные поля, а светлые в норме — общую плитку не ослаблять: сделать
   отдельную для тёмных полей и назначить её `--surface-tile-dark`
   (`templates/surface.css`), число `--sd` назовёт подсказка. Тёмным полем
   подсказка считает то, где у сайта плитка лежит через `color-burn`, или поле
   с яркостью ниже 130 — а не только полосу замера «тёмный» (до 60): у
   zakroma.rest тёмно-зелёные секции имеют яркость 62. Мимо светлые поля при
   тёмных в норме — наоборот: новая общая плитка, а нынешнюю оставить тёмным
   полям той же переменной. Тёмные поля донора и сайта попали в разные
   полосы замера (яркость 62 и 47) — обе строки «—», вердикт прежний, но
   подсказка говорит «тёмные поля не сверены» и даёт ориентир в процентах:
   взять у себя поле той же яркости, что у донора. Замер донора
   старой версии (до 01.10.2026) — WARN с командой «перемерить», а не FAIL;
   замер без вида плитки (версия 01.10.2026) — строка «вид плитки: не
   снимался» и подсказка перемерить. Проверено 01.10.2026: zakroma.rest против сайта со своей
   плиткой — светлый σ 1.74 против 1.79, OK; 02.10.2026 — на стендах
   проверяющего все три подсказки (отдельная плитка тёмным полям, «не
   сверены», «вид не снимался»).

**Пороги: было → стало** (02.10.2026; master e2beb7b → первая правка →

Правила наложения:

- светлые и цветные поля — `multiply`: плитка умножается на цвет поля, цвет
  сохраняется. Обычный слой донора с непрозрачной светлой плиткой на белом
  выглядит так же;
- тёмные поля — `color-burn`: умножение там гаснет (разброс падает в Y/255
  раз), а color-burn затемняет основу, и прожилки видны;
- граница — яркость поля 130: светлее сильнее умножение, темнее — color-burn.
  На белом color-burn гаснет совсем;
- прозрачность слоя донора переводится в силу плитки (`--sd`), а не в
  `opacity`: в фоне блока картинку не сделать прозрачнее самого блока;
- вместе с зерном живёт: зерно — слой поверх, фактура — в фоне. Замер их
  разделяет: зерно меряется на снимке без плитки.

## 3D

**Фото, видео или 3D — по смыслу сайта, для каждого блока отдельно.** Пользователь (24.09): «надо понимать по
контексту: если 3D-модель нужна как украшение заднего фона или как продукт — что-то уникальное для сайта; для ресторана
больше подойдёт видео прожарки стейка, для кофейни — красивое фото; так что индивидуально». 3D — когда это сам товар
(его крутят), уникальная деталь сайта или фон-украшение, которого иначе не сделать; процесс, где важны движение и
живость (прожарка, розлив, работа мастера), — видео; атмосфера и вкус (кофейня, интерьер) — фото. Рендер там, где его
не крутят и где есть живой кадр, — нет: на VN3D пользователь заменил рендер принтера в блоке автора фото («нет смысла
было делать 3D, лучше фото»). Выбор и причину — в план (`analysis.md`), не «по умолчанию».

**Сначала — нужно ли.** По умолчанию 3D нет. Если нужно — предмет
заказчика или объект из языка донора; частицы и сетки точек «для
атмосферы» — в каталоге дефолтов (`reference/authorship.md`). 3D оправдано, когда оно улучшает историю (объект
бренда, который иначе не показать), подачу продукта (вращающийся товар),
иерархию первого экрана (живой фон, который не спорит с текстом) или
взаимодействие (объект отвечает на курсор). Не оправдано: «чтобы было»,
на текстовых сайтах услуг, там, где аудитория со старых телефонов, где
скорость уже на грани.

Подход, от простого к сложному:

| подход | когда |
|---|---|
| CSS 3D-трансформации и перспектива | карточки, лёгкие параллаксы — без WebGL |
| рисунок с объёмом в SVG — `svg3d.mjs` (Zdog, Three.js SVGRenderer, CadQuery) | иконки шагов, предмет-украшение, фон-россыпь, чертёж: объём нужен, а WebGL — слишком много; 1–15 КБ, виден без JS, красится цветами сайта — `reference/svg-3d.md` |
| Blender — `blender.mjs` (`reference/blender.md`) | фотореализм: стекло, металл, ткань с отражениями (Cycles); физика — предметы падают и ложатся на плоскости, ткань драпируется; результат — прозрачные WebP, видео или GLB с запечённой анимацией для живого 3D; нужен Blender на машине, где идёт прогон |
| пререндер в прозрачный WebP — `templates/render3d/` (Three.js в безголовом Chrome, накопление кадров) | предмет-украшение, который не крутят: лента первого экрана, предметы на полях и в плитках, значки шагов на видных местах; на странице — обычная картинка, WebGL нет |
| Three.js + процедурная геометрия (сфера, тор, узлы) | объект из языка донора или товара; не «абстракция по умолчанию» |
| Three.js + шейдер (шум, градиент, искажение) | «дорогой» фон, реагирующий на курсор и прокрутку |
| GLB/GLTF модель (своя или из Higgsfield `generate_3d`) | продукт; вес модели ≤ 1–2 МБ, Draco-сжатие |
| React Three Fiber | только если сайт уже на React |

Обязательные элементы реализации:

- инициализация по `IntersectionObserver`: вне экрана не создаём и не рисуем;
- `renderer.setPixelRatio(Math.min(devicePixelRatio, 2))`, размер по контейнеру, `ResizeObserver`;
- пауза рендера вне видимости и при скрытой вкладке;
- `prefers-reduced-motion: reduce` — статичный кадр или отключение;
- запас: если WebGL недоступен или упал — постер (картинка/градиент), текст не зависит от холста;
- на телефоне — меньше частиц/сегментов, или статичный кадр; решение по `perf.mjs --viewport mobile`;
- сцена не мешает читать: контраст текста поверх проверить `a11y.mjs`;
- Three.js с CDN фиксированной версии, документация — через Context7, не по памяти.

### Пререндер: планка качества первого же кадра

Предмет, который на странице не крутят, дешевле и надёжнее снять один раз и поставить картинкой:
`templates/render3d/` (сцена, свет, материалы, съёмка; порядок и своя сцена — README там же). Набор вынесен из
«Зелёного уголка» (01.10.2026), где владелец дважды вернул рендер: «на процентов 40 лучше», потом «ещё на 25».
Первый кадр тогда был один проход, комната вместо студии, одна «глина» и без теней. Минимум, с которого теперь
начинают, а не к которому приходят на третьем круге:

| что | как | признак, что не сделано |
|---|---|---|
| накопление кадров | `--n 96` (ленты — 64): дрожание камеры в пределах пикселя, ключевой свет по диску, «купол» с тенью из верхней полусферы | ступеньки по краю, жёсткая или отсутствующая тень |
| студия из софтбоксов | тёмный купол и яркие узкие плоскости через PMREM, а не `RoomEnvironment` | блик выбеливает цвет, лак отражает серое |
| глянец рядом с матовым | листья, лента, металл — под лаком; бумага и картон — матовые с волокном (карта рельефа) | всё из одной «глины» |
| детали предмета | шов и гофра пакета, печать на этикетке и число на экране (холст → текстура), прожилки листа геометрией, металл зажима | предмет не узнаётся без подписи |
| тень на земле | под **стоящим** предметом — невидимая плоскость с `ShadowMaterial`; кадр опускается на долю, которую печатает `tools/crop-ground.mjs` | предмет висит над линией |
| блик вдоль ленты | `anisotropy` у материала и `uv` у геометрии | блик пятном, лента «пластиковая» |
| цвет | из дизайн-системы сайта (`--palette имя=цвет`); яркий тёплый цвет со свечением тональная кривая уводит в персиковый | мёд и оранжевое «выцвели» |

До вёрстки — лист «наш предмет рядом с предметом донора» на цвете поля сайта (`--bg`) и показ владельцу
(правило 7 SKILL.md). Плоские значки «3D SVG» рядом с пререндером выглядят слабее: на видных местах — только
объёмные, вектор — там, где значок мелкий. На сайте: `width`/`height`, `loading="lazy"`, кадру первого экрана —
`srcset` с малой копией (`tools/variants.mjs`: лента 2880 px на телефоне стоила секунду к LCP), размер предмета
в плитке — по высоте, чтобы не дотягивался до текста. Проверка — `runtime.mjs --scroll` (не перекрывает текст),
`perf.mjs` (вес картинок, элемент LCP), снимки 1440, 390 и 320 глазами.

**Проверка живого 3D (холста) — только так, никак иначе:**

```
node ~/.claude/skills/site-rework/scripts/runtime.mjs <url> --canvas --shot hero --motion          # рисует, кадр меняется, резкость буфера, кадры/с
node ~/.claude/skills/site-rework/scripts/runtime.mjs <url> --viewport mobile --canvas --resize rotate --shot hero
node ~/.claude/skills/site-rework/scripts/runtime.mjs <url> --reduced-motion --canvas               # что при «меньше движения»
node ~/.claude/skills/site-rework/scripts/perf.mjs <url>                                            # телефон: кадры/с при прокрутке, память
```
Резкость: FAIL, если буфер меньше 0.85 от ширины в CSS px (размыт на любом
экране); WARN, если меньше 0.85 от ширины × DPR — для WebGL это бывает
нарочно (`setPixelRatio(min(dpr, 1.5))`). После `--click`, `--select` и
`--resize` холсты перепроверяются сами: сцена, которая перерисовывается по
действию, часто размывается именно тогда.
Открыть снимки глазами на desktop и mobile. Провести курсором (`--hover`
по контейнеру) и посмотреть снимок: реагирует ли. Только после этого
статус VERIFIED — с цифрой кадров/с в отчёте.

## Рисунки в фоне

Фон «дорогого» сайта редко пустой: кроме фактуры в нём стоят рисунки в тему дела — наброски блюд и зелени от
руки, орнамент у края, гигантские буквы-призраки за текстом (образцы владельца: mamuka.rest, zakroma.rest; его
слова 01.10.2026: «там ещё и 2D красивые в тему картинки встроены, это тоже надо уметь»). Что стоит у образца,
снимает `bgdecor.mjs` (`reference/discovery.md`); свои делаются так:

1. **Что рисовать** — 4–8 предметов из мира **своего** дела (не донора): сырьё, инструмент, растение, посуда.
   Список — в `analysis.md`, «Детали для красоты».
2. **Чем** — `templates/sketch2d/`: фигуры кодом (`sketch-kit.mjs`: эллипс, лист, линия, кривая, поворот,
   расстановка) → `svg3d.mjs rough` (штрих и штриховка от руки, один `--seed` на набор — одна рука) → SVG 5–16 КБ.
   Образец — `botanical.mjs` (клевер, колос, горчица, пчела, росток). Чужие картинки, наборы иконок и файлы
   донора не брать; генерация — только с согласия владельца (`recraft.mjs`).
3. **Как ставить** — вне потока (`position: absolute`, `pointer-events: none`, `alt=""`, `loading="lazy"`),
   цвет — одна «тушь» из палитры сайта, бледность 30–45 % на светлом поле; под заголовком раздела, у края
   колонки, за текстом сбоку. Не под строками основного текста: контраст текста проверяет `a11y.mjs`.
4. **Сколько** — один-два рисунка на раздел и разные от раздела к разделу; один и тот же на каждой странице —
   уже шаблон. На телефоне — меньше и мельче, либо скрыть: проверить 390 и 320 px.
5. **Предметы на полях** — мелкие объёмные предметы (пререндер) слева и справа от колонки на широких экранах
   (от ~1400 px), с лёгким сдвигом по прокрутке; на узких скрыты. Не заходят в колонку содержимого.
6. **Сверка** — `bgdecor.mjs compare` с образцом: сколько, где и какой бледности у него и у нас; глазами —
   пары снимков одного экрана.

Буквы-призраки и крупные бледные слова — приём `templates/decor-kit/` («бледные слова»), а не картинка.

## Движение

Вопросы перед каждой анимацией: где (какой элемент), зачем (направляет
взгляд, показывает связь, отвечает на действие), какая (появление, сдвиг,
масштаб, цвет), сколько (длительность), как (кривая), по какому событию
(загрузка, прокрутка, наведение, клик), что при «меньше движения».

Сначала — язык движения донора или сайта, снятый числами: `motion.mjs <адрес> --out <папка>`
(таблица «вид · где · запуск · из → в · длительность или отрезок прокрутки · рецепт»; рецепты —
`reference/motion.md`), в дополнение — тип появления из `design/site.json` → `desktop.motion.scrollReveal`
(и `mobile.…`) и «что появляется при наведении» из разведки. Перед отчётом — `motion.mjs compare`. У streetwearbrands при
прокрутке появляется один блок, а подписи карточек — при наведении: 21
блок со сдвигом 22 px на своём сайте — это уже не его язык.

Значения по умолчанию — только если у донора и сайта своего языка
движения нет, и с записью об этом в `authorship.md`:

- наведение и клик — 150–250 мс, `ease-out`;
- появление при прокрутке — 500–700 мс, `cubic-bezier(.2,.7,.2,1)`, сдвиг 16–24 px, каскад 60–90 мс, срабатывает один раз при 15–20% видимости;
- бесконечные анимации — только одна на экран и только если она несёт смысл; пульсирующая кнопка — почти всегда лишняя;
- ничего не анимировать дольше 1 с, кроме сцен на холсте.

Технология по возрастанию:

| технология | когда |
|---|---|
| CSS transition | состояния |
| CSS keyframes + класс от `IntersectionObserver` | появления при прокрутке |
| Web Animations API | последовательности из JS без библиотеки |
| GSAP (+ ScrollTrigger) | привязка к прокрутке, сложные таймлайны, закрепление |
| Lottie | только готовые файлы от дизайнера |
| Framer Motion | только на React |

Всегда:

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { animation-duration: .01ms !important; transition-duration: .01ms !important; }
}
```
или адресно — но блоки появления обязаны быть видимыми без анимации.

**Проверка:** `runtime.mjs --scroll` (все спрятанные появились, нет
горизонтальной прокрутки), `--motion` (сколько идёт, бесконечные, что
остаётся при «меньше движения» — в отдельной вкладке; какие законченные
анимации держат свойство), `--hover-all` (каждое правило `:hover` меняет
объявленное; анимация с `fill: both` его перебивает — FAIL), снимки
в фазах (`--shot`), `perf.mjs` — кадры/с при прокрутке: 55 и выше — OK, от 40
до 55 — WARN, ниже 40 — FAIL (порог один для любого экрана).

## Телефон и планшет

Не уменьшать десктоп, а проектировать заново четыре вещи: первый экран
(заголовок, одно действие, «позвонить»), меню (открывается, закрывается,
не прокручивает фон), формы (поля 16 px, цели 44 px, маска телефона),
таблицы и сетки (в карточки или горизонтальную прокрутку с подсказкой).
Планшет — отдельный взгляд: две колонки вместо трёх, меню ещё десктопное
или уже мобильное.

Проверка на `desktop`, `tablet`, `mobile` (и `laptop`, если сетка ломается
на 1280): `shots.mjs`, `runtime.mjs --viewport mobile --scroll --click "<меню>"`,
`a11y.mjs --viewport mobile` (цели, размер полей), `perf.mjs` (по умолчанию
телефон и медленная сеть).
