# Типографика: как набрать текст красиво и проверить числами

Этап 2 — план и дизайн-система, этап 3 — вёрстка, этап 4 — проверка.
Проверяет `scripts/typeset.mjs` (правила, пороги и коды выхода — `typeset.mjs --help`).
Рядом работают:

- `a11y.mjs` — кегль, контраст, `lang`;
- `cliche.mjs` — шаблонные приёмы;
- `verify.mjs` (design-reference) — шкала против донора;
- `perf.mjs` — вес шрифтов;
- `cyrillic-check.mjs` — кириллица у шрифта, до выбора;
- `fonts.mjs` — шрифты Google с кириллицей: подбор (`pick`, `pairs`) и загрузка к себе (`get`).

## 0. Донор сильнее учебника

В режиме донора и при «сохрани стиль» шкала, гарнитуры, начертания,
регистр, разрядка и интерлиньяж берутся из паспорта (`design/*.tokens.css`,
`discovery.md`), даже если они расходятся с числами ниже. Числа этого файла
решают там, где донор молчит:

- длина строки;
- висячие предлоги и одинокие слова;
- переносы;
- загрузка шрифтов, подмена гарнитуры, синтетические начертания;
- набор компонентов, которых у донора нет.

Отойти от донора ради учебника — это решение: запись в
`authorship.md` с причиной.

**Дефекты — не язык донора.** Висячий предлог, синтетический жирный,
₽ системным шрифтом, «реки» выключки, разрыв «3D-|принтер» исправляются,
даже если у донора так же.

**Этот файл — не повод добавлять подписи капсом с разрядкой.** Это шаблон
(`cliche.mjs`: `caps-microlabel`, `eyebrow`). Правило про разрядку капса — только
для капса, который уже есть в языке донора или сайта.

## 1. Длина строки

| где | desktop | телефон |
|---|---|---|
| основной текст | 55–75 знаков с пробелами (норма 45–80) | 30–45 |
| лид под заголовком | 40–60 | 25–40 |
| карточки, подписи, FAQ | 35–55 | 25–40 |
| заголовок h1 | до 35 в строке при кегле от 64 px, до 45 — при 40–56 px; нижней границы нет | 10–20 |

Русские слова длиннее английских: при той же ширине в строке меньше слов,
чаще остаются висячие и одинокие. Держаться середины диапазона.

```css
.prose { max-width: 36em; }  /* гротеск 16–18 px: около 62–68 знаков кириллицы */
.lead  { max-width: 30em; }
```

Замер стенда `typeset`: Commissioner 500, 18 px, `max-width: 34em` — от 54 до
67 знаков в строке, медиана 61, в Chrome и Firefox одинаково. Единица `ch` —
ширина цифры «0», а не русской буквы. Число знаков по `ch` у кириллицы
расходится с настоящим, поэтому верить замеру `typeset`, а не единице.

- Длиннее 80 знаков — сузить колонку, разбить на две или поднять интерлиньяж
  до 1.6 и выше.
- Короче 30 знаков на desktop — рваный край и частые висячие. Основной
  текст в узких карточках не набирать.

`typeset` (правило `measure`) судит медиану полных строк основного текста:

| экран | OK | INFO | WARN | FAIL |
|---|---|---|---|---|
| desktop | 45–80 | 30–44 (карточки, FAQ) | меньше 30, 81–95 | больше 95 |
| планшет | 40–80 | 30–39 | меньше 30, 81–95 | больше 95 |
| телефон | 28–50 | 22–27, 51–55 | меньше 22, больше 55 | — |

Русские сайты из разобранных набирают уже — колонками по 20–45 знаков (§20).
Длину строки и в режиме донора решает этот файл: узкую колонку донора не копировать.

## 2. Интерлиньяж по кеглю

| кегль, px | роль | line-height |
|---|---|---|
| 12–14 | подписи, сноски | 1.4–1.6 |
| 15–18 | основной текст | 1.5–1.65 |
| 19–24 | лид, крупный текст | 1.35–1.5 |
| 25–40 | h2–h3 | 1.15–1.3 |
| 41–64 | h1, дисплей | 1.0–1.15 |
| 65 и больше | дисплей | 0.9–1.05 |

- Значение без единиц. Длиннее строка — больше интерлиньяж.
- **Выше верхней границы — не ошибка**, если строка длинная или текст тонкий на
  тёмном: quakerschool.org 21 px / 1.6, g-part.tech 15 px / 1.73, piszczek.pl
  14.5 px / 1.7. **Ниже нижней — ошибка:** loaf.agency 18 / 1.3, romashka.media
  16 / 1.19, madeon.studio 17 / 1.24. `typeset`: ниже — WARN, выше — INFO; меньше
  1.0 у текста до 24 px — FAIL.
- **Крупный h1 от 80 px в 2+ строки — 0.8–1.05** (у сайтов 0.8–0.92). Ниже 0.9
  проверить Й, Ё, Ц, Щ, Д на снимке (romashka.media — 0.8 на кириллице).
- Капс в заголовке — от 1.0: выносных вниз у прописных нет. Ниже 1.0 у капса и
  слов с «Ё», «Й» знаки над буквой касаются строки выше. Смотреть на снимке.
- Один рецепт на все заголовки: `line-height: calc(1em + 0.5rem)`. При 16 px
  это 1.5, при 40 px — 1.2, при 72 px — 1.11. Интерлиньяж сам уменьшается с кеглем.

```css
:root { --lh-text: 1.6; }
body { line-height: var(--lh-text); }
h1, h2, h3, .display { line-height: calc(1em + 0.5rem); }
```

## 3. Шкала и clamp()

- Шаг шкалы: 1.2 — спокойно, много уровней, телефон; 1.25–1.333 —
  выразительно; от 1.5 — плакат, 3–4 уровня. На desktop шаг крупнее, на телефоне 1.2.
- Уровней не больше 5–6: мелкий, основной, h3, h2, h1, дисплей. Соседние
  уровни отличаются хотя бы в 1.15 раза. Ближе — глаз их не различает:
  различать весом или не делать отдельным уровнем.
- Разных кеглей с текстом на странице — не больше 8 (`typeset` WARN при большем;
  считаются кегли с текстом от 20 знаков). VN3D — 10 на desktop и 12–13 на телефоне.
- Соседние кегли, отличающиеся не больше чем на max(1 px, 4 %), — один уровень: 23 и 24 от одного
  `clamp()` в карточках разной ширины (или от округления 23.4/23.6) `typeset` показывает как «23–24 px» и
  считает одним уровнем; 16 и 18, 32 и 36 — разные уровни. Уровни заголовков с такой разницей (h3 23.5 и
  h4 24) — не «перевёрнуты», а WARN «один уровень» при одном весе. В json — `summary.sizeLevels`.
- h1 крупнее h2 на каждом экране. На телефоне VN3D h2 40 px крупнее h1 34 px —
  уровни перевёрнуты (`typeset` WARN).
- h1 к основному тексту: desktop 3–6× (до 10× при заголовке из 1–3 слов), телефон 2–3×.

Плавный кегль между двумя ширинами:

```
наклон     = (max − min) / (ширина_max − ширина_min)
предпочтит = (min − наклон × ширина_min) в rem + наклон × 100 vw
```

h1 от 36 px на 360 до 72 px на 1440: наклон 36/1080 = 3.333vw,
основа 36 − 12 = 24 px = 1.5rem.

```css
:root {
  --fs-body: clamp(1rem,    0.958rem + 0.185vw, 1.125rem); /* 16 → 18 */
  --fs-h3:   clamp(1.25rem, 1.167rem + 0.37vw,  1.5rem);   /* 20 → 24 */
  --fs-h2:   clamp(1.75rem, 1.417rem + 1.481vw, 2.75rem);  /* 28 → 44 */
  --fs-h1:   clamp(2.25rem, 1.5rem   + 3.333vw, 4.5rem);   /* 36 → 72 */
}
```

- В середине всегда должен быть `rem`. Чистый `vw` не растёт при увеличении
  страницы в браузере (WCAG 1.4.4). Максимум — не больше 2.5 минимума.
- В режиме донора крайние точки берутся из токенов extract: `--fs-h1` (1440) и
  `--fs-h1-mobile` (390). Формула та же, ширины 390 и 1440.
- Числа примера — не шкала сайта.

## 4. Вертикальный ритм и сетка

- Шаг 4 или 8 px. Отступы — из токенов `--space-*`, не на глаз.
- Между абзацами — 0.75–1em. Пустых строк нет.
- **Близость.** Заголовок ближе к своему тексту, чем к блоку сверху: сверху
  в 2–3 раза больше, чем снизу (h2: 64–96 сверху, 16–24 снизу). `typeset` WARN,
  если снизу столько же или больше.
- Внутри секции отступы меньше, чем между секциями.
- `text-box: trim-both cap alphabetic` у крупных заголовков убирает пустые
  поля над прописной и под базовой линией: заголовок оптически встаёт в
  сетку. Chrome 153 и Firefox 156 этой машины его понимают. Где не понимают —
  ничего не ломается.

```css
.flow > * + * { margin-block-start: var(--flow, 1em); }
h2 { margin-block: var(--space-section-head, 72px) var(--space-head-text, 20px); }
h1, .display { text-box: trim-both cap alphabetic; }
```

**Горизонтальная сетка.**

- Текст начинается на линии колонки, а не посреди неё. Левый край h1, лида,
  абзацев и кнопки одной секции — одна линия (±2 px).
- Ширина текстовой колонки — целое число колонок. Сетка 12 колонок, контейнер
  1200 px, промежуток 24 px: колонка 78 px. Основной текст — 6–7 колонок
  (588–690 px, при 18 px это около 58–69 знаков кириллицы), лид — 5–6, h1 — 8–10.
- Узкая колонка в широком поле — смещением на колонку (`grid-column: 2 / span 6`),
  а не `margin: auto` по центру, если язык сайта не центрированный.
- На телефоне колонка во всю ширину, поля 16–20 px. Поле меньше 16 px — текст
  липнет к краю экрана.

```css
.wrap  { display: grid; grid-template-columns: repeat(12, minmax(0, 1fr)); column-gap: var(--gutter, 24px); }
.prose { grid-column: 2 / span 6; }
@media (max-width: 767px) { .prose { grid-column: 1 / -1; } }
```

## 5. Гарнитуры: сколько, какие, кириллица

- **Не больше двух.** Акцидентная для заголовков и текстовая — или одна с
  широкой палитрой начертаний. Третья — только моноширинная для кода.
  Иконки — SVG, не иконочный шрифт.
- Пару подбирать по контрасту: гротеск и антиква, геометрический и
  гуманистический. Высота строчных — близкая.
- Контраст — **по ролям**: заголовки одной гарнитурой, текст другой. Одно слово
  курсивной антиквой внутри гротескового h1 — шаблон `italic-serif-accent`
  (`cliche.mjs`, `authorship.md`). Брать, только если это язык донора.
- **Откуда брать.** Шрифт донора с кириллицей — он (§0). Иначе по умолчанию Google Fonts: бесплатно,
  свободные лицензии (почти всё — OFL), кириллица у 293 семейств из 1934. Кандидаты по характеру —
  `fonts.mjs pick --like "<характер по-русски>" [--category serif] [--need "₽№«»"]`: только с кириллицей,
  у каждого ссылка specimen; «ИИ-набор», CJK и «нет latin-ext» помечены и стоят ниже. Готовые пары
  «заголовки → текст» — `fonts.mjs pairs`: из 74 пар ui-ux-pro-max годится 21, у остальных хотя бы один
  шрифт без кириллицы. Данные — снимок ui-ux-pro-max; последнее слово — за файлом, который скачал `get`.
- **Кириллицу проверять до выбора:** `cyrillic-check.mjs "Гарнитура:вес"`.
  Самопроверка: у Oswald кириллица есть, у Bebas Neue — нет. Скачанные файлы `fonts.mjs get` проверяет
  сам, по таблице знаков (cmap): 66 букв с Ёё и ₽№«»„“—–… — по объединению подмножеств, как их получит
  страница; кириллицы нет — отказ, ничего не записано. Подмножество cyrillic-ext без cyrillic — это не
  русские буквы (Fjalla One, Black Ops One и ещё 25 семейств).
- **Знаки русского сайта** проверять отдельно: « » „ “ — – … № ₽ ё Ё. Знак ₽ часто
  выпадает из подмножеств. У Google Fonts он в latin-ext (U+20AD–20C0), а не в
  cyrillic и не в latin. VN3D грузил cyrillic и latin, и ₽ в ценах рисовался
  системным Segoe UI, а Ż в подписи автора фото «Jakub Żerdzicki» — Segoe UI
  Semibold (`typeset`, 28.09): оба знака лежат в latin-ext.
- **На живой странице** это видит `typeset`. В Chrome — по CDP знак за знаком:
  какой шрифт нарисовал каждый знак (очевидные способы врут: у Bebas Neue
  кириллицы нет, а браузер молча подставляет системный). В Firefox CDP нет —
  только знаки вне `unicode-range` веб-шрифта, это наверняка системный шрифт.
  Системным набрана кириллица — FAIL, другие знаки — WARN.
- «Ё» в капсе и крупные Ж, Д, Л, Ф, Ы акцидентного шрифта — смотреть на снимке
  h1 крупно: кириллица бывает нарисована хуже латиницы.
- Запасной стек с кириллицей: `system-ui, -apple-system, "Segoe UI", Roboto, Arial, sans-serif`.
- Часто без кириллицы: Bebas Neue (проверено), Poppins, DM Sans, Space Grotesk, Outfit,
  Plus Jakarta Sans, Lato, Work Sans (список по данным — `fonts.mjs pairs`).
  Перед решением прогнать `cyrillic-check`. Inter, Manrope, Onest, Montserrat
  кириллицу имеют, но это «ИИ-набор» (`cliche`: `overused-font`): брать, только если
  это язык донора.

## 6. Начертания и variable fonts

- 2–4 начертания на гарнитуру, например 400, 500, 700 и курсив, если он есть в
  языке. Каждое загруженное начертание стоит на странице. Каждое, что
  просит CSS, загружено.
- **Синтетика.** CSS просит 700, а файла 700 нет — браузер утолщает буквы сам,
  грязно (`typeset` FAIL). Курсив без курсивного файла — просто наклон. Лечение —
  загрузить начертание или не просить его. `font-synthesis: none` — страховка,
  а не решение: текст молча станет обычным. `typeset` видит синтетику пикселями:
  проба с `font-synthesis` и без неё. На стенде настоящее начертание — 0%,
  жирный 800 при файле 500 — 53–131%, курсив без файла — 96–109% (Chrome и
  Firefox, desktop и телефон); порог — 10%. По ширине не видно: синтетический
  жирный в Chrome ширину не меняет.
- **Вес вне диапазона.** CSS 400 при файле 500–700 рисуется как 500. На VN3D
  подписи карточек с `font: 400` (`css/site.css:100`) не легче соседнего текста.
  Загрузить 400 или писать 500. Запрошенного веса нет — браузер берёт при весе
  больше 500 сначала тяжелее, при весе меньше 400 — легче: демо-сайт кофейни
  просит 700 у кнопок при файлах Montserrat 600 и 800, и рисуется 800, а не 600
  (`typeset` INFO «вес не загружен»).
- **Variable font.** Один файл на диапазон, в `@font-face` — `font-weight: 300 800`. Так пишет
  `fonts.mjs get`: Google отдаёт переменный файл сразу на все запрошенные веса, диапазон — из оси wght файла.
  Стандартные оси — обычными свойствами: `font-weight`, `font-stretch`,
  `font-style`, `font-optical-sizing: auto`. `font-variation-settings` — только для
  своих осей: оно не складывается с этими свойствами, а перебивает их.

```css
@font-face {
  font-family: "Commissioner";
  src: url("fonts/commissioner-cyrillic.woff2") format("woff2");
  font-weight: 400 700; font-style: normal; font-display: swap;
  unicode-range: U+0301, U+0400-045F, U+0490-0491, U+04B0-04B1, U+2116;
}
```

## 7. Разрядка

| что | letter-spacing |
|---|---|
| основной текст | 0 (±0.01em). Строчные в тексте не разряжать |
| мелкий текст 12–13 px | 0…+0.02em |
| мелкий капс до 14 px — если он есть в языке | +0.1…+0.2em (у доноров 0.12–0.3em) |
| крупный капс от 32 px | 0…+0.03em |
| строчный дисплей 40–64 px | −0.015…−0.035em |
| строчный дисплей от 72 px | −0.02…−0.05em |

- Только в `em`: в `px` разрядка не растёт с кеглем.
- На телефоне у h1 до 48 px отрицательная разрядка вдвое меньше, чем на desktop,
  или ноль: github.com/home ставит −0.035em на 64 px и normal на 40 px. raulvbrito.com
  оставляет −0.075em на 41.6 px — кириллица при такой разрядке слипнется.
- Цифры в ценах не разряжать.
- Отрицательную разрядку проверять на самых широких буквах: Ж, Ш, Щ, Ы, Ю.
  Слипание видно у них первым.

## 8. Знаки и замены

- **Кавычки.** Снаружи «ёлочки», внутри „лапки“: «Он сказал: „да“».
- **Тире** в предложении — «—» с пробелами, перед ним неразрывный: `слово&nbsp;— слово`.
- **Диапазоны** — короткое «–» без пробелов: `10–20 см`, `пн–пт`. Минус в числах — «−».
  Дефис — только внутри слов.
- **Многоточие** — один знак «…».
- **Разряды** — узкий неразрывный пробел: `1&#8239;000&nbsp;₽`.
- **Число и единица, номер, параграф** — неразрывно: `5&nbsp;см`, `№&nbsp;5`, `§&nbsp;3`.
- **Сокращения и инициалы:** `т.&nbsp;е.`, `т.&nbsp;д.`, `А.&nbsp;С.&nbsp;Пушкин`.
- **Короткие слова через дефис не рвать:** «3D-принтер», «по-русски», «из-за», «Wi-Fi».
  Нужен неразрывный дефис U+2011 или `<span class="nowrap">`. На VN3D на телефоне
  строка кончалась на «3D-», а «принтере.» уезжал вниз один.
- **Висячая пунктуация.** `hanging-punctuation` понимает только Safari; Chrome 153 и
  Firefox 156 — нет. Для цитат и абзацев, которые начинаются с «:
  `<span class="hang">«</span>` и `.hang { margin-inline-start: -0.5em }`. Число
  подобрать по снимку: ширина «» своя у каждого шрифта. Маркеры списка —
  за оси текста.

## 9. Висячие предлоги и неразрывные пробелы

Неразрывный пробел ставится:

- после одно- и двухбуквенных предлогов, союзов, частиц и местоимений: в, к, с, у,
  о, и, а, я, во, ко, со, об, от, до, по, за, из, на, не, ни, но, да, мы, вы, он;
- после трёхбуквенных предлогов и союзов: для, при, про, без, над, под, или;
- перед частицами же, ли, бы и перед тире;
- между числом и единицей, в инициалах и сокращениях.

**Цепочкой — не больше двух слов.** Длинная неразрывная цепочка на 320 px
вылезает за экран. Проверка — `runtime.mjs --viewport mobile-s --scroll`.

**Где ставить.** В исходном HTML и в данных, из которых он собирается
(`products.js`, json, база). Не скриптом при загрузке: текст перестроится на
глазах, а поиск и копирование увидят старый.

**Разовый типограф** — только по текстовым узлам, не по разметке. JS, флаги `giu`:

```js
const SHORT = 'в|во|к|ко|с|со|у|о|об|обо|от|до|по|за|из|изо|на|не|ни|и|а|но|да|я|мы|вы|он|для|при|про|без|над|под|или';
t = t.replace(new RegExp(`(?<=^|[\\s(«„"])(${SHORT})\\s+(?=\\S)`, 'giu'), '$1\u00a0')
     .replace(/\s+(же|ли|ль|бы|б)(?=[\s.,!?…»]|$)/giu, '\u00a0$1')
     .replace(/\s+—/gu, '\u00a0—')
     .replace(/(\d)\s+(?=(₽|руб|см|мм|кг|г|л|мл|%|шт|лет|года?|мин|ч|сек)(?=[^\p{L}]|$))/gu, '$1\u00a0');
```

Просмотр назад `(?<=…)` нужен, чтобы «и в городе» привязал оба слова: с обычной
группой второе слово пропускается.

**Проверка.** `typeset` — строка «короткое слово в конце строки» (разрывы на этой
ширине) и строка «привязано N из M»: сколько мест защищено на любой ширине. На
VN3D главная — 0 из 58, «Обо мне» — 0 из 53; демо-сайт кофейни — 0 из 109
(28.09, все блоки, кроме меню).

**Сам `typeset` ничего не исправляет.** Он меряет и сообщает: висячий предлог и
одинокое слово — WARN, в том числе на первом экране (там отдельной строкой
«первый экран» и в условии выхода, SKILL.md). Правка — неразрывный пробел в
исходном тексте или данных, затем повторный прогон.

## 10. Одинокие слова: вдовы и сироты

В вебе главное — одно короткое слово в последней строке абзаца или заголовка.
В `typeset` это «одно слово в последней строке».

- **Абзацы.** `text-wrap: pretty`: Chrome и Safari подбирают разрывы так, чтобы
  последнее слово не оставалось одно. На VN3D «Обо мне», телефон, одна строка
  CSS исправила 5 абзацев из 5.
- **Firefox 156 `pretty` не понимает**, а это браузер пользователя. Для лида,
  подписей первого экрана и коротких абзацев под заголовком нужен ещё
  неразрывный пробел между двумя последними словами.
- **Firefox и Chrome ломают строки по-разному.** Firefox набирает тот же
  Commissioner чуть уже: h1 стенда `typeset` в Chrome кончает строки на «для» и
  «и», в Firefox — на «для» и «на», и последнее «заказ» остаётся одно. Первый
  экран проверять и прогоном `typeset --browser firefox`.
- **Заголовки.** `text-wrap: balance` понимают Chrome, Firefox и Safari. Он
  выравнивает короткие блоки (в Chromium — до 6 строк), для абзацев не годится.
- `orphans` и `widows` работают только в колонках и печати: на экране не помогают.

```css
h1, h2, h3, .lead, figcaption, blockquote { text-wrap: balance; }
p, li, dd { text-wrap: pretty; }
```

## 11. Переносы

- `hyphens: auto` работает только с `lang`: `<html lang="ru">` или атрибут на блоке.
- **Где нужны:** узкие колонки (телефон до 400 px, карточки до 300 px) и длинные
  слова в крупном тексте на телефоне («высокодетализированные» при 28 px).
- **Где не нужны:** заголовки на desktop, кнопки, меню, цены, названия.
- **Ограничить:** `hyphenate-limit-chars: 6 3 3` — переносить слова от 6 букв,
  оставлять хотя бы 3 до и после. Chrome 153 и Firefox 156 понимают.
- Одно длинное слово в заголовке — ручной мягкий перенос `&shy;`. Работает везде.
- **Больше двух переносов подряд** — «лесенка». Править текст или ширину.
- **Проверять в Firefox.** Chrome без интерфейса не переносит: словарей нет. На этой
  машине Chrome 153 не перенёс ни русского, ни английского слова, Firefox 156
  перенёс. Поэтому строки на снимках скриптов в Chrome при `hyphens: auto` могут не
  совпадать с тем, что видит человек. Проверка — `typeset.mjs --browser firefox`.

```css
.prose { hyphens: auto; hyphenate-limit-chars: 6 3 3; }
h1, h2, h3, button, .btn, nav, .price { hyphens: manual; }
@media (min-width: 1024px) { .prose { hyphens: manual; } }
```

## 12. Выключка по ширине — нет

- `text-align: justify` в вебе без переносов даёт «реки». На стенде колонка 300 px:
  пробел растянут до 39 px при обычном 3.4 px, в 11 раз.
- Набор — влево (`start`). По центру — только 1–3 строки: заголовок, подпись, кнопка.
- Если заказчик настаивает: только с `hyphens: auto`, строкой от 60 знаков,
  `text-align-last: start` и не на телефоне.

## 13. Композиция первого экрана

- **h1.** Desktop — 1–3 строки, лучше 2. Телефон — до 4, 5 — предел. 6–12 слов.
  Длиннее — сокращать текст, а не уменьшать кегль. `typeset`: desktop 4–5 строк —
  WARN, от 6 — FAIL; телефон 5–6 — WARN, от 7 — FAIL. Демо-сайт кофейни: h1 88 px в
  4 строки, и «утра» в последней строке одно.
- **Висячие и одинокие на первом экране** (h1, лид, кнопка) — отдельной строкой
  «первый экран»; до сдачи их нет (условие выхода, SKILL.md).
- **Контраст размеров.** h1 к основному тексту: desktop 3–6× (до 10× при
  заголовке из 1–3 слов), телефон 2–3×. Лид — в 1–1.7 раза крупнее основного
  или того же кегля, но отличается весом или цветом; 1–3 строки, `max-width: 30em`.
- **Одна ось.** h1, лид и кнопка начинаются от одной левой линии колонки
  сетки (п. 4) — или всё по центру. Центр — шаблон `centered-hero` (`cliche.mjs`),
  если у донора его нет. Кнопка под лидом через 1.5–2.5 высоты его строки (24–40 px).
  `typeset` сравнивает левые края (±4 px), а у первого экрана по центру — центры
  h1, лида и ряда кнопок (±6 px).
- **Кнопка видна без прокрутки** на 1440×900 и 390×844. На 320×568 — тоже, либо
  есть закреплённая панель действия. Главная кнопка для `typeset` — первая
  залитая кнопка ниже h1 и до следующего заголовка (без него — в пределах 3 экранов).
- **Одна главная кнопка.** Вторая — текстовой ссылкой, не второй пилюлей
  (`cliche`: `hero-two-ctas`).
- **Оптика.** Крупный заголовок от 64 px из-за полей букв отступает от оси
  текста. Сдвиг `margin-inline-start: -0.04em…-0.06em` подобрать по снимку;
  по вертикали — `text-box` (п. 4).

## 14. Текст на фото

- Контраст 4.5:1, для крупного текста 3:1. Меряет `a11y.mjs` по пикселям фона.
- Добиваться подложкой-градиентом, а не тенью букв:
  `background: linear-gradient(to top, rgb(0 0 0 / .6), rgb(0 0 0 / 0) 55%)`.
- Текст — на спокойной части кадра, не на лице и не на мелкой детали.
- На телефоне — свой кроп (`object-position`) или текст под фото.
- Тонкие начертания до 300 и мелкий текст на фото — нет.

## 14а. Тёмная тема

По шести сайтам darkmodedesign.com (28.09.2026): raulvbrito.com, lazy.so, yoin-fragrance.netlify.app,
loaf.agency, github.com/home, piszczek.pl.

- Фон не чисто чёрный (#0A0A0B, #121212, #131416, #030303), текст не чисто белый (#EDEDE8, #EAE8E6,
  #E2E8F0). Чистые #000 и #FFF — только под видео и когда текста мало (Loaf).
- Три уровня яркости. Основной — контраст 16–18:1. Второй — 5.5–7.3:1: описания, продолжение
  двухтоновой фразы. Служебный — 2.7–3.1:1, только крупным или капсом: копирайт, рубрики.
- Лёгкие начертания 300 — у заголовков со засечками или с мягким свечением (`text-shadow: 0 0 24px
  rgba(255,255,255,.1)`), у текста — при интерлиньяже 1.7–1.9. Вес 200 на 14 px — нет.
- Вариативный шрифт позволяет чуть облегчить белое: 425 / 460 / 480 вместо 500 / 600 (GitHub).
- Линии и сетки — цветом текста с прозрачностью 0.05–0.22; глубина — ступенями фона
  (#0E0E0E → #151515 → #1C1C1C → #242424), а не тенями.

## 15. Цифры

- `font-variant-numeric: tabular-nums` — в таблицах, колонках цен, прайсах,
  таймерах, счётчиках: столбцы не пляшут, счётчик не дрожит.
  `lining-nums` — если у шрифта по умолчанию цифры разной высоты.
- В тексте абзаца цифры пропорциональные, как по умолчанию.
- Есть ли у шрифта моноширинные цифры: «1111» и «8888» с `tabular-nums` одной
  ширины (`typeset` INFO).
- Цены — `1 000 ₽` с узким неразрывным пробелом, ₽ — в подмножестве шрифта (п. 5).

## 16. Загрузка шрифтов

- **Только woff2 и свои файлы.** От Google Fonts CDN не зависеть: `runtime` уже
  ловил `ERR_CONNECTION_CLOSED`. Скачать к себе — `fonts.mjs get "<Семейство>" --weights 400,700 --out <папка сайта>`:
  файлы в `fonts/`, рядом `fonts/fonts.css` — `@font-face` с `unicode-range` и `font-display: swap`, раздел на
  семейство (повторный `get` заменяет свой раздел, чужие разделы и свой CSS не трогает). Сеть — только в `get`,
  сайт к Google не ходит.
- **Подмножества по `unicode-range`:** cyrillic, latin и нужные знаки — ₽ из latin-ext. `get` по умолчанию
  берёт все три: браузер качает файл подмножества, только когда на странице есть его знаки.
- **Надпись-логотип** крупным акцидентным шрифтом — подмножество ровно под её знаки:
  `fonts.mjs get "<Семейство>" --weights 700 --text "<надпись>" --out <папка сайта>` — 1–3 КБ вместо 30–60
  (Unbounded 700, «Кофейня «Зёрна»» — 2.4 КБ). Свой раздел с `unicode-range` знаков надписи, полному шрифту не
  мешает. Надпись сменилась — скачать заново; все надписи этим шрифтом — одной строкой `--text`.
- **`font-display`:** `swap` для текста; `optional` — если шрифт не критичен и сдвиг
  вёрстки важнее; `block` и `auto` — нет: до 3 с невидимого текста.
- **`preload`** — 1–2 файла первого экрана (кириллица начертаний h1 и основного
  текста), обязательно с `crossorigin`. Без него файл скачается дважды. Строку для файла cyrillic печатает `get`.
  Предзагруженный, но не использованный — предупреждение в консоли.

```html
<link rel="preload" href="fonts/x-cyrillic-700.woff2" as="font" type="font/woff2" crossorigin>
```

- **Прыжок вёрстки при подмене** — запасной с подогнанными метриками. Числа
  подобрать замером ширины одного абзаца обоими шрифтами; в примере они условные.

```css
@font-face { font-family: "X Fallback"; src: local("Arial");
  size-adjust: 104%; ascent-override: 92%; descent-override: 24%; line-gap-override: 0%; }
body { font-family: "X", "X Fallback", system-ui, sans-serif; }
```

- Бюджет — `perf.mjs`: шрифты по сети до 150 КБ, WARN до 400.

## 17. Tilda и конструкторы

- Tilda у нас только донор (`reference/donor-tilda.md`): сайты на Tilda не правим и не
  переносим — отсюда снимаем числа набора донора, а свой сайт набираем по правилам выше.
- Длина строки в Zero Block — ширина текстового элемента на каждом брейкпоинте
  редактора. `typeset` гонять на тех же ширинах: `--viewports 1200x800,960x800,640x900,480x800,320x568`.
- **Кегли Zero Block в вычисленном стиле — без CSS `zoom`.** У madeon.studio на
  1440 zoom 1.2: на экране h1 48 px, а не 40. `typeset` множит кегль на
  `currentCSSZoom`; сравнивать с донором — тоже после умножения.
- `proximity` и `near-align` на Tilda почти всегда ложные (текст в
  `position: absolute`): судить `hang`, `orphan`, `fallback`, `synthetic`.

## 18. Как проверять

| что | чем | когда |
|---|---|---|
| строки, висячие, одинокие, выключка, переносы, интерлиньяж, шкала, гарнитуры, синтетика, подмена, загрузка, первый экран | `typeset.mjs <url> --viewports desktop,mobile,mobile-s` | этап 1 (`--tag base`, донор — `--tag donor`), этап 4 (`--tag after`) |
| переносы, `pretty` и первый экран в браузере пользователя | `typeset.mjs <url> --viewports desktop,mobile --browser firefox --tag after-ff` | если есть `hyphens: auto`, правка держится на `text-wrap: pretty` или на первом экране поправлены висячие и одинокие: строки в Firefox ломаются иначе |
| кириллица и знаки у шрифта | до выбора — `cyrillic-check.mjs "Шрифт:вес"`; скачанные файлы — `fonts.mjs get` сам (таблица знаков) | при любой смене гарнитуры |
| кегль, контраст, текст на фото, `lang` | `a11y.mjs` | этап 4 |
| шаблонность: надзаголовки, капс с разрядкой, гарнитура не донора | `cliche.mjs` | этап 4 |
| шкала и гарнитуры против донора | `verify.mjs` | этап 4, режим донора |
| вес шрифтов, CLS | `perf.mjs`; для CLS — `runtime --init` (qa.md) | этап 4 |
| глазами | вырезки `typeset/<tag>-<экран>/NN-*.png`, первый экран 1:1 — `00-hero.png` | всегда |

`--baseline <протокол донора>` опускает правила стиля, совпавшие с донором, до
INFO «как у донора»; дефекты (висячие, синтетика, системный шрифт) не опускаются.
Решения — `<out>/typeset-decisions.json`: `{ "правило": { "<подпись блока>": "почему" } }`,
тоже только для стиля и композиции.

## 19. Красиво, а не только правильно

- **Один типографский жест на страницу** — из языка донора или товара: огромный
  h1, контраст антиквы и гротеска по ролям, узкая колонка в широком поле. Не три жеста сразу.
- **Крупный шаг** вместо многих мелких: 3–4 заметно разных кегля лучше восьми
  похожих.
- **Воздух вокруг заголовка** больше, чем внутри текста.
- **Одна ось слева** на экран. Рваный правый край — ровный: без лесенок, одиноких
  слов и висячих предлогов.
- **Новый стиль текста — только с ролью.** Если роль не называется, это шум.
- **Смотреть глазами:** снимок первого экрана 1:1 и один длинный абзац на телефоне.
