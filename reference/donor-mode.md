# Режим донора: новый сайт на чужом языке

Когда: «сделай сайт в стиле вот этого», «как у них, но про наше». URL в
брифе — адрес **донора**, а не сайта. Своего «до» нет; эталон — донор.
Сайт собирается с нуля в папке прогона `site/`.

Журнал: `state.mjs <папка> init <адрес донора> "<запрос>" --mode donor --site <папка>/site`,
первой строкой `analysis.md` — «режим: донор; сайт собирается в <путь>».
Свой сайт с исходниками в языке донора — `--mode rework --donor <адрес донора>`.

## 0. Донора нет — предложить, где его взять

Когда: переработка «сделай дороже» без образца, сайт с нуля без референсов. Владелец (01.10.2026): «перед тем
как делать сайт, если у человека нет референса, нужно предлагать сайты, где они есть». Молча выбирать язык самому
нельзя — анкета спрашивает «сайт-образец есть?», на «нет» — два пути на выбор человека:

1. **«Подберите три»** — порядок ниже (Refero Styles, затем каталоги из таблицы): три кандидата со снимками,
   чем каждый подходит, рекомендация.
2. **«Дайте каталоги, выберу сам»** — отдать таблицу ниже как есть (адрес и одна строка, что там искать) и
   попросить вернуть 1–3 адреса живых сайтов со словами, что в каждом нравится: шрифты, фон, движение, раскладка.
   Что нравится в каждом — в `analysis.md`, «Решения пользователя»; дальше §1 по выбранному.

Адреса проверены 01.10.2026 только на доступность (ответ 200); описания — общие, состав каталогов не выверялся.
godly.website перенаправляет на recent.design; siteinspire.com (429), behance.net (403) и dribbble.com (202)
скриптом не открываются — только руками в браузере. Pinterest, Behance и Dribbble — доски настроения с
картинками, а не живые сайты: донором служить не могут (язык, движение и фактура снимаются только с живой
страницы), файлы оттуда на сайт не попадают.

**Refero Styles** — только поиск донора; язык снимается с живого сайта обычным порядком (§1), не с DESIGN.md.

**Доступ.** MCP-сервер `refero` (https://api.refero.design/mcp, вход OAuth через `/mcp` или
`Authorization: Bearer <токен>`) — только на платном тарифе Refero (Pro, Team, Lifetime), до 8 000
вызовов в месяц. Подключение: `claude mcp add --transport http --scope user refero https://api.refero.design/mcp`,
затем `/mcp` → refero → войти. Без тарифа — каталог styles.refero.design в браузере (просмотр бесплатный):
открыть глазами, искать строкой поиска, ничего не выкачивать скриптом.

**Порядок.**
1. Запросы по делу и настроению, по-английски, 2–4 штуки: «restaurant dark warm serif», «karaoke bar
   neon night», «billiards club classic», «coffee shop light editorial». С MCP — `refero_search_styles`,
   для 3–5 лучших `refero_get_style` (роли цвета, шкала кеглей, поверхности, компоненты);
   `refero_search_site` — если нужен сайт того же дела. MCP не подключён или требует входа — те же запросы
   глазами в браузере: Refero Styles, затем 2–3 каталога из таблицы под характер задачи; русское дело с
   кириллицей — сначала «Сделано на Tilda».
2. Отбор до трёх: близкое дело или настроение; живой многостраничный сайт (не одна посадочная);
   есть детали — фон с фактурой, рисунки в тему, предметы на полях, логотипы, игра шрифтов — и движение
   (сайт с ровным белым фоном без деталей кандидатом не брать, если в анкете фон не «ровный»); шрифты с
   кириллицей или ясная замена из Google Fonts (кириллицу проверять `cyrillic-check`); не SaaS-шаблон для
   ресторана. Образцы владельца по фону: zakroma.rest (мятая фактура с прожилками, орнамент на полях),
   mamuka.rest (наброски от руки и буквы-призраки за текстом).
3. Снимки первых экранов трёх живых сайтов (`shots.mjs <url> --viewports desktop,mobile --segments 0`)
   и вопрос пользователю: три кандидата, чем каждый подходит, рекомендация. Разные ответы — разная работа,
   поэтому спрашивать; пользователь недоступен — взять рекомендованный и записать это в отчёт.
4. Выбранный — донор: §1 целиком (discover всех типов страниц, extract design-reference, motion, typeset,
   cliche baseline, детали донора — задание агенту 1 в SKILL.md). DESIGN.md Refero сверить с замером:
   расхождения — в пользу живого сайта.
5. В `analysis.md`, раздел «Донор» — «подобран: каталог, запросы, три кандидата, почему этот» либо «выбран
   владельцем из каталогов: что ему в нём нравится» — его словами.

Фирменный стиль кандидатов одним запросом — `firecrawl.mjs scrape <кандидат> --run <папка> --formats branding`
(по кредиту на кандидата; подсказка, а не замер).

## 1. Снять донора целиком, а не только токены

```
node ~/.claude/skills/site-rework/scripts/discover.mjs <донор> --out <папка>/donor --no-design     # сводка, фактура, паспорт, медиа-слоты; дизайн-систему снимает extract ниже
node ~/.claude/skills/design-reference/scripts/extract.mjs <донор> --out <папка>/donor/design --name donor   # единственная спецификация донора: donor.json, donor.tokens.css — их и брать в вёрстку
node ~/.claude/skills/site-rework/scripts/texture.mjs <донор> --viewport desktop,tablet,mobile --out <папка>/donor/texture   # зерно и крупная фактура (мятая бумага, прожилки, ткань, доски): её вид с уверенностью, рецепты --grain-* и --surface-*
node ~/.claude/skills/site-rework/scripts/bgdecor.mjs <донор> --pages "/,<путь>" --viewport desktop,mobile --out <папка> --tag donor   # фон: рисунки, предметы на полях, буквы-призраки → decor/donor.md, вырезки открыть глазами
node ~/.claude/skills/site-rework/scripts/cliche.mjs baseline <донор> --out <папка>/cliche/donor.json          # desktop и mobile
node ~/.claude/skills/site-rework/scripts/motion.mjs <донор> --pages "home=/,product=<путь>,collection=<путь>" --viewport desktop,mobile --out <папка> --tag donor   # всё движение числами: donor-home, donor-home-mobile, donor-product… одним запуском
node ~/.claude/skills/site-rework/scripts/typeset.mjs <донор> --out <папка> --tag donor --viewports desktop,mobile   # набор донора — база для typeset --baseline на этапе 4
```

Спецификация донора несёт набор: «Набор: строка ~N знаков / M на телефоне, h1 в K строк» и `--measure` в
токенах — абзацам `max-width: var(--measure)`. Длину строки и строки h1 сверяет `verify.mjs`; весь набор
(висячие, одинокие, шрифт каждого знака) — `typeset.mjs --baseline`. Гарнитуры донора и свои —
`cyrillic-check.mjs`: для ru он проверяет и знаки ₽№«»„“—–…Ёё Ż. «нет знаков: ₽» — у Google Fonts ₽ в
latin-ext: подключить его или взять другую гарнитуру; свои подмножества — `--css <свои стили>` (сверка с
unicode-range). Код выхода 2 — кириллица есть, знаков нет.

**Все страницы донора, а не только главная.** Донор задаёт и структуру сайта:
у shapefest.com, кроме главной, — страница набора (товар), коллекция (категория),
тарифы, лицензия, политика, вход. До плана:

```
node ~/.claude/skills/site-rework/scripts/discover.mjs <донор> --out <папка>/donor --no-design --pages-shots 8
```

— раздел «Страницы сайта по типам» (ссылки и sitemap) и `donor/pages/<тип>.png` с h1–h3 по одной
странице каждого типа; открыть снимки глазами и в
`analysis.md` составить таблицу «тип страницы донора → что там → аналог для
нашего проекта → совет». Аналоги, которые подходят по смыслу, — **вопрос
пользователю** (`AskUserQuestion`, несколько вариантов), до плана. Пользователь
просил об этом прямо: «сайт многостраничный … если нашел — спрашивай, нужна ли такая страничка».

**Каждое движение донора — решение.** `motion.mjs` снимает всё движение донора таблицей
(`<папка>/motion/donor-home.md`: вид, элемент, запуск, из → в, длительность или отрезок прокрутки,
рецепт) — её целиком в `analysis.md`, раздел «Движение донора → блоки», и у каждой строки: наш блок
с теми же числами или «почему нет» (в `<папка>/motion-decisions.json`). У shapefest так снято:
фон чёрной плашки 1.4 → 1.1 и 0.9 → 0.5 на отрезке «верх блока 100% → 46% экрана», стопка первого
экрана — параллакс 5–50% прокрутки с поворотом, появления Framer 0 → 1 со сдвигом 20 px, лента
логотипов 50 px/с, печатающийся текст с мигающим курсором, логотип при наведении ×1.1 с поворотом
−3°, карточка ×1.04 с тенью, «Back to top». Копировать по максимуму: пропущенное движение
пользователь видит сразу.

**Каждый тип страницы, который будет у нас, — своим замером.** Все типы — одним запуском:
`motion.mjs <донор> --pages "home=/,product=<путь>,…" --viewport desktop,mobile --tag donor` (протокол
`donor-<тип>` на каждый тип и экран, в том числе движение по клику: меню-бургер на телефоне, аккордеоны,
вкладки), и перед сдачей `motion.mjs compare motion/donor-<тип>.json <наша страница того же типа>` —
все пары одной командой. Сверка только с главной пропускает своё
движение внутренних страниц: у shapefest страница товара дала закреплённую карточку покупки у
галереи (10 350 px прокрутки), появление заголовков разделов и цвет меню при наведении — на
главной этого не видно. `motion-decisions.json` один на прогон: ключи — «вид:подпись»
(`pinned:div.framer-16y10g9`), не номера m01: у разных страниц они совпадают, а при пересъёмке донора сдвигаются
(сверка это заметит — помнит отпечаток строки в `motion-decisions.prints.json` — и решение по номеру к другому движению
не применит, но переносить его придётся руками). У desktop и mobile номера тоже свои —
ключ с экраном: `reveal:div.card:desktop`, `m07:mobile`; ключ без экрана действует на оба. Оба экрана — одним запуском:
`motion.mjs compare motion/donor-home.json <адрес> --viewport desktop,mobile`. Тот же приём, записанный у нас другим
видом (у донора «привязано к прокрутке», у нас «параллакс» или «появление»; бегущая строка Tilda; кнопка, записанная
у донора «ссылкой»), сверка находит сама — статус «ЕСТЬ, ДРУГИМ ВИДОМ» с числами обоих, если место на странице то же;
решением закрывать только то, чего у нас нет или что сделано иначе
(условия пары и статусы — `reference/motion.md`, «Сверка с донором»).
Стопка одинаковых петель — одна строка ×N; решение на неё — `loop:<родитель> > *`, одно на всю стопку
(`loop:div.framer-Nsiv9.framer-x6zctv > *`): поштучные решения ломаются, когда очередной замер находит
другую картинку. Голый `loop:<родитель>` — про сам качающийся контейнер, детей он не закрывает. Окно
«время» на таком доноре само продлевается до 12–20 с — это не зависание.

**Своё и банк идей — сверху донора.** 1–2 движения из самого товара (у VN3D — фигурка печатается
слоями в такт печатающемуся слову) и 1–2 свежие идеи из банка: `ideas.mjs pick --run <папка>
--kind motion --for "<о чём сайт>"` (не было на последних сайтах, пользователь не отверг); взятую —
`ideas.mjs use`. Рецепты — `reference/motion.md`.

Фактура в вёрстку — блок `--grain-*`, а не `--texture-*` из
`donor.tokens.css` (это сырой CSS слоя донора, справочно). С `--no-design`
discover блок не дописывает — его пишет `texture.mjs
<папка>/donor/texture/texture.json --tokens <файл токенов сайта> --css
<папка>/site/grain.css` (`reference/engines.md` → «Фактура»).

Старую разведку донора из прошлого прогона — перезапустить: скрипты
меняются. Медленный TLS (Tilda): скрипты сами повторяют переход; гонять
по одному скрипту за раз.

Донор на Tilda: после команд §1 — `tilda.mjs <донор> --viewport desktop,mobile --out <папка>/donor` и
`tilda.mjs pages <донор> --out <папка>/donor` (строку `--pages` из вывода — в discover и motion), дальше —
`reference/donor-tilda.md`. Что Tilda выключает на телефоне (поле `plays`), на телефоне не повторяем.
discover, motion и cliche узнают Tilda сами: discover пишет раздел «Tilda» и типы страниц по подписи блоков,
motion ставит пункты «атрибуты Tilda» вместо замеров (в строке — «замер совпал / назвал иначе»), cliche не
считает служебное. tilda.mjs нужен для полной карты (`tilda/*.md`, `tilda-layout.json`) и сверки.

Токены донора проверить на бессмыслицу до того, как на них опираться:
акцент подтверждён пикселями или «акцента нет» (акцент — цвет действий: заливка кнопок первого экрана,
в том числе вложенного блока внутри `<a>`, как у Framer; нет залитых кнопок — цвет ссылок при
наведении; фоны секций, шапки и подвала — оформление, не акцент; так считают extract, cliche и discover); приглушённый — «не
выявлено», если контраста нет; размер `0px`; шрифт, который не грузится.
Исправленное — записать.

## 2. Паспорт донора — в `analysis.md`, раздел «Донор»

- **Приёмы-подписи** (3–5): то, по чему донора узнают с одного экрана, —
  с кропами и числами из «Подписных приёмов» разведки.
- **Фактура** — из раздела разведки «Фактура»: чем сделана, какой силы
  (σ по фонам), кипит ли, на каких экранах.
- **Словарь примитивов**: радиусы, толщины линий, пары гарнитур, регистр и
  разрядка по ролям, стили кнопок — только то, что есть в «Паспорте донора».
- **Чего донор не делает никогда** — числами оттуда же.
- **Чего у донора нет, а сайту нужно**: форма, FAQ, шаги, каталог,
  корзина, отзывы. Для каждого — решение по `reference/authorship.md`
  (из какого примитива донора собрано, какая деталь своя, чего избегаем).

## 3. Граница заимствования

Берём: палитру, пары гарнитур, шкалу, ритм, форму примитивов, фактуру,
характер движения, приёмы подачи. Не берём: тексты, фото, иллюстрации,
логотипы, названия, **файлы** донора — в том числе его `noise.gif`: зерно
делается своей плиткой того же характера (`grain-tile.mjs`). Точная копия
страницы — нет; язык — да. В режиме донора заимствование языка и есть
задача, а граница проходит по материалам.

## 4. Своё

Идея сайта, привязанная к его товару (`reference/authorship.md`),
содержание, кадры (`media.mjs` — законные бесплатные источники), компоненты,
которых у донора нет.

## 5. Сверка с донором — обязательна перед отчётом

```
node ~/.claude/skills/design-reference/scripts/verify.mjs <папка>/donor/design/donor.json <адрес сайта>
node ~/.claude/skills/site-rework/scripts/texture.mjs compare <папка>/donor/texture/texture.json <адрес сайта> --viewport desktop,mobile --out <папка>/texture-compare
node ~/.claude/skills/site-rework/scripts/bgdecor.mjs compare <папка>/decor/donor.json <адрес сайта> --out <папка>   # фон: что из рисунков, предметов и букв донора у нас потерялось
node ~/.claude/skills/site-rework/scripts/cliche.mjs <адрес сайта> --baseline <папка>/cliche/donor.json --taste --run <папка> --shot
node ~/.claude/skills/site-rework/scripts/motion.mjs compare <папка>/motion/donor-home.json <адрес сайта> <папка>/motion/donor-<тип>.json <наша страница этого типа> --out <папка>   # пары подряд: compare-home, compare-<тип>
```

`verify.mjs` сверяет с одной спецификацией: внутреннюю страницу — со спецификацией страницы того
же типа у донора (`extract.mjs <страница донора> --name donor-<тип>`), а не главной: у товара свой
заголовок (shapefest: h1 главной 60 px, у карточки товара — меньше), иначе расхождения ложные.

- `verify.mjs` — шкала, цвета, акцент («у образца акцента нет» — тоже
  правило), радиусы, паспорт (`??` — компонент, которого у донора нет:
  решение записано?), слой фактуры и его режим. Сознательные отступления —
  в `donor.ignore`.
- `texture.mjs compare` — сила зерна по полосам фона ±20 %, lag1 ±0.15,
  кипит / не кипит, только при одинаковом DPR; крупная фактура — есть / нет,
  вид плитки (у донора камень, у нас бумага — подсказка, не FAIL: решают
  вырезки 1:1 рядом), сила на ровных участках по полосам ±30 %, наложение.
  FAIL — задача, а не примечание. Подсказка назовёт причину: режим гасит на этом фоне или
  слой слишком слабый. Фактура по слову владельца там, где у донора её нет
  (или наоборот), — FAIL остаётся в протоколе, в отчёт — строкой с его словами.
- `bgdecor.mjs compare` — вид украшения фона, который у донора есть, а у нас
  нет (НЕТ) или заметно реже (РЕЖЕ); без записи в `<папка>/decor-decisions.json`
  — WARN. «У нас чаще» — проверить глазами, что не перебор. Вырезку находки
  донора открыть до решения: размытое пятно-свечение скрипт называет рисунком.
- Протокол сверки с ошибкой («страница не снялась», сверено 0) сверкой не
  считается — `state.mjs show` пишет его строкой «не в счёт»: перепрогнать.
- `cliche.mjs` — приёмы, которых нет у донора, «размножено», запреты из
  журнала вкуса; вердикт по порогам из `reference/authorship.md`, обоснования —
  в `<папка>/authorship-decisions.json`.
- `motion.mjs compare` — каждое движение донора с парой у нас или с решением в
  `motion-decisions.json`; FAIL — пропуск без решения, WARN — числа другие, пара без сверки места или решение по
  номеру, под которым теперь другое движение; «ЕСТЬ, ДРУГИМ ВИДОМ» — тот же приём, записанный другим видом (вердикт не
  портит); «своё» — сверить с планом. Оба экрана — `--viewport desktop,mobile`, ключи решений с экраном, лучше по виду
  и подписи (`reveal:div.card:mobile`).
- Пары снимков донор/результат на одном экране, по одной на каждый
  приём-подпись: открыть обе глазами рядом (не `diff.mjs` — пиксельная
  разница здесь бессмысленна).
- Каждая строка «сохранить» из матрицы — отдельная проверка со ссылкой на
  пару снимков или число. «Сохранить зерно» без `texture.mjs compare` не
  закрывается.

## 6. Отчёт

Раздел «Что взято у донора, что своё, что отличается сознательно» —
таблица по приёмам-подписям с отметкой «сверено: снимок / число», плюс
итог `verify.mjs`, `texture.mjs compare`, `bgdecor.mjs compare`, `cliche.mjs` и `motion.mjs compare` (движение
донора: взято / решено иначе / своё). После сдачи — удачное своё в банк идей (`ideas.mjs add`), реакцию пользователя —
`ideas.mjs status <id> liked|rejected --quote "<его слова>"`.
