# Авторство: как не собирать сайт из дефолтов

Модель по умолчанию выдаёт среднее: то, что чаще всего встречалось в
обучающих данных и в учебниках. Поэтому «правильные» советы превращаются в
шаблон: учебники советуют мелкие подписи капсом над полями — и теперь они
стоят в каждой форме. Шаблон появляется не в тех блоках, которые взяты у
донора, а в тех, **которых у донора нет**: форма, вопросы, шаги, подвал,
сообщения. Там модели не на что опереться, и она достаёт своё.

Прогон «ХОЛСТ» (донор streetwearbrands.ru) показал это числами. Против
базы донора `cliche.mjs` дал индекс 42: форма-набор 5 из 5 признаков,
шаги 01/02/03, FAQ с плюсом в кружке, двоеточие в заголовках ×8, зебра
секций, одинаковые появления, жёлтый акцент, которого у донора нет
(у донора жёлтый был цветом слоя зерна с прозрачностью 7%). Пользователь
про форму написал: «убрать такие шаблонные темы как на первом фото которые
ты везде пихаешь, нужен авторский подход» — это первая запись журнала вкуса.

Этот файл обязателен на этапах 1 (паспорт донора), 2 (решения по блокам) и
4 (проверка). Правило одно: **каждое визуальное решение ссылается либо на
правило донора, либо на задачу блока. «Так обычно делают» — не причина.**

## 1. Каталог дефолтов

Приём сам по себе не плох. Он читается как шаблон, когда стоит без причины,
повторяется по всей странице или взят не из языка сайта. Id совпадают с
`scripts/cliche.mjs` (`node ~/.claude/skills/site-rework/scripts/cliche.mjs rules` печатает каталог).
Вес: 3 — сильный признак, 2 — средний, 1 — слабый.

Как сравнивается с донором: **декоративные** приёмы (надзаголовок,
двоеточие, бегущая строка, мелкий капс, мелкий текст, градиентный текст,
курсив-акцент) — частотой на 10 000 px высоты: «размножено ×N», если штук
больше, чем у донора, и частота выше вдвое. **Функциональные** (пилюли,
одно скругление) — долей внутри своего класса: пилюли у сайта 98% кнопок, у
донора 100% — это «есть у донора». Остальные — есть у донора или нет.

Не ловится скриптом, смотреть глазами: заголовок-обещание без предмета
(«Искусство, которое вдохновляет»), подзаголовок из трёх фактов через
запятую, «Спасибо!» с восклицанием, иконка-эмодзи, случайная иллюстрация
вместо фото товара, раскладка «текст слева — картинка справа» во всех
секциях по очереди, двоеточие не перед списком.

**Длинное тире в русском тексте — не признак**: это норма пунктуации.

## 2. Паспорт донора — этап 1

До любого макета записать в `analysis.md` прогона раздел «Паспорт донора»:
8–12 правил «как донор делает X» и 5 правил «чего донор не делает никогда».
Каждое — с кропом снимка и числом из разведки (раздел «Паспорт донора: есть
/ нет» в `discovery.md`), не «на глаз».

Правила «как» — по восьми вопросам: как у донора лежит **текст на фоне**,
какая **линия**, какая **кнопка**, как стоит **фото**, как устроен
**заголовок**, как он обращается с **пустотой**, как **движется**, какая
**фактура**. Пример для streetwearbrands.ru:

| вопрос | правило донора | доказательство |
|---|---|---|
| текст на фоне | жирный гротеск капсом узкой колонкой (~280 px) на пустом чёрном поле | `discover/desktop-scroll-02.png` |
| линия | толстая: рамка 4 px, радиус ~30, без заливки, вокруг абзаца | `discover/desktop-scroll-01.png` |
| кнопка | большая контурная пилюля 292×60, жирный капс 20 px, **без разрядки** | паспорт: кнопки капсом 21 из 21, letter-spacing 0 |
| фото | в край карточки r30, название антиквой капсом прямо на фото | медиа-слоты: фото 4:5 cover, без плёнок |
| заголовок | антиква капсом 70 px; двоеточие — только перед списком (1 раз) | `discover/desktop-scroll-05.png` |
| пустота | половина экрана пустая, текст прижат к краю | лист прокрутки |
| движение | при прокрутке появляется один блок сверху (−100 px); подписи «О БРЕНДЕ» — при наведении на фото | разведка: «появляются при прокрутке 1», «58 × появляется при наведении» |
| фактура | зерно везде, и на чёрном: σ ≈ 5 на плоском поле, 4 кадра по 100 мс, только ≥1200 px | `texture.mjs`: σ 5.04 / 5.05 |

Правила «никогда» (у донора ноль — значит, у нас ноль без причины):
разрядка у кнопок и навигации (0 из 21 и 0 из 5); скругления 8–12 px (0);
форм и полей (0); цветной акцент (жёлтого на экране 0% — это не акцент);
спрятанное содержимое (аккордеонов и вкладок нет).

Приём донора переносится **на то же место и в той же роли**: у
streetwearbrands бегущая строка стоит на стыке цветной секции и каталога,
внутри — имя бренда; у нас та же строка со слоганами между любыми блоками —
это уже `marquee` из каталога, хоть `cliche.mjs` и пометит её «есть у
донора». Место и смысл детектор не видит — их сверяет пара снимков
донор/результат (`reference/donor-mode.md` §5).

Цвет, шрифт или приём попадает в паспорт, только если он **виден на
снимке**: для цвета — доля пикселей ≥0.2% (`extract.mjs` проверяет сам);
слои с малой прозрачностью и полноэкранные `pointer-events: none` — это
фактура, не палитра.

## 3. Решение по каждому ключевому блоку — этап 2

Ключевые блоки: первый экран, главный список (каталог, услуги), форма,
всё, чего у донора нет. Для каждого — запись в `<папка>/authorship.md` по
пяти шагам. Без этой записи задача блока не переходит в `impl`.

1. **Три необычные черты донора**, которые можно применить к блоку.
   Необычные — то, чего нет в каталоге дефолтов; «пилюли» и «чёрный фон»
   не считаются.
2. **Три кандидата из разных направлений**: (а) буквальный перенос правила
   донора на этот блок; (б) предмет отрасли — как это выглядит в реальном
   мире заказчика (для картин: музейная этикетка, паспарту, аукционный
   лист); (в) задача блока — что человек здесь делает и как сделать это
   короче.
3. **Отсев**: кандидат, совпавший с каталогом (§1) или с запретом в журнале
   вкуса (§6), вычёркивается, если не опирается на правило донора. Причину
   — одной строкой.
4. **Эскиз двух выживших**: быстрый HTML в `<папка>/sketch/<блок>-a.html`,
   снимок desktop и mobile, `Read` рядом с кропом донора. Выбор — «похоже
   на донора, не похоже на шаблон», одной строкой почему.
5. **Проверка**: `node ~/.claude/skills/site-rework/scripts/cliche.mjs
   file:///<папка>/sketch/<блок>-a.html --baseline <папка>/cliche/donor.json
   --run <папка> --json <папка>/cliche/sketch-<блок>.json` (путь без `file:///`
   не принимается; свой `--json`, чтобы не затереть итог страницы
   `cliche/cliche.json`) — блок не добавляет ни
   одного правила веса 3 «НЕТ У ДОНОРА»; если добавил — обоснование в
   `authorship-decisions.json` или переделка. Шаблонность — не всё: у формы
   ещё `a11y.mjs`, обход с клавиатуры и снимок на 390 px (§4).

### Пример: форма заявки «ХОЛСТа»

Было: «ИМЯ / ТЕЛЕФОН / РАБОТА / КОММЕНТАРИЙ» 11 px капсом с разрядкой
0.14em, поля #0E0E0E r10 с рамкой, жёлтая пилюля «ОТПРАВИТЬ ЗАЯВКУ», «не
обязательно» мелко. `cliche.mjs`: form-kit 5 из 5, «НЕТ У ДОНОРА»,
«ЗАПРЕЩЁН пользователем». Ни одна черта формы не взята у донора.

- **Черты донора**: рамка 4 px r30 вокруг абзаца; жирный капс узкой
  колонкой на пустоте; фото с названием антиквой прямо на нём; чёрная
  лента во всю ширину.
- **Кандидаты**: (а) форма внутри рамки донора, поля — подчёркнутые пропуски
  в тексте; (б) этикетка у картины: выбранная работа рядом, поля как строки
  этикетки; (в) одно поле телефона и кнопка «Пришлите видео».
- **Отсев**: «одно поле в тёмной коробке с жёлтой пилюлей» вычеркнут —
  form-kit и accent-added; само «одно поле» вошло в (б).
- **Эскизы** (прототип `proto/form.html` в материалах аудита): «Записка в
  рамке» — форма как предложение жирным гротеском, поля — подчёркивание
  4 px, отправка — контурная пилюля донора без разрядки; «Этикетка у
  работы» — выбранная картина в карточке донора, строки «ИМЯ ____ /
  ТЕЛЕФОН ____» антиквой донора.
- **Проверка**: `cliche.mjs file:///<путь>/proto/form.html --baseline
  <папка>/cliche/donor.json --json <папка>/cliche/sketch-form.json` → индекс 0,
  OK на desktop и mobile.
- **Чего шаблонность не видит** — прототип не эталон целиком. «Записка»
  сделана верно в главном: у каждого поля во фразе скрытая подпись, выбор
  работы остался внутри фразы, в полях фразы — подсказка формата, а не
  выдуманное значение (у поля P.S. placeholder — готовая фраза «хочу
  посмотреть вживую в субботу», её заменить подсказкой). Но на 390 px каждое
  поле встаёт отдельной строкой, а запятая и точка отрываются от него. У «Этикетки» кнопка-лента без `aria-label`: её
  имя для читалки — «Хочу эту работу •» шесть раз подряд; лента на телефоне
  обрезана и едет только по `:hover`. Нужно: `aria-label="Отправить заявку"`,
  текст ленты `aria-hidden`, на телефоне одна фраза без обреза.

## 4. Компоненты, которых у донора нет

Выводить из правил паспорта, а не из памяти:

| компонент | из каких правил донора собирается | чего не делать |
|---|---|---|
| форма | линия донора (рамка, подчёркивание его толщины), его кнопка, его текст на фоне; форма-фраза — только с подписью у каждого поля (`label`, можно скрытый, или `aria-label`), без выдуманного значения в placeholder (подсказка формата или вне поля), выбор (работа, услуга) — внутри фразы; проверка: `a11y.mjs`, обход с клавиатуры, снимок на 390 px | коробки полей r10, капс-подписи с разрядкой, «не обязательно» мелко; поля без подписи ради чистой фразы |
| закреплённое меню, панель | стекло и цвет донора | текст, который читается только над одним фоном: над каждым фоном, который проезжает под меню, — подложка или смена цвета текста; `a11y.mjs` мерит его и на прокрутке (строка «контраст закреплённого текста на прокрутке»), а при WARN «смотреть глазами» — `scroll-NN` глазами |
| вопросы и ответы | как донор ставит текст на фоне: вопрос жирным, ответ сразу под ним, открыто (донор ничего не прячет) | аккордеон с плюсом, если у донора нет раскрытий |
| шаги | как донор пишет списки (у streetwearbrands — «- пункт» дефисом в тексте) | 01/02/03 в три одинаковые колонки |
| подвал | как донор заканчивает страницу | четыре колонки с капс-заголовками и гигантское слово |
| сообщение, ошибка | цвет и линия донора; ошибка — словами рядом с полем | всплывающая плашка r14 с тенью |
| фокус | инверсия или толщина линии донора | цвет акцента, которого у донора нет |
| появление, наведение | язык движения донора (у streetwearbrands едет один блок; наведение — надпись на фото) | сдвиг 16–24 px у каждого блока, подъём карточки на 4 px с тенью |

## 5. Проверка — этапы 1 и 4

```
node ~/.claude/skills/site-rework/scripts/cliche.mjs baseline <донор или сайт «до»> --out <папка>/cliche/donor.json   # desktop и mobile сразу
node ~/.claude/skills/site-rework/scripts/cliche.mjs <наш url> --baseline <папка>/cliche/donor.json --taste --run <папка> --shot
node ~/.claude/skills/site-rework/scripts/cliche.mjs rules                                                           # каталог
```

| флаг | что делает |
|---|---|
| `--baseline <json>` | база донора или сайта «до»; экраны по умолчанию — из базы |
| `--taste [папка]` | журнал вкуса (по умолчанию `~/.claude/site-rework/taste`) |
| `--viewport <список>` | экраны; без базы — desktop |
| `--run <папка>` | папка прогона: туда `cliche/cliche.json` и снимки, оттуда `authorship-decisions.json` |
| `--decisions <json>` | свой файл обоснований |
| `--shot` | снимок с рамками вокруг тяжёлых и запрещённых приёмов |
| `--json <файл>` или `-` | итог в файл или JSON в stdout |

Вывод: правило, число, доля страницы, селекторы, пометка «есть у донора /
НЕТ У ДОНОРА / размножено ×N / ЗАПРЕЩЁН пользователем / ВОПРОС
пользователю». Вердикт экрана:

- **FAIL** — есть ЗАПРЕЩЁН; правило веса 3 «НЕТ У ДОНОРА» без записи в
  `authorship-decisions.json`; «размножено» больше ×2 у правила веса 2–3
  (обоснование не снимает — снижать частоту);
- **WARN** — «НЕТ У ДОНОРА» веса 1–2 без записи; «размножено» у веса 1;
  ВОПРОС пользователю; нет базы; база снята на другом экране;
- **OK** — остальное.

Код выхода: 0 — OK или WARN, 1 — FAIL, 2 — аргументы, 3 — страница не
открылась. Обоснования — `<папка прогона>/authorship-decisions.json`:
`{ "правило": { "блок": "почему" } }` или `[{ "rule", "block", "why" }]`,
«почему» не короче 8 знаков. Снимает только «НЕТ У ДОНОРА»; запрет снимает
только пользователь.

Индекс сам по себе ничего не значит: донор без базы — 16 (desktop) и 12
(mobile), bureau.ru 6, linear.app 13, «ХОЛСТ» против базы донора 42. Важна
разница с донором и список. Без донора (переработка своего сайта) базой
служит снимок сайта «до»: правило, которого не было, — новое, и ему нужна
причина.

Детектор не видит смысла: подпись капсом у донора и у нас выглядят
одинаково, поэтому решает сравнение с донором, а не сам признак. Роль
двоеточия («только перед списком») не проверяется — смотреть текст
заголовков в выводе.

## 6. Опыт: журнал вкуса

«Опыт» у человека — память о том, что сработало и что отвергли, с
картинкой перед глазами. Между прогонами у скилла такой памяти нет. Журнал
вкуса это заменяет:

```
~/.claude/site-rework/taste/
  README.md       как вести (пишет add, если его нет; свой не перезаписывается)
  journal.jsonl   дата, прогон, донор, блок, вердикт, кто решил, правила, цитата, причина, картинка
  img/            кропы: что отвергли и что приняли (появляется с первым --img)
```

```
node ~/.claude/skills/site-rework/scripts/taste.mjs brief --blocks form,hero,faq          # в начале прогона
node ~/.claude/skills/site-rework/scripts/taste.mjs add --block form --verdict rejected --by user --rule form-kit \
     --quote "<слова пользователя дословно>" --why "<о чём это>" --img <кроп.png> --run <прогон> --donor <url>
node ~/.claude/skills/site-rework/scripts/taste.mjs bans                                   # действующие запреты
node ~/.claude/skills/site-rework/scripts/taste.mjs bans --baseline <папка>/cliche/donor.json   # что из запретов спорит с новым донором
node ~/.claude/skills/site-rework/scripts/taste.mjs check                                    # целостность журнала: битые строки, by user без цитаты, нет картинки
```

- **Кто решил.** `--by user` принимается только с `--quote` — дословными
  словами пользователя; пересказ — не запрет. Свой отсев на шаге 3 —
  `--by self`: он записывается, но запретом не бывает.
- **Когда писать**: пользователь сказал «шаблонно», «не то», «нравится» или
  выбрал вариант — запись сразу, в том же ходе, с кропом.
- **Когда читать**: этап 0 — `taste.mjs brief --blocks <блоки плана>`,
  открыть `Read` картинки отвергнутого и принятого. Запреты — в матрицу
  «не делать» `analysis.md`.
- **Как влияет** (`cliche.mjs --taste`): запрет на приём, которого у донора
  нет, — ЗАПРЕЩЁН (FAIL, вес в индексе удваивается). Запрет на приём,
  который у **нового** донора есть, — ВОПРОС пользователю (WARN): спросить,
  а ответ записать `taste.mjs add --block <блок> --rule <id правила> --by
  user --verdict accepted --donor <url> --quote "<слова пользователя
  дословно>" --why "<о чём это>"` (снимает запрет по этому правилу только
  для этого донора) или то же с `--verdict rejected`.
- **Эталоны**: принятое пользователем — первый кандидат на шаге 2 для
  такого же блока в следующем прогоне, если не спорит с паспортом нового
  донора.

Сейчас в журнале одна запись пользователя: form-kit — форма заявки
«ХОЛСТа» с кропом. Расширять запрет на соседние приёмы (мелкий капс,
акцент) — только после вопроса пользователю.

Что журнал не даёт: вкус не появится из него сам. Настоящий сигнал — слова
пользователя после показа снимка, поэтому эскиз двух вариантов (шаг 4)
показывать до сборки всей страницы, а не после.
