# Реестр инструментов

Ревизия при запуске — обязательный первый шаг: состав меняется от машины к
машине и от сессии к сессии (MCP-серверы подключаются, кредиты кончаются).
Результат записать в `<папка прогона>/tools.md` — коротко: есть / нет / чем заменено.

## Чек-лист ревизии

1. Скрипты: `node -e "import('puppeteer-core')"` из папки проекта; путь к
   браузеру — `lib.mjs` найдёт сам (`CHROME_PATH` для своего).
2. Браузерные MCP: `ToolSearch "select:mcp__chrome-devtools__new_page"` и
   `"select:mcp__playwright__browser_navigate"` — если схема пришла, сервер жив.
3. Скиллы рядом: `~/.claude/skills/design-reference` (снятие дизайн-системы),
   проектные скиллы вроде `predrelease` (проверки перед коммитом в конкретном репозитории).
4. Картинки и 3D: Higgsfield — `balance` (кредиты); Figma — `whoami`.
   Серверы, которым нужна авторизация, в сессии не включить — записать как недоступные.
5. Документация: Context7 (`resolve-library-id` → `query-docs`) для Three.js, GSAP, Swiper и прочих.
6. Ограничения среды: ОС, оболочка, лимиты сервера (например, 5 запросов в минуту с адреса).

## Браузер и runtime

| инструмент | назначение | вход → выход | ограничения | когда | когда не надо |
|---|---|---|---|---|---|
| `scripts/discover.mjs` | разведка целиком: техника, содержимое, визуал, снимки на 3–4 экранах, дизайн-система | url → `discovery.md/json`, `before/*.png`, `design/site.tokens.css` | нужен puppeteer-core рядом; страницы за логином не снимает | всегда первым шагом | повторно на каждую мелкую правку — для этого `runtime.mjs` и `shots.mjs` |
| `scripts/runtime.mjs` | проверка в браузере: консоль, холсты (по снимкам с холстом и без, плюс буфер в пяти зонах), анимации, наведение, клик, ввод, прокрутка, «меньше движения»; `--init` ставит код до скриптов страницы | url + шаги → протокол OK/WARN/FAIL, `runtime/*.json`, снимки | шаги идут по порядку; берётся первое видимое совпадение селектора; ленивому 3D даётся до 4 с | после каждой правки, зависящей от JS/CSS-движения; базовая линия при разведке; поиск виновника сдвигов вёрстки | для чисто текстовых правок достаточно снимка |
| `scripts/shots.mjs` + `diff.mjs` | снимки «до/после» и где изменилась картинка; при смене высоты страницы — сравнение со сдвигом (съехало или изменилось) | url, tag → `before/`, `after/`, `diff/` | diff нужен sharp; говорит «где», не «лучше ли» | до первой правки и после последней; при регрессе — «изменилось только там, где планировали?» | как замена взгляда: картинку diff всё равно открыть |
| `scripts/perf.mjs` | скорость с бюджетами: LCP, FCP, CLS, вес по типам, кадры/с, память; `--runs 3` — медиана и разброс | url → таблица + `perf/*.json` | один прогон ±20% — для решения «хуже или нет» брать `--runs 3`; headless без реального GPU-профиля телефона | база при разведке; после картинок, шрифтов, 3D, анимаций | не заменяет Lighthouse для SEO/best-practices |
| `scripts/a11y.mjs` | контраст (по вычисленным цветам, а на картинках и градиентах — по снимку фона за текстом), alt, подписи, имена кнопок, фокус, цели нажатия, reduced-motion | url → протокол + `a11y/*.json` | не читает экраном, не проверяет ARIA-семантику глубоко; оценка по снимку — до 24 элементов | база и финал; после правок цветов, форм, меню | — |
| `scripts/mirror.mjs` + `serve.mjs` | верстак для чужого сайта: зеркало с `rework.css/js`; `serve.mjs --proxy <оригинал>` отдаёт API и формы оригиналу | url → `mirror/` | страницы за логином не снимаются; скрипты оригинала могут ломаться (`--no-scripts`); «до» снимать с нетронутого зеркала | исходников нет, а показать переработку надо | когда исходники есть — править их |
| chrome-devtools MCP | живой браузер из чата: `new_page`, `navigate_page`, `resize_page`, `emulate`, `click`, `hover`, `fill`, `press_key`, `drag`, `evaluate_script`, `take_screenshot`, `take_snapshot`, `list_console_messages`, `list_network_requests`, `performance_start_trace/stop_trace/analyze_insight`, `lighthouse_audit` | — | headless, изолированный профиль; экран по умолчанию нестандартный — задавать `resize_page`; на этой машине WebGL работает (ANGLE D3D11) | ручное исследование сложного поведения: пошаговое взаимодействие, трассировка производительности, Lighthouse (доступность, SEO, best practices) | массовые снимки и повторяемые проверки — это скрипты |
| playwright MCP | то же, плюс `browser_snapshot` — дерево доступности с координатами (`boxes: true`), `browser_emulate_media`, `browser_run_code_unsafe` | — | отдельный браузер, свои страницы | когда нужно дерево доступности или Playwright-семантика ролей; запасной браузер | одновременно с chrome-devtools на одной задаче — путаница в состоянии |
| `Read` на PNG | «открыть глазами» — единственный способ визуальной проверки | путь к снимку → картинка в контексте | большие full-page снимки читать по частям (сначала first, потом full) | всегда после снимка | — |

## Дизайн и анализ

| инструмент | назначение | когда |
|---|---|---|
| скилл `design-reference` (`extract.mjs`, `verify.mjs`, `cyrillic-check.mjs`) | дизайн-система с живой страницы в переменные CSS и спецификацию; численная сверка своей страницы со спецификацией; проверка кириллицы у шрифта | референсы; свой сайт как база; любая смена гарнитуры (кириллица!) |
| скилл `frontend-design` | направление, чтобы результат не выглядел шаблонно | перед крупной визуальной переработкой |
| скилл `design:design-critique` | структурированная критика снимка: иерархия, удобство, консистентность | самопроверка после первого круга правок |
| скилл `design:accessibility-review`, `design:ux-copy` | аудит по WCAG; формулировки кнопок, ошибок, пустых состояний | доступность; тексты интерфейса |
| Figma MCP (`get_design_context`, `get_screenshot`, `use_figma`, генерация дизайна) | читать макеты пользователя; выкладывать результат в Figma | только если у пользователя есть Figma-ссылка или он просит макет |
| Context7 | актуальная документация библиотек | Three.js, GSAP, Swiper, Lenis — не писать API по памяти |
| `WebSearch`, `WebFetch` | факты о платформе сайта, о конкурентах, о шрифтах | когда чего-то нет в DOM и в документации |
| `Agent` (Explore / Plan / general-purpose) | параллельная разведка исходников, план по большому репозиторию | большой проект; несколько референсов сразу |

## Код

`Read`, `Edit`, `Write`, `Glob`, `Grep`, `Bash`/`PowerShell`, `git`. Большие
файлы писать `Write`, не heredoc через Bash: на Windows длинная команда не
проходит в аргумент. Коммит и пуш — только по просьбе; в репозиториях с
проектным скиллом проверок (`predrelease`) — сначала он.

## Картинки

Порядок всегда один: **переиспользовать существующее → отредактировать →
сгенерировать**. Каждый новый кадр открыть глазами: стоковые фотографии
регулярно противоречат подписям (чужие телефоны, доллары в ценнике,
не та кухня).

| инструмент | назначение | цена / ограничения |
|---|---|---|
| Higgsfield MCP: `generate_image` (`gpt_image_2_5` по умолчанию, `marketing_studio_image` для товарного), `upscale_image`, `remove_background`, `outpaint_image`, `reframe` | новые кадры, обтравка, увеличение, дорисовка полей под нужную пропорцию | кредиты со счёта пользователя: сначала `balance`, потом `get_cost:true`, тратить только с согласия; при 0 кредитов — недоступно |
| SVG и CSS-графика (градиенты, зерно, узоры, иллюстративные формы) | фоны, разделители, иконки, декор в цветах дизайн-системы | бесплатно, легко, всегда в стиле; образец — `tools/gen-art.mjs` в студийном репозитории |
| фото по свободной лицензии (Openverse: CC0, PDM, BY, BY-SA) | реальные кадры, когда генерация недоступна | атрибуция для BY; обязательно смотреть глазами; образец — `tools/fetch-openverse.mjs` |
| `sharp` | пережать в WebP/AVIF, нарезать под srcset, обрезать | из проекта |
| скиллы `canvas-design`, `algorithmic-art` | постер, генеративный фон на p5.js | когда нужен характер, а не фото |

Требования к любому кадру: пропорция под место (не растягивать), цвета из
палитры сайта, место под текст, если он поверх, вес под бюджет `perf.mjs`.

## 3D и WebGL

| подход | когда | проверка |
|---|---|---|
| Three.js с CDN (`cdnjs`, `jsdelivr`), процедурная геометрия, частицы, шейдер | по умолчанию: абстракция бренда, фон первого экрана, интерактивный объект | `runtime.mjs --canvas` (буфер не пуст, кадр меняется, кадры/с), снимок глазами, `perf.mjs` на телефоне, `--viewport mobile` |
| готовая модель GLB/GLTF пользователя | показать продукт | то же + вес модели в бюджете |
| Higgsfield `generate_3d` (`image_to_3d`, `multi_image_to_3d`, `sam_3_3d`), `scene_builder_3d_*` | модель из фото товара, когда своей нет | кредиты; согласие пользователя |

3D не добавлять там, где оно не улучшает историю, бренд, подачу продукта
или иерархию. Всегда: ленивая инициализация по видимости, `devicePixelRatio`
не выше 2, остановка вне экрана, постер-запас без WebGL, отключение при
`prefers-reduced-motion`.

## Движение

CSS-переходы и ключевые кадры → Web Animations API → GSAP (с CDN) только
для последовательностей и привязки к прокрутке, которые CSS не тянет →
Lottie только с готовыми файлами. Проверка: `runtime.mjs --motion --scroll --hover`,
снимки в фазах, `perf.mjs` (кадры/с при прокрутке).

## Проверки и тесты

Скрипты этого скилла; `lighthouse_audit` из chrome-devtools (доступность, SEO,
best practices — не скорость); `performance_start_trace` там же — когда
`perf.mjs` показал проблему и нужно найти виновника; проектные наборы
(`npm test`, `smoke`, `e2e`, `audit`, `mobile`, `controls`, скилл `predrelease`
в студийном репозитории) — перед коммитом в такой проект.

## Недоступно или требует авторизации

Runway, второй сервер «higgsfield AI», коннекторы `design:*` (Asana,
Atlassian, Intercom, Linear, Notion, Slack) — не нужны для переработки
сайта; если понадобятся, пользователь авторизует их в настройках claude.ai.
Gmail и Calendar к задаче отношения не имеют.

## Ограничения среды (эта машина)

- Windows 11, Git Bash и PowerShell; Node 22; `puppeteer-core` и `sharp` только в проектах, глобально нет.
- Edge в безголовом режиме завершается молча — Chrome стоит первым в поиске.
- Higgsfield: бесплатный план, 0.8 кредита — генерация фактически недоступна без пополнения.
- Студийный сервер: 5 запросов в минуту с адреса на API — два прогона проверок подряд дают ложные 429.
