# Реестр инструментов

Ревизия при запуске — обязательный первый шаг: состав меняется от машины к
машине и от сессии к сессии (MCP-серверы подключаются, кредиты кончаются).
Результат записать в `<папка прогона>/tools.md` — коротко: есть / нет / чем заменено.

## Чек-лист ревизии

1. Скрипты: `puppeteer-core`, `sharp`, `ffmpeg-static` ищутся в `SITE_REWORK_PROJECT`, текущей папке и `~/.claude/site-rework/node_modules`; путь к браузеру — `lib.mjs` найдёт сам (`CHROME_PATH` для своего).
2. Браузерные MCP: `ToolSearch "select:mcp__chrome-devtools__new_page"` и
   `"select:mcp__playwright__browser_navigate"` — если схема пришла, сервер жив.
3. Скиллы рядом: `~/.claude/skills/design-reference` (снятие дизайн-системы),
   проектные скиллы вроде `predrelease` (проверки перед коммитом в конкретном репозитории).
4. Картинки и 3D: Higgsfield — `balance` (кредиты); Figma — `whoami`.
   Серверы, которым нужна авторизация, в сессии не включить — записать как недоступные.
5. Документация: Context7 (`resolve-library-id` → `query-docs`) для Three.js, GSAP, Swiper и прочих.
6. Ограничения среды: ОС, оболочка, лимиты сервера (например, 5 запросов в минуту с адреса).

## Браузер и runtime

| инструмент | назначение | вход → выход | ограничения | когда | когда не надо |
|---|---|---|---|---|---|
| `scripts/discover.mjs` | разведка целиком: техника, содержимое, визуал, фактура, паспорт донора «есть / нет», подписные приёмы, медиа-слоты, снимки на 3 экранах + проход 320, дизайн-система | url → `discovery.md/json`, `discover/*.png`, `design/site.tokens.css` | страницы за логином не снимает; медленный TLS — по одному скрипту за раз | всегда первым шагом, по сайту и по донору | повторно на каждую мелкую правку — для этого `runtime.mjs` и `shots.mjs` |
| `scripts/runtime.mjs` | проверка в браузере: консоль, клик с настоящим эффектом, якоря, ввод и правка поля с маской (`--edit`), выбор (`--select`), смена окна (`--resize`), холсты (рисует ли, резкость буфера), наведение всех правил (`--hover-all`), меню (`--nav`), выброшенный CSS (`--css`), видео, анимации, «меньше движения», утверждения (`--assert`, `--expect`); `--init` ставит код до скриптов страницы | url + шаги → протокол OK/WARN/FAIL, `runtime/*.json`, снимки | шаги идут по порядку; берётся первое видимое совпадение селектора (скрытый блок появления сначала прокручивается к экрану); после клика, выбора и смены окна холсты и переполнение перепроверяются сами | после каждой правки, зависящей от JS/CSS; автопроверки состояния перед отчётом (`reference/qa.md`) | для чисто текстовых правок достаточно снимка |
| `scripts/texture.mjs` + `grain-tile.mjs` | фактура числом: слои зерна (фон, img, svg feTurbulence, canvas, video, псевдоэлементы), файл текстуры по кадрам, σ по полосам фона по вкладу слоя, кипение; рецепт и `--grain-*`; `compare` донор против сайта; своя плитка вместо чужого файла | url или texture.json → протокол, `texture.json`, вырезки 1:1, `grain.css` | сравнение только при одинаковом DPR; σ на снимке без слоя могут давать картинки — поэтому решает вклад слоя | у донора с зерном, шумом, плёнкой; после своего слоя — `compare` до OK | сайтам без фактуры не нужен |
| `scripts/shots.mjs` + `diff.mjs` | снимки «до/после»: первый экран до прокрутки и после возврата (FAIL «состояние не сбрасывается»), снимки окна по всей высоте, склейка segments, shots.json с вердиктом и масштабом; diff — где изменилось, масштаб ×2/×1 приводится, при смене высоты — «со сдвигом» | url, tag → `before/`, `after/`, `diff/` | diff нужен sharp; говорит «где», не «лучше ли»; края букв после приведения масштаба расходятся на несколько % | до первой правки и после последней; при регрессе — «изменилось только там, где планировали?» | как замена взгляда: картинку diff всё равно открыть |
| `scripts/perf.mjs` | скорость с бюджетами: LCP, FCP, CLS, вес по типам, кадры/с при честной прокрутке (FAIL замера, если не дошли до низа), картинки мельче показанного, вес видео первого экрана, `--overlay` — цена слоя в покое; `--runs 3` — медиана и разброс | url → таблица + `perf/*.json` | один прогон ±20% — для решения «хуже или нет» брать `--runs 3`; headless без реального GPU-профиля телефона | база при разведке; после картинок, шрифтов, 3D, анимаций | не заменяет Lighthouse для SEO/best-practices |
| `scripts/a11y.mjs` | после полной прокрутки: контраст с прозрачностью элемента и предков и с поправкой на зерно (на картинках — по снимку фона), кегль (<12 WARN, <10 FAIL), alt, подписи, имена кнопок, фокус на свежей странице, цели нажатия, reduced-motion | url → протокол + `a11y/*.json` | не читает экраном, не проверяет ARIA-семантику глубоко; оценка по снимку фона — до 60 элементов, не больше 3 с одной сигнатурой; закреплённый текст — только на верху страницы | база и финал; после правок цветов, форм, меню | — |
| `scripts/mirror.mjs` + `serve.mjs` | верстак для чужого сайта: исходный HTML ответа (скрипты не запускаются дважды) или отрисованный DOM без скриптов (`--no-scripts`), `rework.css/js`, MIRROR.md; `serve.mjs --proxy <origin>` отдаёт API, формы, модули и шрифты оригиналу; Range для видео; только эта машина | url → `mirror/` | страницы за логином не снимаются; смотреть только через `serve --proxy`; «до» снимать с нетронутого зеркала; при повторном снятии правленые файлы уходят в `.bak` | исходников нет, а показать переработку надо | когда исходники есть — править их |
| `scripts/state.mjs` | журнал прогона: режим, папка сайта, этапы, задачи с приоритетами, статусы **только с доказательствами** (`--evidence протокол.json[#шаг]` или `--evidence снимок.png`), NA с причиной | команды init / meta / add / set / stage / show | доказательство отвергается: FAIL (протоколом или шагом), без вердикта, снимок для runtime/perf, старше правки сайта, лежит в папке сайта, desktop для mobile (протокол — по viewport, снимок — по shots.json рядом), протокол целиком, уже подтвердивший другую задачу (с #шагом можно; тот же файл#шаг или снимок — WARN), VERIFIED нескольким задачам одним вызовом; план «чем проверяем» с протоколом не сверяет | весь прогон | — |
| `scripts/cliche.mjs` + `taste.mjs` | шаблонность числами: 39 дефолтов на живой странице против базы донора или сайта «до» и против журнала вкуса пользователя; обоснования — `authorship-decisions.json` | url + база → протокол, `cliche/cliche.json`, снимок с рамками | не видит смысла — решает сравнение с донором; роль двоеточия не проверяет | этап 1 (база), этап 2 (эскизы), этап 4 (финал) | как оценку красоты: это только поиск своего по умолчанию |
| chrome-devtools MCP | живой браузер из чата: `new_page`, `navigate_page`, `resize_page`, `emulate`, `click`, `hover`, `fill`, `press_key`, `drag`, `evaluate_script`, `take_screenshot`, `take_snapshot`, `list_console_messages`, `list_network_requests`, `performance_start_trace/stop_trace/analyze_insight`, `lighthouse_audit` | — | headless, изолированный профиль; экран по умолчанию нестандартный — задавать `resize_page`; на этой машине WebGL работает (ANGLE D3D11) | ручное исследование сложного поведения: пошаговое взаимодействие, трассировка производительности, Lighthouse (доступность, SEO, best practices) | массовые снимки и повторяемые проверки — это скрипты |
| playwright MCP | то же, плюс `browser_snapshot` — дерево доступности с координатами (`boxes: true`), `browser_emulate_media`, `browser_run_code_unsafe` | — | отдельный браузер, свои страницы | когда нужно дерево доступности или Playwright-семантика ролей; запасной браузер | одновременно с chrome-devtools на одной задаче — путаница в состоянии |
| `Read` на PNG | «открыть глазами» — единственный способ визуальной проверки | путь к снимку → картинка в контексте | большие full-page снимки читать по частям (сначала first, потом full) | всегда после снимка | — |

## Дизайн и анализ

| инструмент | назначение | когда |
|---|---|---|
| скилл `design-reference` (`extract.mjs`, `verify.mjs`, `cyrillic-check.mjs`) | дизайн-система с живой страницы в переменные CSS и спецификацию; численная сверка своей страницы со спецификацией; проверка кириллицы у шрифта | референсы; свой сайт как база; любая смена гарнитуры (кириллица!) |
| скилл `frontend-design` | направление, чтобы результат не выглядел шаблонно | перед крупной визуальной переработкой |
| скилл `design:design-critique` | структурированная критика снимка: иерархия, удобство, консистентность | самопроверка после первого круга правок |
| скилл `design:accessibility-review`, `design:ux-copy` | аудит по WCAG; формулировки кнопок, ошибок, пустых состояний | доступность; тексты интерфейса |
| Figma MCP (`get_design_context`, `get_screenshot`, `use_figma`, генерация дизайна) | читать макеты пользователя; выкладывать результат в Figma | только если у пользователя есть Figma-ссылка или он просит макет |
| Context7 | актуальная документация библиотек | Three.js, GSAP, Swiper, Lenis — не писать API по памяти |
| `WebSearch`, `WebFetch` | факты о платформе сайта, о конкурентах, о шрифтах | когда чего-то нет в DOM и в документации |
| `Agent` (Explore / Plan / general-purpose) | параллельная разведка исходников, план по большому репозиторию | большой проект; несколько референсов сразу |

## Код

`Read`, `Edit`, `Write`, `Glob`, `Grep`, `Bash`/`PowerShell`, `git`. Большие
файлы писать `Write`, не heredoc через Bash: на Windows длинная команда не
проходит в аргумент. Коммит и пуш — только по просьбе; в репозиториях с
проектным скиллом проверок (`predrelease`) — сначала он.

## Картинки

Порядок всегда один: **переиспользовать существующее → законные бесплатные
источники (`media.mjs`) → отредактировать → сгенерировать**. Подробно —
`reference/engines.md` → «Картинки и видео». Каждый новый кадр открыть глазами: стоковые фотографии
регулярно противоречат подписям (чужие телефоны, доллары в ценнике,
не та кухня).

| инструмент | назначение | цена / ограничения |
|---|---|---|
| Higgsfield MCP: `generate_image` (`gpt_image_2_5` по умолчанию, `marketing_studio_image` для товарного), `upscale_image`, `remove_background`, `outpaint_image`, `reframe` | новые кадры, обтравка, увеличение, дорисовка полей под нужную пропорцию | кредиты со счёта пользователя: сначала `balance`, потом `get_cost:true`, тратить только с согласия; при 0 кредитов — недоступно |
| SVG и CSS-графика (градиенты, узоры, иллюстративные формы) | разделители, иконки, декор в цветах дизайн-системы | бесплатно; только с причиной в `analysis.md`, для товара «на глаз» фото не заменяет; образец — `D:/ssi/sites/tools/gen-art.mjs` (студийный репозиторий) |
| `scripts/grain-tile.mjs` + `templates/grain.css` | зерно, шум, плёнка: своя плитка и слой по рецепту `texture.mjs` донора | не SVG/CSS «на глаз» и не чужой файл; порядок — `reference/engines.md` → «Фактура» |
| `scripts/media.mjs` (doctor, search, pick, import, credits) | фото и видео из законных бесплатных источников: Unsplash, Pexels, Pixabay (по ключу), Commons, WordPress Photos, Openverse, музеи (Met, Cleveland, Rijks, AIC, SMK; Smithsonian — по ключу SI_API_KEY), Mixkit; лист-контакт, ворота --seen/--caption, обработка без растяжения, видео-петли под бюджет, credits | без ключей — Commons, Mixkit, музеи, Openverse; отбор только глазами по листу; Commons бывает 429 волнами; видео нужен ffmpeg |
| `sharp` | пережать в WebP/AVIF, нарезать под srcset, обрезать | из проекта |
| скиллы `canvas-design`, `algorithmic-art` | постер, генеративный фон на p5.js | когда нужен характер, а не фото |

Требования к любому кадру: пропорция под место (не растягивать), цвета из
палитры сайта, место под текст, если он поверх, вес под бюджет `perf.mjs`.

## 3D и WebGL

| подход | когда | проверка |
|---|---|---|
| Three.js с CDN (`cdnjs`, `jsdelivr`), процедурная геометрия, шейдер | только когда 3D нужно: предмет заказчика или объект из языка донора; по умолчанию 3D нет, частицы «для атмосферы» — дефолт из каталога | `runtime.mjs --canvas` (буфер не пуст, кадр меняется, кадры/с), снимок глазами, `perf.mjs` на телефоне, `--viewport mobile` |
| готовая модель GLB/GLTF пользователя | показать продукт | то же + вес модели в бюджете |
| Higgsfield `generate_3d` (`image_to_3d`, `multi_image_to_3d`, `sam_3_3d`), `scene_builder_3d_*` | модель из фото товара, когда своей нет | кредиты; согласие пользователя |

3D не добавлять там, где оно не улучшает историю, бренд, подачу продукта
или иерархию. Всегда: ленивая инициализация по видимости, `devicePixelRatio`
не выше 2, остановка вне экрана, постер-запас без WebGL, отключение при
`prefers-reduced-motion`.

## Движение

CSS-переходы и ключевые кадры → Web Animations API → GSAP (с CDN) только
для последовательностей и привязки к прокрутке, которые CSS не тянет →
Lottie только с готовыми файлами. Проверка: `runtime.mjs <url> --motion --scroll --hover "<селектор>"`
(все правила :hover разом — `--hover-all`),
снимки в фазах, `perf.mjs` (кадры/с при прокрутке).

## Проверки и тесты

Скрипты этого скилла; `lighthouse_audit` из chrome-devtools (доступность, SEO,
best practices — не скорость); `performance_start_trace` там же — когда
`perf.mjs` показал проблему и нужно найти виновника; проектные наборы
(`npm test`, `smoke`, `e2e`, `audit`, `mobile`, `controls`, скилл `predrelease`
в студийном репозитории) — перед коммитом в такой проект.

## Недоступно или требует авторизации

Runway, второй сервер «higgsfield AI», коннекторы `design:*` (Asana,
Atlassian, Intercom, Linear, Notion, Slack) — не нужны для переработки
сайта; если понадобятся, пользователь авторизует их в настройках claude.ai.
Gmail и Calendar к задаче отношения не имеют.

## Ограничения среды (эта машина)

- Windows 11, Git Bash и PowerShell; Node 22; `puppeteer-core`, `sharp` и `ffmpeg-static` стоят в `~/.claude/site-rework/node_modules` — скрипты запускаются из любой папки.
- Edge в безголовом режиме завершается молча — Chrome стоит первым в поиске.
- Кредиты Higgsfield меняются — смотреть `balance` при каждой ревизии и записывать в `tools.md` прогона, а не сюда.
- Студийный сервер (`D:/ssi/sites`): 5 запросов в минуту с адреса на API — два прогона проверок подряд дают ложные 429.
