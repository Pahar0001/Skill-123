## Статусы и доказательства (правило 2)

**2. Не притворяться.** Пять разных состояний, и они не сливаются:

| состояние | что означает |
|---|---|
| ANALYZED | изучено по снимкам, DOM, коду |
| IMPLEMENTED | код написан, страница открывается |
| RUNTIME VERIFIED | в браузере произошло ожидаемое: нет ошибок, клик/скролл/холст дали результат |
| VISUALLY VERIFIED | снимок открыт глазами на нужных экранах и выглядит как задумано |
| PERFORMANCE VERIFIED | измерено `perf.mjs`, бюджеты соблюдены или отклонение записано |

VERIFIED ставится **только с доказательством**, снятым после последней
правки файлов сайта: протокол `runtime/*.json` (или его шаг) с вердиктом не
FAIL, снимок, замер — `state.mjs set … --evidence <файл[#шаг]>`. Журнал
сам отвергает доказательство с FAIL, старше правки сайта или лежащее в
папке сайта, VERIFIED нескольким задачам одним вызовом (`set 1,2 …`) и
протокол целиком, уже подтвердивший другую задачу (второй раз — только с
`#шагом`). Каждый протокол помнит, каким кодом снят (поле `generator`:
скрипт и `lib.mjs`, коммит, незакоммиченные правки); `state.mjs set` и `show`
пишут WARN «протокол снят другой версией скрипта — перепрогнать», если скрипт
с тех пор менялся, — отметка ставится, но такое доказательство перепрогнать
до отчёта. NA — только с причиной (`--note`); отчёт считает раздельно:
«проверено N, неприменимо M, без доказательства K, устарело S».
Поля журнала: `impl` — TODO / DOING / DONE / BLOCKED / DROPPED; `runtime`,
`visual`, `mobile`, `perf` — NOT_CHECKED / VERIFIED / FAILED / NEEDS_WORK / NA;
ANALYZED — этап, а не поле. runtime и perf подтверждаются только протоколом
`.json`, visual и mobile — протоколом или снимком (для mobile — снятым на
экране уже 1024 px: протокол журнал проверяет по его viewport, снимок —
только если он из `shots.mjs` и рядом лежит `shots.json`; снимок
`runtime/*.png` по ширине не проверяется — для mobile брать протокол
`--viewport mobile` или `after/*-mobile-*.png`). «WebGL проверен» без открытого
холста, «mobile готов» без снимка на 390 и 320 px, «оптимизировано» без
замера — запрещённые фразы.

## 0. Подготовка

```
node ~/.claude/skills/site-rework/scripts/state.mjs <папка> init <url|-> "<запрос>" --site <папка сайта> --mode rework|mirror|donor|new
node ~/.claude/skills/site-rework/scripts/requirements.mjs <папка> ingest --text "<бриф>" --kind brief   # и каждый файл ТЗ: --file; в new — обязательно, в других — при >1 источнике
node ~/.claude/skills/site-rework/scripts/taste.mjs brief --run <папка> --blocks <блоки из запроса>   # запреты и эталоны: общие и этого прогона
```
И прочитать `~/.claude/site-rework/taste/WISHES.md` — пожелания пользователя
его словами и выводы «как делать нешаблонно» (раздел «Два журнала» ниже).
Открыть `Read` картинки из вывода `taste.mjs`: запреты — в матрицу «не
делать». Определить режим; папка сайта для `--site`: исходники — папка
проекта, зеркало — `<папка>/mirror`, донор и `new` — `<папка>/site` (в `new` init создаст её
сам; адрес `-` — сайта ещё нет, `meta --url` — когда поднят). По ней журнал
узнаёт, что доказательство устарело (сайт правили после проверки). Локальный проект — поднять сервер (`npm run dev`
или что есть; статическую папку — `serve.mjs`, он сжимает как хостинг) **отдельным процессом** с журналом в папке
прогона: фоновая команда сессии гаснет при её перезапуске, и проверки молча падают на пустой порт
(`reference/environment.md` → «Стенд»). Сервер без сжатия — рядом прокси со сжатием
(`templates/run-tools/gzip-proxy.mjs`), и базу скорости снимать через него **до первой правки**: после правок
«до» уже не снять без разворачивания старой версии. Разовые инструменты прогона — `cp -r
~/.claude/skills/site-rework/templates/run-tools <папка>/tools` (README там же). Узнать браузер пользователя по
умолчанию — первая строка вывода `runtime.mjs` («у пользователя по умолчанию Firefox — проверьте и в нём:
--browser firefox»): в нём — дымовая проверка перед сдачей. Записать ревизию инструментов в `<папка>/tools.md` по
чек-листу `reference/tool-registry.md`.

**Под задачу не хватает умения** (формат документа, библиотека, сервис, которых нет в реестре) — сначала готовый
навык, а не свой: где искать и как выбрать — `reference/skills-search.md`; до установки —
`node ~/.claude/skills/site-rework/scripts/skill-audit.mjs audit <папка | .zip | адрес GitHub>` (из навыка ничего
не запускается; FAIL — не ставить). Ставить `skill-audit.mjs install <источник> --skill <имя> --yes` — только с
согласия пользователя; навык про то же, что уже стоит, — оставить лучший, остальные выключить, не удалять
(`install` печатает похожие; широкое описание — `skillOverrides` name-only или user-invocable-only).

## 2. Анализ и план

По `reference/analysis.md`: разобрать запрос на области, составить матрицу
**менять / не трогать**, пройти воронку Arrival → Understanding → Interest
→ Trust → Decision → CTA → Conversion и найти трение. Каждое решение — с
причиной.

Для каждого ключевого блока и для каждого компонента, которого нет у
донора, — запись в `<папка>/authorship.md` по `reference/authorship.md` §3:
три черты донора → три кандидата из разных направлений → отсев по каталогу
и журналу вкуса → эскизы двух → выбор с причиной. **Показать эскизы
пользователю до сборки страницы**, если сессия интерактивная. Направление и
критика кандидатов — справочники `impeccable` (`reference/craft.md`); без донора — отправные
точки из UI UX Pro Max (`reference/craft.md` → «UI UX Pro Max»); всё проходит тот же отсев.

**Что показать на эскизе, кроме раскладки** (правило 7 — впечатление из вариантов, а не первый рабочий):

- **три плашки акцента рядом** на одном первом экране: спокойнее образца, близко к образцу (на 60–70 % пути к
  его акценту), как у образца. Приглушать акцент донора до «палитры заказчика» молча нельзя: на «Зелёном
  уголке» владелец после показа попросил «чуть кислотней». Выбор — `taste.mjs add --run <папка>` его словами;
- **лист «наш предмет рядом с предметом донора»** — если на сайте будут предметы с объёмом: первый же кадр по
  планке `reference/blender.md` → «Планка качества», а не черновик (черновик на 32 сэмпла — только себе, для формы и света);
- **фон**: вырез 1:1 своей фактуры на цвете поля рядом с вырезом образца (`surface-tile.mjs --like <texture.json образца>` — вид берётся из замера; «не определён» — два кандидата рядом), и один набросок
  в тему в его настоящем размере и бледности;
- **шапка при прокрутке** — кадр наверху страницы и кадр на середине (`run-tools/scroll-shots.mjs`);
- `cliche.mjs <эскиз> --baseline <папка>/cliche/donor.json` — на эскизе главной и потом после сборки каждой
  новой страницы: типовые блоки (полоса цифр, одинаковые плитки и карточки) дешевле убрать на эскизе.

**Движение** — отдельной таблицей в `analysis.md` («Движение донора → блоки»), по `reference/motion.md`:
каждая строка `motion/<донор>.md` — наш блок с теми же числами или «почему нет» в
`<папка>/motion-decisions.json` (копировать по максимуму; один файл на desktop и mobile — ключи по виду и подписи с экраном: `reveal:div.card:mobile`;
приём, сделанный у нас другим видом, сверка находит сама — в решения не писать); сверху — 1–2 движения из самого товара и
1–2 свежие идеи из банка: `ideas.mjs pick --run <папка> --for "<о чём сайт>"` (не было на последних
сайтах, пользователь не отверг; взятое — `ideas.mjs use <id> --run <папка> --block <блок>`).

План — задачи в журнале с приоритетом:

```
node ~/.claude/skills/site-rework/scripts/state.mjs <папка> add "Меню на телефоне не открывается" --priority P0 --area mobile
```
Есть реестр — план из него: `requirements.mjs <папка> plan R-… "<задача>" --area …` (задача и
связь одной командой; приоритет по умолчанию — из видов требований), таблица плана — `report --plan`.
Задача без требования допустима, требование без задачи — нет. У каждого требования — критерий
(`reference/new-site.md` §1); `runtime`-критерий — `--assert "/*R-007.a*/ …"`, тогда доказательство
находится само. `list --open` пуст — план готов.

P0 сломано · P1 крупная проблема UX · P2 крупная визуальная · P3 тексты ·
P4 движение · P5 полировка. Порядок: P0 → P5, внутри — зависимости:
дизайн-система раньше UI, тексты раньше подгонки вёрстки, кадры раньше
секций, которым они нужны, 3D и движение после того, как вёрстка встала.

## 3. Реализация — по одной задаче

Для каждой задачи: сделать → перезагрузить → `runtime.mjs` с шагами именно
под неё → снимок → открыть глазами → исправить → повторить. Не принимать
первый результат: минимум один круг исправлений на каждую заметную задачу.

- вёрстка и UI: правки в дизайн-системе сайта (переменные из `design/site.tokens.css`,
  в режиме донора — `donor/design/donor.tokens.css`),
  не поверх; новый сборщик или фреймворк — только с выигрышем и работающей выкладкой (правило 5);
- тексты: `reference/copy.md` — своё (бриф, слова владельца) в `<папка>/copy/facts.json` с источником,
  чего нет — придумать правдоподобно и в список для владельца `<папка>/copy/invented.json` (числа и
  `copy:stub` lint с `--out` дописывает сам, имена, отзывы, адреса — руками), голос бизнеса,
  заголовки, кнопки, формы; `copy.mjs lint <url> --out <папка> --tag after`; типограф
  `copy.mjs fix --typograph <файл>` — сначала показ, дифф пользователю, `--write` после согласия; сайт с
  серверным рендером (тексты в коде шаблонов и в базе) — `reference/copy.md` → «Сайт с серверным рендером»:
  строки шаблонов `run-tools/strings.mjs`, набор при выводе `run-tools/typo.mjs`, чужой текст — только набор;
- типографика: `reference/typography.md`; шрифт — донора с кириллицей, иначе подбор по образцу:
  `fonts.mjs measure <донор>` → `match` → `sheet` (лист глазами) → `decide`, подробности — `reference/fonts.md`;
  образца нет — `fonts.mjs pick --like "<характер>"` (пары — `fonts.mjs pairs`); к себе — `fonts.mjs get "<Семейство>" --weights 400,700
  --out <папка сайта>` (свои woff2 и `fonts/fonts.css`, кириллица и ₽ проверены по файлам), надпись-логотип —
  `--text "<надпись>"`; неразрывные пробелы и неразрывные дефисы — в исходном тексте и данных (`products.js`, json,
  база), не скриптом на странице; `typeset.mjs` только меряет;
- фото и видео: `reference/engines.md` → «Картинки и видео»: `media.mjs search` → лист-контакт
  глазами → `pick` с `--seen` и `--caption` → `credits`;
- фактура: `reference/engines.md` → «Фактура»: зерно — своя плитка `grain-tile.mjs`, слой `templates/grain.css`;
  крупная фактура (мятая и зернистая бумага, камень с прожилками, ткань) — своя бесшовная плитка `surface-tile.mjs`, слой
  `templates/surface.css` (умножением на цвет поля, на тёмных плитках — затемнением);
- рисунки в фон: `reference/engines.md` → «Рисунки в фоне»: свои наброски от руки `templates/sketch2d/`
  (фигуры кодом → `svg3d.mjs rough`), бледной тушью, вне потока; чужие картинки и наборы иконок не брать;
- 3D: `reference/engines.md` → «3D»: сначала ответ «нужно ли», потом подход, потом обязательная проверка холста;
  предметы-украшения без вращения — рендером Blender в прозрачный WebP: `blender.mjs render` (сцены-образцы —
  `templates/blender/`, планка качества и цена кадра — `reference/blender.md`); нет Blender — `blender.mjs doctor`
  говорит, что ставить; предмета с объёмом без него нет (мелкий значок — `svg3d.mjs`, набросок — `sketch2d`);
  команда: `node ~/.claude/skills/site-rework/scripts/blender.mjs render icons.py --variant pack --out out --bg <цвет поля>`
  (из копии сцен `<прогон>/blender`; остальные — `reference/blender.md` → «Порядок»);
- состояния и длинные страницы — `templates/run-tools/`: `states.mjs` (меню, фильтры, подсказки, ошибки форм,
  сообщение после отправки — сценарием, лист-контакт), `look.mjs` + `tops.mjs` (все страницы одним взглядом),
  `slices.mjs` (длинная страница кусками), `scroll-shots.mjs` (кадры в точках прокрутки для привязанного к ней
  движения и шапки); это листы для глаз — вердикты и доказательства дают `runtime`, `shots`, `a11y`, `perf`;
- картинки каталога под карточки — малые копии и `srcset`: `run-tools/img-variants.mjs` (на «Зелёном уголке»
  760 → 400 px дали −60 % веса каталога);
- детали для красоты (правило 6): по разделу «Детали для красоты» плана (`reference/analysis.md`). Механика —
  `templates/decor-kit/`: скопировать `decor-kit.css` и `decor-kit.js` к сайту, две строки в `<head>`, README — приёмы,
  переменные, мотивы. Вид — свой: шрифт и знак у каждого раздела (Google Fonts, кириллица — `cyrillic-check.mjs`),
  свой спрайт рисунков линией из мира дела (README: `pathLength="1"` у каждого контура, без `vector-effect`,
  currentColor, без заливок), свой мотив у каждого раздела; образец — `templates/decor-kit/demo.html`;
- картинка заменена под тем же именем — метка версии в адресе (`photo.webp?v=<хэш содержимого>`): иначе кэш
  браузера до 7 дней показывает старый кадр («Эпицентр», 29.09);
- фоновое видео — `reference/motion.md` → `video-bg` (лёгкое, без звука, постер, пауза вне экрана);
- движение: рецепты `reference/motion.md` по таблице motion.mjs (числа донора, не на глаз), `reference/engines.md` → «Движение»; чем делать — `motion.md` → «Техника» (CSS, Motion, GSAP — что лучше даёт эффект; код на Motion — по навыку `motion`), `prefers-reduced-motion` всегда;
- своё движение и полировка: числа своего — `motion.md` → «Когда чисел донора нет»; детали, состояния, телефон —
  `reference/craft.md` (impeccable и навыки Эмиля — справочники, ведёт site-rework; навык `impeccable` не вызывать и
  `scripts/impeccable` не запускать — читать его `reference/*.md`);
- телефон: отдельная вёрстка первого экрана, меню, форм и таблиц, а не «ужать десктоп»; 320 px тоже.

## Перевести весь сайт в новый язык

Главная уже в новом языке (донор, своя палитра и шрифты), а страниц ещё десятки: услуги, работы, контакты,
собранные генератором. По прогону burbey.ru (03.10, язык owlsdepartment).

1. **Слой поверх старого CSS, а не переписывание страниц.** Один файл (`lang.css`) подключается на каждой
   странице после `site.css` и переворачивает переменные палитры и шрифтов: `--paper`, `--ink`, `--acc`,
   `--display`, `--text`… Разметку страниц не трогать, пока слой не встал; что не берёт переменные (жёстко
   прописанные цвета) — точечными правилами в том же слое.
2. **Инверсные блоки** — тёмные карточки «чернилами» с жёстко прописанным белым текстом. После переворота они
   светлые, а текст остался белым. Внутри них вернуть прежнюю пару переменных (`.card--ink { --paper: …;
   --ink: … }` со старыми значениями), а не перекрашивать детей по одному. Ловушки:
   - светлое по светлому: блоки с `background: var(--ink)` и `color: #fff`; акцентные узлы с `background:
     var(--acc)` и белым текстом (акцент сменился, белый остался);
   - кнопки без модификатора в чёрных карточках берут общий вид кнопки — теперь в цвет карточки;
   - мелкие подписи 11 px в новом языке читаются хуже — поднять до 12 px.
   Селекторы для всех трёх собирать **скриптом по старому CSS** (`var(--ink)` рядом с `#fff`, `var(--acc)`,
   `font-size: 11px` / `.6875rem`), а не глазами по страницам — глазами находится половина.
3. **Шапка с `mix-blend-mode: difference`** (как у донора) над средне-серым фоном и скриншотами работ теряет
   контраст: серое минус серое. Прозрачная с difference — только в первом экране, дальше — подложка (класс по
   прокрутке). Как шапка донора живёт при прокрутке вниз и вверх — `run-tools/frames.mjs <тег> <донор>
   --scroll-down --scroll-up` (полоса шапки кадрами; в `frames.json` у шапки записан `blend`).
4. **Капс с `line-height` меньше 1** — Й и Ё налезают на строку выше. `typeset.mjs` с `--pages` по всем
   страницам; строку «смотреть Й Ё на снимке» — проверить на снимке, а не пропускать.
5. **Генераторы страниц** (`portfolio-build` и т. п.) — тот же слой в их шаблон, иначе следующая пересборка
   вернёт старый вид. Генератор не должен падать, если на главной больше нет старого блока, который он
   обновлял: нет метки — пропустить с предупреждением.
6. **Выкладка.** Новые папки страниц — в `Dockerfile` и конфиг сервера (`COPY`, правила Caddy или nginx), иначе
   на бою 404, хотя на стенде всё открывается: сверить список папок с конфигом выкладки до пуша:
   `node ~/.claude/skills/site-rework/scripts/deploy-check.mjs <папка исходников> --out <папка>` (без FAIL; после
   выкладки — с `--pages "/,/новая/" --url <боевой адрес>`, `reference/qa.md` → «Перед выкладкой»).
   Переснятые скриншоты работ под теми же именами — с новой меткой версии в адресе (`?v=<хэш>`).
7. **Проверка — по ВСЕМ страницам**, не только по главной: `runtime.mjs --scroll` и `a11y.mjs` на каждой
   странице, на mobile и desktop (экран один за запуск — циклом), плюс `look.mjs` + `tops.mjs` — все страницы
   одним листом для глаз.

```sh
BASE=http://localhost:3100
for p in home services works contacts; do for v in desktop mobile; do
  u="$BASE/${p/home/}"
  node ~/.claude/skills/site-rework/scripts/runtime.mjs "$u" --viewport $v --scroll --out <прогон> --tag "lang-$p-$v"
  node ~/.claude/skills/site-rework/scripts/a11y.mjs "$u" --viewport $v --out <прогон> --tag "lang-$p-$v"
done; done
```

## 5. Отчёт — `templates/report.md`

Обязательные разделы: сайт и режим, запрос, **требования** (если есть реестр —
`requirements.mjs report --md`: источник и дата, решение, задачи, критерии, статус; что не взято из
документов; вопросы с ответами и допущениями; «Ждём от вас»; «Не проверено здесь»; история
изменений), что изучено, инструменты и
зачем, изменения, авторские решения, проверено в браузере (контрол →
сценарии → протокол), функции (чек-лист: да / нет / неприменимо с
причиной), проверено глазами, скорость (до и после), кадры и
лицензии, **придумано — проверить владельцу** (`copy/invented.json`, допущение о деле, кадры с `invented`

Любая оценка пользователя («шаблонно», «нравится», выбор варианта) —
сразу `taste.mjs add --run <папка>` с его словами дословно и кропом. Удачное своё — в банк идей
(`ideas.mjs add`), отзыв на взятую идею — `ideas.mjs status <id> liked|rejected --quote "<его слова>"`.

## Журналы по ходу любого прогона

- **Пожелания пользователя** — `~/.claude/site-rework/taste/WISHES.md`, только
  **общие**, для всех сайтов. Читать на шаге 0 вместе с `taste.mjs brief`.
  Замечание по одному сайту («здесь форма шаблонная») — в `analysis.md` прогона,
  раздел «Пожелания по этому сайту», и `taste.mjs add --run`; общим его не
  делать, пока пользователь сам так не скажет (непонятно — спросить). Запись журнала
  вкуса с `--run <папка>` действует только в этом прогоне (область site); общей
  (`--scope general`) её делают, только если пользователь сказал, что это для всех сайтов.
  Вывод «как делать нешаблонно» из общего замечания — в раздел выводов WISHES.md.
- **Банк идей** — `~/.claude/site-rework/taste/ideas.json` (`ideas.mjs`, читать — `IDEAS.md`): удачные
  ходы прошлых сайтов и заготовки, где стояли и как на них отозвался пользователь. На плане —
  `pick`, после сдачи — `add` и `status`. Разнообразие: одна «подписная» идея не ставится на два
  сайта подряд, отвергнутое не предлагается.
- **Неточности самого скилла** — `docs/SKILL-ISSUES.md` в папке навыка (нельзя править
  папку навыка — `~/.claude/site-rework/SKILL-ISSUES.md`, перенести при коммите): скрипт
  упал, соврал, вывод путает, инструкция расходится со скриптом, не хватило
  флага. Записывать сразу, как заметил (формат — в шапке файла), обойти и
  работать дальше; чинить — после прогона, отдельным коммитом.

## Требования по ходу работы

Пользователь пишет посреди работы («а ещё…», «нет, лучше…», файл, голосовое) — это источник, а не реплика:

1. `requirements.mjs <папка> ingest --text "…"` (файл — `--file`, голосовое — сначала расшифровка whisper, `reference/new-site.md` §1);
2. атомы — `add` / `change --quote` / `status … dropped --quote` / `status <старое> superseded --by <новое>`; своё — только `--self --why`; не уверен, что это требование, — `impact --text`;
3. `conflicts` — вопрос одним сообщением, если ответы ведут к разной работе; нет связи — `assume Q-… "…"`; иначе решить и записать причину;
4. `impact R-…` — какие задачи переоткрыть, снять, добавить (`link` / `plan` / `review`); язык сайта задет — это широкая правка, сказать об этом;
5. сделать; быстрый круг — `checks --only R-… --sh quick.sh`; перед сдачей — все проверки заново (правка сайта и смена требования делают старые доказательства устаревшими);
6. пользователю три строки: что пришло → что изменилось → чем проверено.

Оценка вида «шаблонно / нравится» по-прежнему идёт в журнал вкуса (`taste.mjs add`); требование к сайту — в реестр.
Одно и то же сообщение бывает и тем и другим — тогда в оба.

## Прогресс для пользователя

При каждом переходе между этапами показывать чек-лист из `state.mjs show`:

```
✓ Сайт разведан
✓ Открыт в браузере, консоль и сеть сняты
→ Дизайн разобран глазами
· План с приоритетами составлен
```
Между этапами — короткие строки: что делается, что нашлось. Без пересказа
файлов и без обещаний того, что не проверено.

## Когда спрашивать, а когда решать самому

Спрашивать (через `AskUserQuestion`, если сессия интерактивная; иначе принять
допущение, записать его в отчёт и продолжать):
- при запуске — анкета, два вызова (раздел «Вход»): о работе — близость к образцу, разнообразие, что главное,
  контент; о виде — есть ли сайт-образец (нет — три кандидата или каталоги, `reference/donor-mode.md` §0), фон
  (ровный, фактура и рисунки, только фактура), шапка при прокрутке, цвет;
- запрос конфликтует с ограничением («сделай ярче» при «не менять основной цвет»);
- генерация картинок или 3D стоит денег на счету пользователя (Higgsfield, Recraft: `recraft.mjs` без `--yes` печатает сумму — её и назвать в вопросе);
- нужны крупные кадры первого экрана или видео, а `media.mjs doctor` пишет, что
  `PEXELS_API_KEY` не задан, — один раз попросить бесплатный ключ (pexels.com/api);
  перед поиском на Commons без `MEDIA_CONTACT` — спросить контакт для User-Agent
  (сайт или рабочая почта; личные данные самому не подставлять). Подробно —
  `reference/engines.md` → «Картинки и видео»;
- удаление секций, смена цен, контактов, юридических текстов;
- запрет из журнала вкуса спорит с явной чертой нового донора;
- две трактовки ведут к разным сайтам, и референсов нет — предложить два направления одним вопросом, с эскизами;
- требования описывают веб-сервис с сервером: делать ли демо (демо с пометкой / готовый сервис / отдельная работа); нет связи — демо с пометкой, допущение (`requirements.mjs assume`);
- стек из ТЗ меняет работу; строка документа похожа на пример шаблона, а без неё меняется план;
- противоречие двух требований из одного источника (из разных — новое `superseded` старое без вопроса);
- снять, отложить или вынести требование — только словами пользователя;
- типограф `copy.mjs fix --typograph` меняет тексты сайта — сначала показать дифф.

Не спрашивать: размеры отступов, выбор гарнитуры в рамках текущего языка,
длительности анимаций, порядок секций внутри плана, формулировки текстов,
атомы и критерии требований, трактовку размытого, приоритет внутри must, раскладку
требований по страницам и блокам — сделать, показать снимком, поправить по отклику.
