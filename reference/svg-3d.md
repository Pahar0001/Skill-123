# 3D SVG: фоны, иконки и украшения с объёмом — чистым вектором

Стек из бесплатных библиотек с открытым кодом, один инструмент — `scripts/svg3d.mjs`. Даёт рисунки
с объёмом (предмет, а не плоский значок), которые остаются обычным SVG: весят единицы килобайт,
красятся цветами сайта, чёткие на любом экране, видны без JS. Образцы сцен и страница, где всё стоит
как на сайте, — `templates/svg3d/` (README там же).

Это **детали для красоты** (правило 6 в `SKILL.md`), а не «3D везде»: решение «фото, видео или 3D —
по смыслу сайта» из `engines.md` → «3D» остаётся в силе. SVG с объёмом уместен там, где WebGL —
слишком много: ряд иконок шагов, предмет рядом с текстом, россыпь на фоне, схема.

```
node ~/.claude/skills/site-rework/scripts/svg3d.mjs doctor      # что работает на этой машине
node ~/.claude/skills/site-rework/scripts/svg3d.mjs --help      # все команды и флаги
```

Зависимости — в `templates/deps/package.json` (`npm i --prefix ~/.claude/site-rework`): zdog, three,
svgo, roughjs, @neplex/vectorizer. CadQuery — в Python (`pip install cadquery`), Blender и potrace —
необязательные. Плагинов и платных сервисов нет.

## Какой движок когда

| задача | движок | почему | вес образца |
|---|---|---|---|
| ряд иконок шагов, преимуществ, разделов | `zdog` + `--css-vars --for icon` | круглые «игрушечные» предметы из десятка фигур; цвета — переменными сайта; один набор — один характер | 0.9–2.2 КБ |
| предмет-украшение рядом с текстом, «живой» | `zdog` + `templates/svg3d/zdog-live.js` | та же сцена поворачивается за прокруткой и мышью, статичный SVG — запасной вид | 1.5–2.5 КБ + Zdog 30 КБ (7 КБ после сжатия), один раз |
| гранёный предмет: соты, кристалл, коробки, дома, детали | `three` | настоящая геометрия и свет: у каждой грани свой ровный оттенок; пересечения предметов считаются честно | 5–8 КБ |
| схема, «как устроено», чертёж изделия | `cad` | проекция со скрытыми линиями пунктиром, как в конструкторской документации; красится цветом текста | 1.5–13 КБ |
| фон-россыпь | `scatter` из рисунков любого движка | каждый рисунок описан один раз, расставлен много раз; `--frames` даёт один предмет в разных ракурсах | 7–13 КБ на 9–16 предметов |
| готовый рендер или рисунок → вектор | `trace` | растр сводится к палитре и обводится кривыми; `--palette` притягивает цвета к цветам сайта | 2–10 КБ |
| «нарисовано от руки» | `rough` | дрожащая линия и штриховка; лучше всего на чертежах `cad` и контурных значках | 10 КБ (линии) … 50 КБ (штриховка) |
| обычные значки интерфейса (телефон, стрелка, меню) | `icon` (Iconify) | открытые наборы, цвет — `currentColor`; лицензия набора — в `credits.json` | 0.3–0.5 КБ |
| чужой или старый SVG перед вставкой на сайт | `optimize` | SVGO + правила безопасности: без скриптов, внешних ссылок и растра | — |

Чего стек **не** делает: фотореализм, текстуры, тени, блики, прозрачные материалы, мягкий свет — это
растр (пререндер WebGL в WebP, `engines.md` → «3D») или фото. Сложная органика (лицо, животное,
складки ткани) в Zdog и «гранёном» виде выходит игрушкой — если это не стиль сайта, брать
иллюстрацию (`recraft.mjs`) или фото.

## Движки

### zdog — круглые «игрушечные» предметы

Сцена — ES-модуль, исполняется в безголовом Chrome (Zdog рисует через DOM), сеть закрыта:

```js
export const view = { size: [160, 160], rotate: { x: -0.42, y: 0.6 } };   // поле и поворот, радианы
export const palette = { ink: '#16301F', moss: '#5E7A33', clay: '#C8643C' };
export function build({ Zdog, illo, palette: c, TAU }) {
  new Zdog.Cylinder({ addTo: illo, diameter: 58, length: 34, stroke: false, color: c.clay, rotate: { x: TAU / 4 } });
}
```

```
node svg3d.mjs zdog scenes/zdog-sprout.mjs --out img --css-vars --for icon --preview "#E9EEDD"
node svg3d.mjs zdog scenes/zdog-sprout.mjs --out img/frames --frames 8 --size 200 --preview "#E9EEDD"   # 8 ракурсов и лист кадров
node svg3d.mjs zdog scenes/zdog-sprout.mjs --out img --palette "clay=#3A6EA5,shade=#2C5580"             # другой цвет
```

- **Закрытые целиком фигуры убираются сами** (задние грани коробок, донышки, перекрытые детали) — до
  половины узлов файла, и края перестают просвечивать каймой. `--no-cull` — оставить.
- **`--css-vars`**: цвет палитры пишется переменной с запасным значением — у цвета `moss` это
  `fill="var(--c-moss,#5e7a33)"`. Сайт перекрашивает рисунок, вписанный в страницу, одной строкой CSS;
  в `<img>` и фоне CSS остаётся запасной цвет. Оттенки («тёмная сторона») — отдельными именами палитры.
- **Порядок слоёв у Zdog — по центру фигуры.** Большая плоская фигура и маленькая над ней спорят:
  маленькую — в отдельную `Zdog.Group` (группа рисуется целиком по своему началу). Деталь, которая
  всегда лежит на другой (жилка на листе), — в одну `Group` с ней, без `updateSort`. Проверять
  ракурсы: `--frames 8 --preview`.
- **`backface: false` у `Zdog.Box` прячет не те грани** (проверено на 1.1.3) — не использовать.
- Поле сцены — с запасом на поворот: у «живой» сцены и у кадров предмет не должен выходить за `view.size`
  (инструмент предупредит: «рисунок выходит за поле»).

**«Живой» Zdog на сайте.** Тот же файл сцены, что дал статичный SVG:

```html
<div data-zdog-live="/assets/svg3d/zdog-sprout.mjs">
  <svg viewBox="-80 -80 160 160" aria-hidden="true" focusable="false">…статичный вид…</svg>
</div>
<script type="module" src="/assets/svg3d/zdog-live.js"></script>
```

`zdog-live.js` (из `templates/svg3d/`, копировать на сайт вместе с `vendor/zdog.dist.min.js`) грузит
библиотеку, только когда блок подходит к экрану; предмет доворачивается вслед за прокруткой и мышью и
останавливается — петли нет. Без JS, при ошибке загрузки и при «меньше движения» остаётся статичный
SVG (библиотека при «меньше движения» не грузится вовсе). Настройки — атрибуты `data-zdog-mode`,
`data-zdog-turn`, `data-zdog-lib` (README образца).

### three — гранёные предметы (Three.js SVGRenderer)

```js
export const view = { size: [320, 300], pad: 10, camera: { type: 'ortho', dir: [0.9, 1.05, 1] } };
export const palette = { sun: '#E8B647', moss: '#5E7A33' };
export function build({ THREE, root, color, lights }) {
  lights({ ambient: 0.34, key: { dir: [0.25, 1, 0.45], power: 0.74 }, fill: { dir: [1, 0.15, 0.2], power: 0.2 } });
  root.add(new THREE.Mesh(new THREE.CylinderGeometry(1, 1, 1.4, 6), new THREE.MeshLambertMaterial({ color: color('sun') })));
}
```

```
node svg3d.mjs three scenes/three-honeycomb.mjs --out img --preview "#E9EEDD"
node svg3d.mjs three scenes/three-honeycomb.mjs --out img --tones 4          # меньше оттенков — меньше узлов
```

Что инструмент делает поверх SVGRenderer (у «сырого» вывода соты — 11 КБ и 199 узлов со щелями
между всеми треугольниками; после — 7 КБ и 47 узлов):

1. **Порядок граней исправляется по глубине.** SVGRenderer раскладывает грани по центру — длинная
   грань с дальним центром перекрывает ближнюю. Здесь каждая пара перекрывающихся граней сравнивается
   в точке перекрытия; грани, проходящие друг сквозь друга, сначала режутся по линии пересечения.
   Остаётся одно неразрешимое: перекрытие по кругу (A над B, B над C, C над A) — WARN.
2. **Грани одной заливки склеиваются** в один контур, внутренние рёбра убираются (треугольники →
   многоугольники).
3. **Щели между гранями закрываются** обводкой цветом заливки, 1 px экрана при любом масштабе (`--seam`).

Правила сцены: материал — `MeshLambertMaterial` (плоская грань со светом) или `MeshBasicMaterial`
(цвет как есть); свет — через `lights({ ambient, key, fill })`, сила — в линейном пространстве
(окружающий 0.3–0.4 и верхний 0.7–0.8 дают освещённой грани почти чистый цвет палитры); камера по
умолчанию без перспективы и подгоняется под предмет сама. Круглые тела — с малым числом сегментов
(6–12), иначе каждый сегмент — свой оттенок и свой узел; `--tones 3` сводит оттенки к ступеням.
**Переменными CSS не перекрашивается** (оттенок грани считает свет) — другой цвет даёт повторный запуск
с `--palette`. Линии и спрайты в сцене рисуются, но порядок с ними не исправляется (WARN).

### cad — чертёжная проекция (CadQuery)

```
node svg3d.mjs cad gear --out img --view iso --param teeth=20,holes=6 --preview "#E9EEDD" --color "#16301F"
node svg3d.mjs cad scenes/cad-gears.py --out img/sheet.svg --view top,front --size 720 --hidden faint
node svg3d.mjs cad crate --out img --draw --hidden none          # под прорисовку линией decor-kit
```

Встроенные фигуры — `gear`, `crate`, `nut`; свой сценарий — обычный файл CadQuery с переменной
`result` (или `show_object(obj)`), параметры приходят словарём `params` из `--param`. Сценарий — код,
он исполняется на машине: чужие сценарии читать до запуска.

- Видимые линии — одной толщины (`--stroke`), скрытые — тоньше и пунктиром (`--hidden dashed`),
  бледными (`faint`) или без них (`none`). Несколько видов (`--view top,front`) — в ряд, в одном
  масштабе, на общей нижней линии, как на листе.
- Цвет по умолчанию — `currentColor`: рисунок красится свойством `color` блока. `--color` — жёстко.
- Дуги и сплайны из ядра приходят частыми точками; инструмент заменяет их кривыми Безье (шестерня:
  26 → 15 КБ) — линия гладкая при любом увеличении.
- Толщина линии масштабируется вместе с рисунком: `--size` — ширина, с которой рисунок стоит на
  сайте. Чертёж на ширину 1200 px от файла с `--size 480` даст линию в 2.5 раза толще.
- Python с cadquery ищется сам (`SVG3D_PYTHON`, `py -3.9 … python`); найденный запоминается в
  `~/.claude/site-rework/cache/svg3d-python.json`. Файлов ядро не пишет — пути с кириллицей не мешают.

### blender — Freestyle SVG Exporter (необязательно)

Только если Blender установлен: `node svg3d.mjs blender сцена.blend --out img`. Без него команда
честно отказывает (код 2) и подсказывает замену. **Ветка ни разу не запускалась** — при разработке
Blender на машине не было; первый запуск на новой машине считать проверкой самой ветки, результат
открыть глазами. Скрипт Blender не ставит и ничего не скачивает; с 4.2 дополнение «Freestyle SVG
Exporter» ставится в самом Blender (Get Extensions).

## Утилиты

| команда | что делает | на что смотреть |
|---|---|---|
| `optimize <svg>…` | SVGO (viewBox сохраняется, нет — добавляется из размеров), id и классы — с приставкой, убираются `<script>`, обработчики, `javascript:`, внешние ссылки и картинки, `<foreignObject>`, SMIL-анимации; картинка «до и после» сверяется попиксельно | список «убрано при чистке»; `--allow-raster`, `--keep-anim`, `--keep-size`, `--label` — осознанные исключения |
| `trace <картинка>` | растр → вектор (vtracer): `--colors`, `--simplify`, `--drop-bg`, `--palette`; `--mono` — одним цветом (potrace, если установлен: линия плавнее) | тонкие линии пропадают при малом `--colors`; фото не трассировать — только рендеры и рисунки с ровными пятнами |
| `rough <svg>` | вариант «от руки» (Rough.js), одинаковый при одном `--seed` | штриховка просвечивает: объёмному рисунку — `--paper <цвет фона>` или `--fill-style solid`; для Zdog не годится (его фигуры — толстые обводки, WARN) |
| `icon <набор:имя>…` | иконка Iconify с `currentColor`, запись в `credits.json`; `--search <слово> --preview` — лист найденного | лицензия набора: MIT, ISC, Apache-2.0, CC0 — берём; CC BY — только с `--allow-attribution` (подпись на сайте); некоммерческие, GPL, неизвестные — отказ |
| `scatter <svg>…` | фон-россыпь: `<symbol>` + `<use>`, раскладка постоянна при `--seed`; `--area edges` оставляет середину под текст | предметы не должны лежать на тексте — проверить снимком; телефону — своя полоса (`--size 640x220`) |
| `preview`, `sheet` | PNG на фоне сайта и лист-контакт | рисует librsvg, не браузер: `var()` и `currentColor` подставляются; окончательно — страница в `runtime.mjs` |

Любая команда-движок принимает `--preview "<фон>"`, `--for icon|decor|background`, `--label`, `--json`.

## Правила качества

1. **Палитра сайта, а не библиотеки.** Цвета — из `design/site.tokens.css` через `--palette`; в сцене
   не больше 4–6 цветов, оттенки тени — свои имена (`clay` и `shade`), не случайные.
2. **Один характер на сайт.** Иконки одного ряда — один движок, один поворот (`view.rotate`), одна
   толщина обводки; Zdog и гранёный Three в одном ряду не смешивать. С рисунками линией из
   `decor-kit` согласуется `cad` (линия, `currentColor`); Zdog и Three — заливками, им нужен свой блок.
3. **Бюджет** (`--for`, сверх него — WARN):

   | назначение | вес | узлов | если больше |
   |---|---|---|---|
   | `icon` | 4 КБ | 40 | упростить сцену; иконка из 60 фигур — уже иллюстрация |
   | `decor` | 15 КБ | 200 | `--tones`, меньше сегментов и предметов |
   | `background` | 60 КБ | 800 | растровый пререндер (WebP) дешевле и для браузера, и по весу |

   Число узлов важнее килобайт: браузер рисует каждый узел при каждой перерисовке. Россыпь из
   16 предметов по 15 фигур — 240 фигур под текстом; анимировать такой фон целиком нельзя.
4. **Когда вместо SVG — растр.** Больше ~800 узлов; мягкие тени, градиенты света, текстуры; предмет
   сложнее 300–400 граней; фон на весь экран с мелкими деталями. Тогда — сцена Three.js в WebGL,
   снимок в WebP (`engines.md` → «3D»).
5. **Доступность.** Все рисунки по умолчанию — декор: `aria-hidden="true"` и `focusable="false"`
   ставит сам инструмент. Рисунок со смыслом (схема, которую не пересказывает текст) — `--label
   "что на рисунке"` (`role="img"`, `aria-label`). У `<img>` с декором — `alt=""`.
6. **«Меньше движения».** Статичный SVG — и есть вид при «меньше движения» и без JS. SMIL-анимации
   из чужих SVG убираются (они настройку не слушают). Живой Zdog — только через `zdog-live.js`.
   Кадры `--frames`/`--sprite` для смены кадров — в CSS под `@media (prefers-reduced-motion: no-preference)`.
7. **Не на тексте.** Россыпь — у краёв (`--area edges`, `left`, `right`); проверка — снимок на
   1440, 390 и 320 px. Под текстом допустим только бледный слой (10–35 % непрозрачности).

## Артефакты и как их обходить

| что видно | причина | что делать |
|---|---|---|
| волосяные светлые линии между гранями | сглаживание краёв соседних контуров | у `three` закрыто обводкой (`--seam 1`); не ставить `--seam 0`; у `trace` — `--simplify` больше |
| дальняя грань поверх ближней | сортировка «по центру грани» | у `three` исправляется само; WARN «перекрываются по кругу» — развести предметы |
| маленькая фигура Zdog уходит под большую | Zdog сортирует по центру фигуры | маленькую — в `Zdog.Group`; смотреть `--frames 8 --preview` |
| рисунок обрезан | предмет вышел за поле сцены | `--fit`, больше `--size` или `view.size` (WARN «выходит за поле») |
| толстая линия чертежа | файл с `--size 480` растянут на 1200 px | собрать с `--size`, равным ширине на сайте |
| штриховка `rough`: видны дальние грани | штриховка прозрачна | `--paper <фон>` или `--fill-style solid` |
| иконка не красится цветом текста | набор цветной или с жёстким цветом | WARN у `icon`; взять контурный набор (lucide, tabler, ph) |
| цвет не меняется переменной | рисунок стоит в `<img>` или фоне CSS | вписать SVG в страницу; или пересобрать с `--palette` |

## Как ставить на сайт

- **Вписать в страницу** (`<svg>…</svg>`) — когда нужны переменные (`--css-vars`), `currentColor` или
  живой Zdog. Приставка id у каждого файла своя (из имени файла, `--id-prefix`) — рисунки не делят id.
- **`<img src="…svg" alt="" width height loading="lazy">`** — гранёные предметы и всё, что не
  перекрашивается; размеры в атрибутах — чтобы вёрстка не прыгала.
- **Фон CSS** — россыпь: `background: url(bg.svg) center / cover no-repeat` на слое с
  `pointer-events: none`; заменённый под тем же именем файл — с меткой версии (`bg.svg?v=<хэш>`).
- Файлы копируются в папку сайта; на папку навыка сайт не ссылается.

## Проверка

```
node ~/.claude/skills/site-rework/scripts/svg3d.mjs selftest                       # после правок инструмента или на новой машине
node ~/.claude/skills/site-rework/scripts/svg3d.mjs sheet <папка рисунков> --out <папка>/sheet.png --bg "<фон сайта>"
node ~/.claude/skills/site-rework/scripts/runtime.mjs <url> --out <папка> --tag svg3d --scroll --fullpage
node ~/.claude/skills/site-rework/scripts/runtime.mjs <url> --out <папка> --tag svg3d-320 --viewport mobile-s --scroll
node ~/.claude/skills/site-rework/scripts/runtime.mjs <url> --out <папка> --tag svg3d-calm --reduced-motion --assert "!window.Zdog"
node ~/.claude/skills/site-rework/scripts/runtime.mjs <url> --out <папка> --tag svg3d-ff --browser firefox --scroll
```

Лист-контакт и снимки страницы **открыть глазами**: предметы не лежат на тексте, у ряда иконок один
характер, нет дыр и перевёрнутых граней, на 320 px рисунки на месте. `selftest` зелёный — это «инструмент
работает», а не «рисунок хорош»; строка SKIP в нём значит, что движка на машине нет и он не проверен.
