# Неточности и баги скилла site-rework, найденные в бою

Пишется по ходу прогонов: что скрипт или инструкция сделали не так, как
написано, или мешали работе. Одна запись — одна проблема. Чинить потом,
отдельным коммитом в git скилла, и перепрогонять то, что этот скрипт уже
проверял. Закрытое — не удалять, а отмечать «закрыто <коммит>».

Формат записи:

```
## <дата> · <прогон> · <скрипт или раздел инструкции>
Что: <что произошло — команда и вывод, коротко>
Ждал: <что должно было быть по документации или по смыслу>
Важность: мешает | путает | мелочь
Обход: <как выкрутился в этом прогоне>
```

## 2026-09-24 · figurki · serve.mjs + perf.mjs — вес без сжатия
Что: serve.mjs отдаёт статику без gzip/brotli, perf.mjs мерит «JS по сети» по фактической передаче: three.module.min.js — 691 КБ. На хостинге со сжатием тот же файл — 172 КБ gzip / 139 КБ brotli. Бюджет JS (300/600 КБ) на локальном сервере даёт FAIL, которого на бою не будет.
