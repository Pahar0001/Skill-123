# render3d — объёмные предметы пререндером

Сцена и съёмка для правила «фото, видео или 3D — по смыслу»: предметы из мира дела и ленты рисуются
в Three.js один раз, в безголовом Chrome, и стоят на сайте прозрачными WebP. Живого WebGL на странице
нет — нечему тормозить и ломаться на телефоне. Вынесено из боевого прогона «Зелёный уголок»
(01.10.2026), где владелец дважды попросил «рендер лучше»: всё, что ниже названо планкой, — итог тех
двух кругов, а не пожелание.

Набор даёт **сцену, свет, материалы и съёмку**. **Предметы у каждого сайта свои**: `scenes/` здесь —
образец (магазин семян: лента, пакет, заявка, счёт, калькулятор, коробка, росток, соты, семена, лист),
на сайт клиента их не переносить — писать свои по этому образцу.

| Файл | Что в нём |
|---|---|
| `stage.html` | сцена: студийное окружение из софтбоксов, свет, материалы, камера по рамке предмета, накопление кадров |
| `render.mjs` | съёмка: сервер на папку, Chrome, прозрачный PNG и WebP, превью на цвете сайта, доля заполнения кадра |
| `scenes/_kit.js` | заготовки геометрии: лист с прожилками, шестиугольник, пластина с фаской, трубка, скруглённый прямоугольник |
| `scenes/icons.js` | предметы-значки вариантами (`--variant pack`, `form`, `invoice`, `calc`, `box`, `pack-stand`, `seed`, `seeds`, `leaf`, `hex`) |
| `scenes/ribbon.js` | ребристая лента по кривой (`--variant wave`, `arc`, `loop`, `curl`) |
| `scenes/sprout.js`, `honeycomb.js` | росток из семени; соты с мёдом |
| `tools/variants.mjs` | малые ширины кадра под `srcset` |
| `tools/crop-ground.mjs` | рамка стоящего предмета с тенью на земле |

## Порядок

```sh
cp -r ~/.claude/skills/site-rework/templates/render3d <прогон>/3d        # сцены правятся в прогоне, не в скилле
cd <прогон>/3d
node render.mjs icons --variant pack --w 1000 --h 1000 --dpr 1 --trim --bg <фон сайта без #> --name icon-pack
node render.mjs ribbon --variant wave --w 1440 --h 640 --dpr 2 --bg <фон> --name hero-ribbon --n 64
node tools/variants.mjs out/hero-ribbon.png --widths 960,1440            # телефону — малая копия
node render.mjs icons --variant pack-stand --w 900 --h 900 --dpr 1 --trim --name pack-stand
node tools/crop-ground.mjs out/pack-stand.png                            # предмет на линии, тень ниже
```

Three.js ставить рядом не нужно: `render.mjs` отдаёт его из `~/.claude/site-rework/node_modules`.
`--n 1` — черновик в один проход (без теней) для подгонки формы; сдаётся только накопленный кадр.
Каждый кадр открыть глазами **на цвете сайта** (`--bg`) и листом рядом с предметами донора — до вёрстки.

## Планка качества — минимум первого же кадра

1. **Накопление, а не один проход** (`--n 96`, ленты — 64): камера дрожит в пределах пикселя (края без
   ступенек), ключевой свет гуляет по диску (тень с мягким краем), «купол» светит из случайной точки
   верхней полусферы с тенью (затенение в стыках и под выступами).
2. **Студия из софтбоксов**, а не комната: тёмный купол и яркие узкие плоскости — на лаке длинные блики,
   цвет не выбеливается отражением.
3. **Глянец рядом с матовым.** Листья, лента, монета — под плотным лаком; бумага и картон — матовые, с
   волокном (карта рельефа из шума и штрихов). Одна «глина» на всём — тот самый слабый первый кадр.
4. **Детали, по которым вещь узнают**: заваренный верх пакета с гофрой, этикетка с печатью, прожилки
   листа рельефом, металл зажима, гурт монеты, число на экране (холст → текстура), клапаны и скотч коробки.
5. **Тень на земле — под стоящим предметом** (`ground` в ответе сцены): невидимая плоскость, на которой
   видна только тень. Парящим предметам первого экрана она не нужна.
6. **Блик вдоль ленты**: `anisotropy` у материала и `uv` у геометрии — блик тянется по длине, как на атласе.
7. **Цвет — из дизайн-системы сайта**: `--palette` или `PAL` в `stage.html`. Яркий оранжевый с собственным
   свечением тональная кривая уводит в персиковый — мёд держать одним материалом и не пересвечивать.

## Своя сцена

```js
// scenes/<имя>.js
import { plate, roundedRect, mesh } from './_kit.js';
export function build({ THREE, root, PAL, clay, gloss, leafy, metal, paper, honey, printed, RoundedBoxGeometry, q }) {
  const g = new THREE.Group();
  g.add(mesh(new RoundedBoxGeometry(2, 1.4, 1.2, 8, 0.12), paper(PAL.kraft)));   // тело
  g.add(mesh(plate(roundedRect(0.9, 0.5, 0.08), 0.05, 0.02), gloss(PAL.moss), [0, 0, 0.62]));
  root.add(g);
  return { view: [0, 0.12, 1], fov: 24, margin: 1.1 /*, ground: 0.34 — тень на земле */ };
}
```

Материалы сцены: `clay` — мягкий с тонким лаком, `gloss` — гладкий под лаком, `leafy` — глянец со своим
свечением (листья), `metal`, `paper` — матовая бумага с волокном, `honey` — с преломлением, `printed(w, h,
рисовать)` — надпись с холста. Камера сама встаёт по рамке предмета; `view` — откуда смотрим, `margin` —
поле, `distance` и `target` — если рамка нужна своя (ленты).

## На сайте

- `<img>` с `width`, `height`, `alt=""`, `loading="lazy"`; кадру первого экрана — `fetchpriority="high"` и
  `srcset` с малой копией: лента 2880 px на телефоне стоила 1 с к LCP.
- Предмет в углу плитки — `position: absolute` и размер **по высоте**, чтобы не дотягивался до текста;
  на телефоне — меньше, проверить на 320 px.
- Стоящий предмет с тенью: кадр опустить на долю, которую печатает `crop-ground.mjs`
  (`transform: translateY(6.5%)`), иначе он висит над линией.
- Плоские значки («3D SVG», Zdog) рядом с пререндером выглядят слабее — на видных местах только объёмные;
  вектор оставлять там, где значок мелкий.

## Чем проверить

`runtime.mjs <url> --scroll` (кадр не перекрывает текст), `perf.mjs` (вес картинок, LCP — кадр первого
экрана), снимки 1440, 390 и 320 глазами. Доля заполнения кадра меньше 1 % — `render.mjs` сам даёт FAIL.

## Чего набор не делает

Не анимирует (движение — CSS и скрипт сайта: привязка к прокрутке, мышь), не трассирует лучи (отражения —
из окружения, преломление — приближённое), не проверен в Firefox и Safari как движок съёмки (снимает
только Chrome; результат — обычные картинки). Сцен «под любое дело» в нём нет и не будет.
