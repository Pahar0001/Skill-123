# Переработка сайта: от адреса до проверенного результата

Это не чат и не генератор кода, а порядок работы команды разработки:
разведка → анализ → план → реализация → проверка в браузере → отчёт.
Скрипты в `scripts/` снимают факты с живой страницы. Решения о дизайне и
тексте принимаются глазами по снимкам. Ничто не считается готовым, пока
не открыто в браузере и не проверено взаимодействием.

Здесь — порядок и правила. Подробности каждого шага — `reference/steps.md`, проверка — `reference/qa.md`,
среда Windows, сбои и полный список файлов — `reference/environment.md`, какой инструмент когда —
`reference/tool-registry.md`, все флаги — `reference/flags.md`.

**Требования живут в реестре**, а не в памяти разговора: `scripts/requirements.mjs`, `<папка>/requirements.json`.
Каждое сообщение, файл, голосовое или скриншот, где пользователь чего-то хочет, — источник с дословной
цитатой; каждое требование — с критерием приёмки и задачами журнала. В режиме `new` реестр обязателен, в
остальных — как только источников требований больше одного.

**Запуск скриптов.** Полным путём `node ~/.claude/skills/site-rework/scripts/<скрипт>.mjs` (в PowerShell 5.1 —
`$HOME/.claude/…`); зависимости — в `~/.claude/site-rework/node_modules`, скрипты работают из любой папки.
`-h` — все флаги, ничего не запускает. **Каждому скрипту — `--out <папка прогона>`** (у `cliche.mjs` — `--run`):
без него протокол ляжет в папку по адресу страницы, и `--evidence` его не найдёт. Опечатка во флаге — у
большинства скриптов ошибка, у части — `WARN неизвестный флаг` в stderr: увидел — поправить команду и
перепрогнать. Экран за запуск у `runtime`, `a11y`, `perf` — один; списком — у `discover`, `shots`, `typeset`,
`cliche`. Поменял флаг или строку `-h` — `node scripts/flags-doc.mjs`, перед коммитом скилла — `--check`.

**Среда (Windows).** Большие файлы — инструментом `Write`; обратные косые и экраны Юникода теряются в
`node -e`, heredoc и `python -` — такие правки литералом через `Edit` или файлом `.cjs`/`.py`; Git Bash
подменяет пути вида `/sites/…` — давать полные `C:/…`; фоновый прогон гасить по номеру процесса, не `pkill`
по слову. Подробно — `reference/environment.md`.

## Вход

Бриф — `templates/brief.md` (или форма `ui/brief-form.html`), можно свободным текстом:

| поле | если нет |
|---|---|
| URL | обязательный вопрос (в режиме донора — адрес донора); в режиме `new` адреса нет — нужен хотя бы один источник требований |
| Задача | «улучши» без уточнений — пройти воронку UX (`reference/analysis.md`) и предложить самому |
| Референсы, донор | снять через скилл `design-reference`, брать принципы; «сделай в языке вот этого» — режим донора; донора нет — подобрать (ниже) |
| О чём сайт | в переработке — из сайта; в доноре и `new` — спросить; без человека — придумать правдоподобное дело и записать допущение |
| Кадры и видео | свои → свободные источники (`media.mjs`) → генерация с согласия (Higgsfield, `recraft.mjs`) |
| Стиль, ограничения | сохранять язык сайта, если не просили менять; не менять контакты, цены, логотип, основной цвет, бэкенд |

**Анкета при запуске — до разведки**, двумя `AskUserQuestion` подряд: о работе и о виде (в одном вызове — не
больше четырёх вопросов; что есть в брифе — не спрашивать; без человека — рекомендованное, записать допущение).
Ответы — в `analysis.md`, «Решения пользователя», и в каждое задание агентам. Рекомендуемый вариант выделен.

| о работе | варианты | что меняет |
|---|---|---|
| Насколько близко к образцу | очень близко / **в духе образца** (язык образца + свои детали и идеи из банка) / только вдохновение | сколько берём у донора и как строго сверяем `verify`, `cliche --baseline`, `motion compare` |
| Сколько своих идей | сдержанно / **заметно** (детали в каждом разделе, свой мотив у раздела, 2–3 идеи из банка) / смело | сколько деталей и `ideas.mjs pick --n` |
| Что главное (несколько) | заявки и продажи / красота / телефон и скорость / тексты | приоритеты P1–P2 |
| Контент | пришлю свой / частично есть / **нет — сделай сам** | своё главнее придуманного; чего нет — пишем сами в голосе дела, фото — `media.mjs`, `copy.mjs lint --invent`; придуманное — списком владельцу (`copy/invented.json`) |

| о виде | варианты | что меняет |
|---|---|---|
| Сайт-образец | есть — вот адрес / **нет — подберите три** / нет — дайте каталоги, выберу сам | без образца язык не выбирать: три кандидата со снимками или каталоги живых сайтов — `reference/donor-mode.md` §0 |
| Фон | ровный / **фактура и рисунки в тему** (мятая бумага, прожилки, наброски, предметы на полях) / только фактура | что снять у образца (`texture.mjs`, `bgdecor.mjs`) и что сделать своим: плитка `surface-tile.mjs`, наброски `templates/sketch2d/` |
| Шапка при прокрутке | плотная / **полупрозрачная с размытием** / прячется при прокрутке вниз | вёрстка шапки; контраст закреплённого текста над фото — `a11y.mjs` |
| Цвет | спокойнее образца / **близко к образцу** / ярче образца | акцент и поля; окончательно — на эскизе, по трём плашкам акцента рядом |

Вопросы «о виде» появились после «Зелёного уголка» (01.10): фон, шапку и цвет владелец назвал правками уже по
собранному сайту — «и вообще надо спрашивать о таком в начале».

Контент «сделай сам» — сначала факты о деле: `firecrawl.mjs facts --run <папка> --about "<дело, город>"` (около
7 кредитов) → `copy/facts-candidates.json`; это кандидаты, в `copy/facts.json` — только проверенное глазами
(`reference/firecrawl.md`). Отдельным вопросом, если неясно: какие страницы донора нужны (`reference/donor-mode.md`
§1) и куда выкладывать — выкладка на сайт только словами пользователя. Проверка — быстрая по умолчанию, не спрашивать.

**Четыре режима — определить до разведки**, записать в журнал и отчёт:

| режим | когда | что «до» | чем сверяем |
|---|---|---|---|
| исходники | `localhost` или домен нашёлся `grep` по текущей папке и `deploy/` | снимки до правок | `diff.mjs` before/after |
| зеркало | исходников нет | нетронутое зеркало (`mirror.mjs`, `serve.mjs --proxy`) | `diff.mjs` по зеркалу |
| донор | «сделай в стиле …», «как у них, но про наше» | эталон — донор | `verify.mjs`, `texture.mjs compare`, `bgdecor.mjs compare`, `cliche.mjs --baseline`, `motion.mjs compare`, пары снимков |
| с нуля (`new`) | «сделай с нуля», «вот ТЗ» | эталон — выбранное направление и критерии | `verify.mjs`, `cliche.mjs --baseline`, `requirements.mjs report` |

- **Зеркало:** правки в `rework.css`, `rework.js` и HTML зеркала; «до» — с нетронутого зеркала по тому же адресу.
- **Донор** даёт язык, но не половину компонентов (формы, вопросы, шаги) — порядок `reference/donor-mode.md`,
  компоненты без донора — `reference/authorship.md`.
- **С нуля** — `reference/new-site.md`: реестр → вопросы → язык (донор; 2 направления из референсов; без них — 3 с
  эскизами) → план → сборка → проверка по критериям; веб-сервис с сервером — спросить про демо.
- **Донора нет** — не начинать без образца: по ответу анкеты подобрать 3 кандидата со снимками и рекомендацией
  или дать человеку каталоги живых сайтов, чтобы выбрал сам (`reference/donor-mode.md` §0: Refero Styles и ещё
  девять каталогов; MCP `refero` — только на платном тарифе, иначе каталог в браузере).

## Правила, которые не обсуждаются

**1. Статике не верить.** `new THREE.Scene()` не значит, что 3D рисуется; `onClick` — что кнопка работает;
`animation:` — что движение выглядит хорошо; объявление в CSS — что браузер его принял. Всё, что зависит от JS,
WebGL, Canvas, анимаций, наведения, клика, прокрутки и состояния, — проверяется `runtime.mjs` или браузерным MCP
и открывается глазами: сделать → запустить → открыть → снимок → посмотреть → взаимодействовать → консоль → VERIFIED.

**2. Не притворяться.** Пять состояний не сливаются:

| состояние | что означает |
|---|---|
| ANALYZED | изучено по снимкам, DOM, коду |
| IMPLEMENTED | код написан, страница открывается |
| RUNTIME VERIFIED | в браузере произошло ожидаемое: нет ошибок, клик/скролл/холст дали результат |
| VISUALLY VERIFIED | снимок открыт глазами на нужных экранах и выглядит как задумано |
| PERFORMANCE VERIFIED | измерено `perf.mjs`, бюджеты соблюдены или отклонение записано |

VERIFIED — только с доказательством, снятым после последней правки сайта: `state.mjs set … --evidence
<протокол.json[#шаг] | снимок.png>`. Журнал сам отвергает доказательство с FAIL, старое, одно на несколько
задач; протокол, снятый другой версией скрипта, — WARN «перепрогнать». NA — только с причиной (`--note`).
«WebGL проверен» без открытого холста, «mobile готов» без снимка на 390 и 320 px, «оптимизировано» без
замера — запрещённые фразы. Какое доказательство годится какому полю — `reference/steps.md` → «Статусы».

**3. Минимум достаточных инструментов — но без отказа от сложных.** Правка CSS не требует Lighthouse; сцена на
Three.js требует холста, снимка, замера кадров и телефона. Выбор — `reference/tool-registry.md`.

**4. Не ставить своё по умолчанию.** Каждое визуальное решение ссылается на правило донора (паспорт) или на
задачу блока. Совпало с каталогом дефолтов `reference/authorship.md` без такой ссылки — переделать.
Проверяется `cliche.mjs --baseline`, а не взглядом. Жёлтая кнопка при доноре без акцента, подписи капсом с
разрядкой, поля r10 — тот самый шаблон, который пользователь уже отверг.

**5. Любые инструменты для красоты.** CSS, Motion, GSAP (ScrollTrigger, SplitText), Lenis, Three.js и шейдеры,
Lottie, видео, сборщик или фреймворк — если выигрыш того стоит и выкладка не ломается (`reference/motion.md` →
«Техника»). Вместо запретов — забота: платное — только с согласия владельца; лицензии кадров и шрифтов;
безопасность; «меньше движения» — всегда, и это «тише, а не выключено» (`reference/motion.md`); скорость меряет `perf.mjs` и пишется в отчёт, но эффект не запрещает.

**6. Детали для красоты — на каждом сайте**, в любом режиме: фон с характером (фактура — мятая бумага, прожилки,
зерно; свои рисунки в тему от руки; предметы на полях; крупные бледные слова), надписи-логотипы разделов, игра
шрифтов, предметы за краем карточек, печать с настоящими фактами, у каждого раздела свой мотив и движение,
сверху 1–2 идеи из банка. Что донор делает разным, не унифицировать. Ровный фон без фактуры и деталей — только
если так выбрано в анкете. Раздел «Детали для красоты» в `analysis.md` обязателен; приёмы — `templates/decor-kit/`,
фактура — `surface-tile.mjs`, наброски — `templates/sketch2d/`, предметы с объёмом — `blender.mjs` (`templates/blender/`).
Сайт без деталей не сдаётся.

**7. Впечатление — с высокой планки и из вариантов.** Всё, что определяет впечатление (первый экран, цвет,
предметы, фон), показывать листом из двух-трёх вариантов до сборки, а не сдавать первый рабочий. Предмет с
объёмом — сразу по планке `reference/blender.md` → «Планка качества» (сэмплы и денойз, студийный свет, тень под
стоящим, детали на предмете, поле кадра) и рядом с предметом донора на одном листе. На «Зелёном уголке» рендер переделывали дважды
(«на 40 % лучше», потом «ещё на 25 %»), а цвет — после слов «чуть кислотней».

И правила поменьше:
- **контента нет — придумываем сами** в голосе дела, правдоподобно для отрасли и города; своё от пользователя и
  с сайта «до» главнее; всё придуманное (цены, сроки, часы, адреса, телефоны, отзывы, награды, цифры, имена) —
  в `<папка>/copy/invented.json` и разделом «Придумано — проверить владельцу» в отчёте;
- **материалы донора не копировать** — принципы и язык да, тексты, фото, файлы нет;
- **кадры — только из законных источников** (`media.mjs`, лицензия в `credits.json`; Pinterest — только доска
  настроения); **фото, видео или 3D — по смыслу сайта**, а не «3D везде» (`reference/engines.md` → «3D»); **подпись автора фото — сбоку, мелко и светло**;
- **тексты — для читателя сайта**, без жаргона и «AI-копирайтинга», голос у каждого бизнеса свой
  (`reference/copy.md`);
- **о мелочах не спрашивать** — только там, где разные ответы ведут к разной работе.

## Скрипты меряют, агент смотрит

Скрипты — для чисел: переполнение и перекрытый текст, контраст, скорость, шрифт каждого знака, ошибки консоли,
маски полей, движение числами донора. Всё, где нужно понять смысл страницы или вкус, — **отдельному агенту с
глазами** (снимки и клики) коротким заданием, а не новым правилам в скриптах. На боевой «Эпицентр» 29.09 самое
серьёзное (реклама в карте, чужой автор под фото, кадр не того кафе) нашли агенты, а скрипты давали ложные
тревоги. Ложную тревогу скрипта кругами не чинить: «ложная — скрипт» в отчёт и в SKILL-ISSUES.md, идти дальше.

Задания агенту — по одному на задачу, результат — список с путями к снимкам:
1. **Детали** (разведка): по снимкам всех типов страниц донора (без донора — сайта «до» и сайтов того же дела)
   выписать декоративные детали и видимое движение, к каждой — аналог из мира нашего дела; фон — по замерам
   `texture.mjs` (фактура) и `bgdecor.mjs` (рисунки, предметы на полях, слова-призраки, узоры, свечения; плюс его строки
   «крупное за содержимым» и «чего скрипт не меряет» — глазами); сверху 2–3 идеи
   `ideas.mjs pick --run <папка> --kind motion`. Сверка — `reference/craft.md` §3.
2. **Глаза и клики** (быстрая проверка, раз за круг): изменённые страницы на 390 и 1440 глазами; прокликать меню,
   формы, фильтры, ссылки; фото ↔ подпись ↔ название; чужие блоки (карты, виджеты) — реклама и ошибки; админка —
   что правка меняет на сайте; детали и движение — `reference/craft.md` §4. P0–P2 — в правки, остальное — в отчёт.
3. **Выбор фото** — листы-контакты глазами, по одному (`reference/engines.md` → «Картинки и видео»).
4. **Тексты** — задание `templates/copy-prompt.md` (факты, образец голоса владельца, списки признаков машинного
   текста для русского и английского); своё не подменено придуманным; придуманное всё в списке для владельца.
5. **Движение из банка** — какие 2–3 идеи уместны и где; отвергнутое — с причиной в `analysis.md`.
6. **Подбор донора** (донора не дали) — каталоги `reference/donor-mode.md` §0 → 3 кандидата со снимками и
   рекомендацией; фон и детали кандидатов — обязательный признак отбора.

Скептики (несколько агентов опровергают сделанное) — только в полной проверке перед сдачей.

## Порядок работы

Этапы — в журнал: `node ~/.claude/skills/site-rework/scripts/state.mjs <папка> stage <этап> done|active|todo|skipped`
(requirements discovered browser design direction tech tools tokens plan ui content assets three motion runtime
visual mobile perf a11y polish report; requirements и direction — только в `new`), чек-лист `state.mjs show` —
пользователю при каждом переходе. Подробно по каждому шагу — `reference/steps.md`.

### 0. Подготовка

```
node ~/.claude/skills/site-rework/scripts/state.mjs <папка> init <url|-> "<запрос>" --site <папка сайта> --mode rework|mirror|donor|new
node ~/.claude/skills/site-rework/scripts/requirements.mjs <папка> ingest --text "<бриф>" --kind brief   # и каждый файл ТЗ: --file
node ~/.claude/skills/site-rework/scripts/taste.mjs brief --run <папка> --blocks <блоки из запроса>
```
Прочитать `~/.claude/site-rework/taste/WISHES.md` и открыть картинки из вывода `taste.mjs` — запреты в матрицу
«не делать». Папка сайта для `--site`: исходники — папка проекта, зеркало — `<папка>/mirror`, донор и `new` —
`<папка>/site`. Поднять сервер (статику — `serve.mjs`, он сжимает как хостинг) — **отдельным процессом**, а не

### 3. Реализация — по одной задаче

Сделать → перезагрузить → `runtime.mjs` с шагами под задачу → снимок → открыть глазами → исправить; минимум
один круг исправлений на каждую заметную задачу. Где что — `reference/steps.md` §3:
- вёрстка — в дизайн-системе сайта (`design/site.tokens.css`, у донора — `donor/design/donor.tokens.css`);
- тексты — `reference/copy.md`; типограф `copy.mjs fix --typograph` — сначала дифф пользователю; у сайта с
  серверным рендером строки шаблонов — `run-tools/strings.mjs`, набор при выводе — `run-tools/typo.mjs`; чужой
  текст из базы — только набор, слова — списком «было → стало» владельцу;
- шрифты — донора с кириллицей, иначе по порядку `reference/fonts.md`: `fonts.mjs measure <донор>` (числа шрифта
  образца по отрисовке) → `match` (кандидаты с кириллицей из реестра источников `scripts/fonts/sources.json`, только
  с лицензией на веб) → `sheet` (лист для глаз: образец рядом, ₽, капс с Й/Ё при межстрочном 0,9 и 1,0) → `decide`
  (решение и лицензия — `<папка>/fonts/decision.json`) → `get`; без образца — `pick --like "<характер>"`;
  латинская надпись — ещё и Fontshare (`match --latin`, `get "fontshare:…" --latin`; файлы не урезать и не
  передавать клиенту — условия в decision.json); Adobe Fonts — не подключать (свои файлы запрещены);
  неразрывные пробелы — в исходном тексте и данных, `typeset.mjs` только меряет (`reference/typography.md`);
- фото и видео — `media.mjs search` → лист-контакт глазами → `pick --seen --caption` → `credits`; заменённая
  под тем же именем картинка — метка версии в адресе (`photo.webp?v=<хэш>`);
- фактура, 3D — `reference/engines.md`: зерно — `grain-tile.mjs` и `templates/grain.css`; крупная фактура (мятая и
  зернистая бумага, камень с прожилками, ткань) — `surface-tile.mjs` и `templates/surface.css`; детали — `templates/decor-kit/`
  (README); наброски от руки в фон — `templates/sketch2d/`; предметы с объёмом — только Blender: `blender.mjs`
  рендерит их в прозрачный WebP (и стекло, ткань, физику — предметы ложатся на плоскости, ткань драпируется), живое
  3D на странице — GLB из Blender и просмотрщик (`reference/blender.md`; `blender.mjs doctor` — что есть на машине и
  что ставить; без видеокарты чистовой кадр — минуты); мелкие объёмные значки и фоны в SVG — `svg3d.mjs`
  (`reference/svg-3d.md`), на видных местах рядом с рендером они слабее — туда только рендер;
- состояния (меню, фильтры, подсказки, ошибки форм, «заявка принята») и длинные страницы — листами для глаз:
  `templates/run-tools/` (`states`, `look`, `tops`, `slices`, `scroll-shots`); как живёт страница донора или своя —
  загрузка, покой, шапка при прокрутке, переход при наведении — покадрово: `run-tools/frames.mjs`; вердикты
  по-прежнему дают скрипты; перевод всего сайта в новый язык — рецепт `reference/steps.md`;
- движение — рецепты `reference/motion.md` по числам `motion.mjs`; `prefers-reduced-motion` всегда, но «тише, а не
  выключено»: появления до 24 px за 0,6 с, петли вдвое медленнее с видимой кнопкой паузы, привязка к прокрутке
  вполовину, за мышью ничего не ходит (в Windows анимации выключены у многих — сайт не должен выглядеть мёртвым); своё и
  полировка — `reference/craft.md` (навык `impeccable` не вызывать — читать его `reference/*.md`);
- телефон — своя вёрстка первого экрана, меню, форм и таблиц, а не «ужать десктоп»; 320 px тоже.

После задачи — статусы с доказательствами:
```

node ~/.claude/skills/site-rework/scripts/state.mjs <папка> set <id> visual=VERIFIED --evidence <папка>/after/<снимок>.png
```

## Требования по ходу работы

Сообщение посреди работы («а ещё…», файл, голосовое) — источник, а не реплика: `requirements.mjs ingest` →
`add` / `change --quote` / `status … superseded` → `conflicts` (вопрос, если ответы ведут к разной работе) →
`impact R-…` (что переоткрыть) → сделать и проверить → пользователю три строки: что пришло, что изменилось,
чем проверено. Подробно — `reference/steps.md` → «Требования по ходу работы». Оценка «шаблонно / нравится» —
в журнал вкуса; требование к сайту — в реестр; бывает и то и другое.

## Когда спрашивать

Спрашивать (`AskUserQuestion`; без человека — допущение в отчёт): анкета при запуске (о работе и о виде:
образец, фон, шапка при прокрутке, цвет); запрос спорит с ограничением; трата денег (Higgsfield, Recraft —
назвать сумму); ключ Pexels или контакт для Commons; удаление секций, смена цен, контактов, юридических
текстов; запрет журнала вкуса спорит с чертой донора; две трактовки — два направления с эскизами; веб-сервис —
делать ли демо; противоречие требований одного источника; снять или отложить требование; типограф меняет
тексты — сначала дифф. Полный список — `reference/steps.md` → «Когда спрашивать».

Не спрашивать: отступы, гарнитуру в рамках языка, длительности анимаций, порядок секций, формулировки текстов,
атомы и критерии требований — сделать, показать снимком, поправить по отклику.
