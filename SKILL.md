# Переработка сайта: от адреса до проверенного результата

Это не чат и не генератор кода, а порядок работы команды разработки:
разведка → анализ → план → реализация → проверка в браузере → отчёт.
Скрипты в `scripts/` снимают факты с живой страницы. Решения о дизайне и
тексте принимаются глазами по снимкам. Ничто не считается готовым, пока
не открыто в браузере и не проверено взаимодействием.

Скриптам нужны `puppeteer-core`, `sharp`, для видео — `ffmpeg-static`. Они
стоят в `~/.claude/site-rework/node_modules`, поэтому скрипты запускаются
из любой папки (ещё ищутся в `SITE_REWORK_PROJECT` и в текущей папке).
Папка прогона по умолчанию `~/.claude/site-rework/runs/<slug>`, своя —
`--out`. У каждого скрипта `--help` печатает все флаги.

## Вход

Бриф — `templates/brief.md` (или форма `ui/brief-form.html`), но можно и
свободным текстом. Из него вынуть:

| поле | что делать, если нет |
|---|---|
| URL | без него не начинать — единственный обязательный вопрос |
| Задача | «улучши» без уточнений → пройти воронку UX (`reference/analysis.md`) и предложить сам |
| Референсы | снять через скилл `design-reference`; не копировать, брать принципы |
| Донор | «сделай сайт в языке вот этого» — режим донора (ниже) |
| Пожелания по стилю | вывести из текущего сайта: сохранять его язык, если не просили менять |
| Ограничения | по умолчанию: не менять контакты, цены, логотип, основной цвет, бэкенд |
| Исходники | искать самому, см. режимы ниже |

**Три режима — определить до разведки** и записать в журнал и отчёт:

| режим | когда | что считается «до» | чем сверяем |
|---|---|---|---|
| исходники | адрес `localhost` или домен нашёлся `grep` по текущей папке и её `deploy/` | снимки сайта до правок | `diff.mjs` before/after |
| зеркало | исходников нет | нетронутое зеркало | `diff.mjs` по зеркалу |
| донор | «сделай новый сайт в стиле …», «как у них, но про наше» | снимков «до» нет; эталон — донор | `verify.mjs` по спецификации донора, `texture.mjs compare`, `cliche.mjs --baseline`, пары снимков донор/результат |

**Зеркало.** `mirror.mjs` снимает страницу в верстак, правки идут в
`rework.css`, `rework.js` и HTML зеркала, результат — зеркало для показа
плюс патч для переноса. Поднять `serve.mjs <папка>/mirror --proxy <адрес
оригинала>` (API и формы уйдут на оригинал), а снимки «до» снимать **с
нетронутого зеркала** по тому же адресу, что и «после», — иначе `diff.mjs`
не сложит пары.

**Донор.** Донор даёт язык, но не даёт половину компонентов: у
streetwearbrands.ru нет формы, вопросов, шагов. Именно в них прогон
«ХОЛСТ» собрал приёмы, которых у донора нет, и получил шаблон. Порядок —
`reference/donor-mode.md`, решения по компонентам без донора —
`reference/authorship.md`.

**Среда.** Большие файлы писать инструментом `Write`: длинный heredoc через
Bash на Windows не проходит. Git Bash подменяет аргументы вида `/sites/…`
на путь внутри своей папки — передавать полные адреса и пути вида `C:/…`.

## Правила, которые не обсуждаются

**1. Статике не верить.** `new THREE.Scene()` в коде не значит, что 3D
рисуется; `onClick` не значит, что кнопка работает; `animation:` в CSS не
значит, что движение выглядит хорошо; объявление в CSS не значит, что
браузер его принял. Всё, что зависит от JS, WebGL, Canvas, анимаций,
наведения, клика, прокрутки, касания и состояния, — проверяется
`runtime.mjs` или браузерным MCP и открывается глазами. Порядок для любого
визуального результата: сделать → запустить → открыть в браузере → снимок
→ посмотреть → взаимодействовать → консоль → и только тогда VERIFIED.

**2. Не притворяться.** Пять разных состояний, и они не сливаются:

| состояние | что означает |
|---|---|
| ANALYZED | изучено по снимкам, DOM, коду |
| IMPLEMENTED | код написан, страница открывается |
| RUNTIME VERIFIED | в браузере произошло ожидаемое: нет ошибок, клик/скролл/холст дали результат |
| VISUALLY VERIFIED | снимок открыт глазами на нужных экранах и выглядит как задумано |
| PERFORMANCE VERIFIED | измерено `perf.mjs`, бюджеты соблюдены или отклонение записано |

VERIFIED ставится **только с доказательством**, снятым после последней
правки файлов сайта: протокол `runtime/*.json` (или его шаг) с вердиктом не
FAIL, снимок, замер — `state.mjs set … --evidence <файл[#шаг]>`. Журнал
сам отвергает доказательство с FAIL, старше правки сайта, и пачку
статусов одним вызовом. NA — только с причиной (`--note`); отчёт считает
раздельно: «проверено N, неприменимо M, без доказательства K, устарело S».
Поля журнала: `impl` — TODO / DOING / DONE / BLOCKED / DROPPED; `runtime`,
`visual`, `mobile`, `perf` — NOT_CHECKED / VERIFIED / FAILED / NEEDS_WORK / NA;
ANALYZED — этап, а не поле. runtime и perf подтверждаются только протоколом
`.json`, visual и mobile — протоколом или снимком (для mobile — снятым на
телефонном экране). «WebGL проверен» без открытого
холста, «mobile готов» без снимка на 390 и 320 px, «оптимизировано» без
замера — запрещённые фразы.

**3. Минимум достаточных инструментов — но без отказа от сложных.**
Простая правка CSS не требует Lighthouse; сцена на Three.js требует
холста, снимка, замера кадров и телефона. Выбор — по
`reference/tool-registry.md`.

**4. Не ставить своё по умолчанию.** Каждое визуальное решение ссылается
на правило донора (паспорт) или на задачу блока. Что совпало с каталогом
дефолтов `reference/authorship.md` без такой ссылки — переделать.
Проверяется `cliche.mjs --baseline`, а не взглядом: взгляд к своему шаблону
привыкает. Своя жёлтая кнопка при доноре без акцента, подписи капсом с
разрядкой, поля r10 — тот самый шаблон, который пользователь уже отверг.

И правила поменьше: **ничего не выдумывать** (цены, сроки, отзывы, факты
о бизнесе — только с сайта или от пользователя); **материалы не
копировать** (принципы и язык — да; тексты, фото, файлы донора — нет);
**кадры — только из законных источников** (`media.mjs`, лицензия в
`credits.json`; Pinterest — только доска настроения); **тексты — для
читателя сайта**, не для разработчика, без жаргона и без
«AI-копирайтинга»; **о мелочах не спрашивать** — спрашивать только там,
где разные ответы ведут к разной работе.

## Порядок работы

Этапы отмечать в журнале: `node scripts/state.mjs <папка> stage <этап> done`,
и показывать пользователю чек-лист (`state.mjs show`) при каждом переходе.

### 0. Подготовка

```
node scripts/state.mjs <папка> init <url> "<запрос>" --site <папка сайта> --mode rework|mirror|donor
node scripts/taste.mjs brief --blocks <блоки из запроса>      # запреты и эталоны прошлых прогонов
```
Открыть `Read` картинки из вывода `taste.mjs`: запреты — в матрицу «не
делать». Определить режим; папка сайта для `--site`: исходники — папка
проекта, зеркало — `<папка>/mirror`, донор — `<папка>/site`. По ней журнал
узнаёт, что доказательство устарело (сайт правили после проверки). Локальный проект — поднять сервер (`npm run dev`
или что есть). Записать ревизию инструментов в `<папка>/tools.md` по
чек-листу `reference/tool-registry.md`.

### 1. Разведка — состояние ANALYZED

```
node scripts/discover.mjs <url>                      # техника, содержимое, визуал, фактура, паспорт, медиа-слоты, 320, дизайн-система
node scripts/runtime.mjs <url> --scroll --canvas --motion --video --fullpage
node scripts/runtime.mjs <url> --viewport mobile --scroll --click "<переключатель меню>" --shot menu
node scripts/runtime.mjs <url> --css --hover-all --nav     # автопроверки состояния, reference/qa.md
node scripts/perf.mjs <url>                          # телефон, медленная сеть — база для сравнения
node scripts/a11y.mjs <url> --viewport mobile
node scripts/shots.mjs <url> --tag before --pages /,<другие страницы в задаче> --with-320
node scripts/cliche.mjs baseline <url или донор> --out <папка>/cliche/donor.json
```
Если у сайта или донора есть зерно, шум, плёнка — `node scripts/texture.mjs
<url>` (рецепт и `--grain-*`, `reference/engines.md` → «Фактура»).

Прочитать `discovery.md`. **Открыть снимки** (`Read` показывает PNG): первый
экран, лист прокрутки, `scroll-NN` на desktop и mobile, вырезки фактуры 1:1.
Заполнить визуальный разбор словами по `reference/discovery.md` — язык
дизайна, иерархия, приём, фактура, паспорт «как / никогда», что сильное и
сохраняется. Режим донора — ещё `reference/donor-mode.md` §1–2.

Что выяснить на выходе: платформа и ограничения (Tilda, WordPress, свой код),
что уже хорошо, что сломано (P0), как сайт зарабатывает (звонок, заявка,
корзина) и где на этом пути трение.

### 2. Анализ и план

По `reference/analysis.md`: разобрать запрос на области, составить матрицу
**менять / не трогать**, пройти воронку Arrival → Understanding → Interest
→ Trust → Decision → CTA → Conversion и найти трение. Каждое решение — с
причиной.

Для каждого ключевого блока и для каждого компонента, которого нет у
донора, — запись в `<папка>/authorship.md` по `reference/authorship.md` §3:
три черты донора → три кандидата из разных направлений → отсев по каталогу
и журналу вкуса → эскизы двух → выбор с причиной. **Показать эскизы
пользователю до сборки страницы**, если сессия интерактивная. Скилл
`frontend-design` — здесь, на шаге кандидатов; его предложения проходят тот
же отсев.

План — задачи в журнале с приоритетом:

```
node scripts/state.mjs <папка> add "Меню на телефоне не открывается" --priority P0 --area mobile
```
P0 сломано · P1 крупная проблема UX · P2 крупная визуальная · P3 тексты ·
P4 движение · P5 полировка. Порядок: P0 → P5, внутри — зависимости:
дизайн-система раньше UI, тексты раньше подгонки вёрстки, кадры раньше
секций, которым они нужны, 3D и движение после того, как вёрстка встала.

### 3. Реализация — по одной задаче

Для каждой задачи: сделать → перезагрузить → `runtime.mjs` с шагами именно
под неё → снимок → открыть глазами → исправить → повторить. Не принимать
первый результат: минимум один круг исправлений на каждую заметную задачу.

- вёрстка и UI: правки в дизайн-системе сайта (переменные из `design/site.tokens.css`),
  не поверх; без новых сборщиков и фреймворков на сайте, где их нет;
- тексты: `reference/analysis.md`, раздел «Тексты»;
- фото и видео: `reference/engines.md` → «Картинки и видео»: `media.mjs search` → лист-контакт
  глазами → `pick` с `--seen` и `--caption` → `credits`;
- фактура: `reference/engines.md` → «Фактура»: своя плитка `grain-tile.mjs`, слой `templates/grain.css`;
- 3D: `reference/engines.md` → «3D»: сначала ответ «нужно ли», потом подход, потом обязательная проверка холста;
- движение: `reference/engines.md` → «Движение»: язык донора первым, CSS первым, `prefers-reduced-motion` всегда;
- телефон: отдельная вёрстка первого экрана, меню, форм и таблиц, а не «ужать десктоп»; 320 px тоже.

После каждой задачи — статусы с доказательствами:
```
node scripts/state.mjs <папка> set <id> impl=DONE runtime=VERIFIED --evidence <папка>/runtime/<tag>.json
node scripts/state.mjs <папка> set <id> visual=VERIFIED --evidence <папка>/after/<снимок>.png
```

### 4. Проверка — по `reference/qa.md`

```
node scripts/shots.mjs <url> --tag after --pages <те же> --with-320   # FAIL, если состояние после прокрутки не сбрасывается
node scripts/diff.mjs <папка>/before <папка>/after       # где изменилось — совпадает ли с планом
node scripts/runtime.mjs <url> --scroll --canvas --motion --video --click ... --edit ... --select ...   # desktop и mobile
node scripts/runtime.mjs <url> --css --hover-all --nav
node scripts/runtime.mjs <url> --viewport mobile-s --scroll
node scripts/perf.mjs <url> --runs 3                     # медиана трёх прогонов против базы; --overlay — цена слоя зерна
node scripts/a11y.mjs <url> --viewport mobile
node scripts/cliche.mjs <url> --baseline <папка>/cliche/donor.json --taste --run <папка> --shot
```
Режим донора — плюс `verify.mjs` и `texture.mjs compare` (`reference/donor-mode.md` §5).
Открыть глазами все `after/*` на desktop, tablet, mobile, вырезки 1:1
изменённых компонентов и все `diff/*.png`: изменения только там, где
планировались; что должно было сохраниться — сохранилось.

Условие выхода из цикла: все P0–P2 VERIFIED по runtime, visual и mobile с
доказательствами новее последней правки; автопроверки состояния без FAIL;
320 без переполнения; `perf` не хуже базы; `a11y` без FAIL; в `cliche.mjs`
нет правил веса 3 «НЕТ У ДОНОРА» без записи в `<папка>/authorship-decisions.json`, «размножено»
не больше ×2, ни одного «ЗАПРЕЩЁН»; иначе — ещё круг. Если круги
закончились по времени — оставшееся честно в отчёт.

### 5. Отчёт — `templates/report.md`

Обязательные разделы: сайт и режим, запрос, что изучено, инструменты и
зачем, изменения, авторские решения, проверено в браузере (контрол →
сценарии → протокол), проверено глазами, скорость (до и после), кадры и
лицензии, **не проверено**, что осталось, рекомендации. Таблица задач — из
`state.mjs show`. Пути к снимкам и протоколам — в отчёт.

Любая оценка пользователя («шаблонно», «нравится», выбор варианта) —
сразу `taste.mjs add` с его словами дословно и кропом.

## Прогресс для пользователя

При каждом переходе между этапами показывать чек-лист из `state.mjs show`:

```
✓ Сайт разведан
✓ Открыт в браузере, консоль и сеть сняты
→ Дизайн разобран глазами
· План с приоритетами составлен
```
Между этапами — короткие строки: что делается, что нашлось. Без пересказа
файлов и без обещаний того, что не проверено.

## Когда спрашивать, а когда решать самому

Спрашивать (через `AskUserQuestion`, если сессия интерактивная; иначе принять
допущение, записать его в отчёт и продолжать):
- запрос конфликтует с ограничением («сделай ярче» при «не менять основной цвет»);
- генерация картинок или 3D стоит денег на счету пользователя (Higgsfield);
- удаление секций, смена цен, контактов, юридических текстов;
- запрет из журнала вкуса спорит с явной чертой нового донора;
- две трактовки ведут к разным сайтам, и референсов нет — предложить два направления одним вопросом, с эскизами.

Не спрашивать: размеры отступов, выбор гарнитуры в рамках текущего языка,
длительности анимаций, порядок секций внутри плана, формулировки текстов —
сделать, показать снимком, поправить по отклику.

## Восстановление после сбоев

Не останавливаться на первом отказе; но в отчёте — что именно не проверено.

| отказало | дальше |
|---|---|
| `scripts/*.mjs` (нет puppeteer-core, браузер не поднялся) | `npm i puppeteer-core sharp ffmpeg-static --prefix ~/.claude/site-rework`, `CHROME_PATH` → chrome-devtools MCP → playwright MCP → пометить UNVERIFIED |
| Edge завершился молча | Chrome стоит первым; или `CHROME_PATH` на Chrome |
| вкладка упала или зависла (мало памяти) | скрипты дают ошибку «вкладка упала», а не ждут вечно; закрыть лишнее и повторить по одному скрипту |
| `sharp` не найден | `diff.mjs` и замер фактуры пропустить, сравнивать снимки глазами; картинки не пережимать |
| `ffmpeg` не найден | видео не обрабатывать (`media.mjs` пишет WARN и отказывается), постер-картинка |
| `design-reference` нет рядом | палитра и шрифты из `discovery.md`, токены выписать руками |
| `texture.mjs` не загрузился | `discover.mjs` мерит фактуру запасным путём; `--no-texture-module` — то же нарочно |
| сеть источников кадров (DNS, VPN) | `media.mjs` пишет «временная ошибка, повторить позже», пробует DoH; не записывать источник как недоступный |
| генерация картинок недоступна | фото из свободных источников (`media.mjs`), SVG/CSS-графика, оставить существующие |
| нет модели для 3D | процедурная геометрия в Three.js, шейдер — не ждать модель; или без 3D |
| сервер отдаёт 429 | подождать минуту, не перезапускать |
| `net::ERR_TIMED_OUT`, `ERR_CONNECTION_RESET` (медленное TLS) | скрипты повторяют переход трижды и пишут «с N-й попытки»; не гонять несколько скриптов по такому сайту параллельно |
| страница за логином, зеркало не снимается | попросить доступ или исходники; работать по снимкам пользователя как ANALYZED |

```
scripts/lib.mjs        браузер, экраны (mobile-s 320, android 360, ШxВ@DPR), прокрутка, снимки, переполнение, холсты, цвета
scripts/discover.mjs   разведка: техника, содержимое, визуал, фактура, паспорт донора, подписные приёмы, медиа-слоты
scripts/runtime.mjs    проверка в браузере: клики с эффектом, маски, выбор, смена окна, холсты и резкость, наведение, меню, CSS, видео
scripts/texture.mjs    фактура числом: слои зерна, σ по фонам, кипение, рецепт, compare донор против сайта
scripts/grain-tile.mjs своя детерминированная шумовая плитка (PNG, спрайт, WebP, GIF) и её проверка
scripts/cliche.mjs     шаблонность: дефолты на живой странице против донора и журнала вкуса
scripts/taste.mjs      журнал вкуса между прогонами: отвергнутое и принятое с картинками
scripts/media.mjs      фото и видео из законных бесплатных источников: doctor, search, pick, import, credits
scripts/media/         модули источников, обработки, видео и манифеста
scripts/shots.mjs      снимки «до/после» на одинаковых экранах; возврат наверх сверяется с первым экраном
scripts/diff.mjs       где изменилась картинка: доля, полосы, картинка различий
scripts/perf.mjs       скорость с бюджетами: LCP, CLS, вес, кадры/с, память, цена слоёв
scripts/a11y.mjs       контраст (с прозрачностью и зерном), кегль, alt, подписи, фокус, цели нажатия
scripts/state.mjs      журнал задач и этапов: статусы только с доказательствами
scripts/mirror.mjs     зеркало чужой страницы как верстак (rework.css / rework.js)
scripts/serve.mjs      статический сервер (Range для видео, только эта машина); --proxy отдаёт остальное оригиналу
templates/grain.css    слой зерна: отдельный элемент, @media по ширине, кипение сдвигом
reference/tool-registry.md   что есть, когда чем пользоваться, чем заменять
reference/discovery.md       визуальный разбор словами, паспорт, фактура, дизайн-система, референсы
reference/donor-mode.md      новый сайт на языке донора: снять, паспорт, граница, сверка
reference/authorship.md      каталог дефолтов, паспорт донора, решение по блоку, компоненты без донора, журнал вкуса
reference/analysis.md        разбор запроса, матрица менять/сохранять, воронка UX, тексты, приоритеты
reference/engines.md         картинки и видео, фактура, 3D, движение, телефон, правила реализации
reference/qa.md              проверки: runtime и автопроверки состояния, визуал, функции, телефон, скорость, доступность
templates/brief.md           форма запроса
templates/report.md          форма отчёта
ui/brief-form.html           форма в браузере, собирает текст брифа
```
